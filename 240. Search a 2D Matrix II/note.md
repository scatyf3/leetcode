### 第一版：二维二分，为什么不对

一开始想的是行、列各自像一维二分一样同时砍：

```python
if matrix[mid_row][mid_col] > target:
    row_r = mid_row - 1; col_r = mid_col - 1   # 只留左上
elif matrix[mid_row][mid_col] < target:
    row_l = mid_row + 1; col_l = mid_col + 1   # 只留右下
```

问题：**跟中点比一次，只能排除一个象限，我却扔了三个。** `mid < target` 只保证左上块全比 target 小；右上块、左下块里有大有小，哪块都不能扔。

反例（题目自带矩阵，target = 18，在左下角 (4,0)）：

```
[ 1,  4,  7, 11, 15]
[ 2,  5,  8, 12, 19]
[ 3,  6,  9, 16, 22]
[10, 13, 14, 17, 24]
[18, 21, 23, 26, 30]
```

中点 (2,2) = 9 < 18 → 只剩右下 [[17,24],[26,30]]，18 所在的左下块直接丢了，返回 False。

> 站在中点，比完不知道挪 row 还是 col —— 中点既不是所在行的最值，也不是所在列的最值。

### 从右上角走一遍

同一个例子，target = 18：

| 位置 | x | 和 18 比 | 动作 | 为什么能扔 |
|---|---|---|---|---|
| (0,4) | 15 | 小 | 往下 | 第 0 行最大的就是 15，整行都比 18 小 |
| (1,4) | 19 | 大 | 往左 | 第 4 列从这往下都 ≥ 19 |
| (1,3) | 12 | 小 | 往下 | 第 1 行剩下的部分都 ≤ 12 |
| (2,3) | 16 | 小 | 往下 | 同理 |
| (3,3) | 17 | 小 | 往下 | 同理 |
| (4,3) | 26 | 大 | 往左 | 第 3 列往下只剩 26 |
| (4,2) | 23 | 大 | 往左 | |
| (4,1) | 21 | 大 | 往左 | |
| (4,0) | 18 | 相等 | ✓ True | |

每步扔一整行或一整列，最多走 m + n 步，O(m + n)。

### 怎么想到右上角

不靠灵感，从「想扔什么」倒推「站哪」：

- x < target 时想**扔整行** → x 得是这一行的**最大值** → 在最右列
- x > target 时想**扔整列** → x 得是这一列的**最小值** → 在最上行
- 两条同时满足 → **右上角**

反过来「行最小、列最大」就是**左下角**，也行。左上（行列都最小）、右下（行列都最大）比完只能排除一个方向，不行。

**转 45° 就是 BST**：右上角往左变小、往下变大，正是「左子树小、右子树大」。整段代码就是在 BST 里查找，每步只有一个确定方向。

**和 [167. Two Sum II](../167.%20Two%20Sum%20II%20-%20Input%20Array%20Is%20Sorted/) 是同款**：l 在最左、r 在最右，和太小 `l += 1`，太大 `r -= 1`。把 `a[l] + a[r]` 画成二维表，167 就是在这张表上从一个角做同样的走法。

> 找一个起点，让它的两个出口**一个变大、一个变小** —— 每次比较方向唯一，且能排除一整行/列。遇到「二维、两个方向各自有序」先找这样的角。
