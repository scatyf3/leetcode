## 关键：二进制拆的是 n，不是 x

快速幂拆的是**指数**：

```
x^13 = x^8 · x^4 · x^1        ← 13 = 1101₂
```

x 是什么类型都行。整数、浮点数、矩阵、模意义下的数都可以，只要它们之间的乘法满足结合律。算法只对 n 做 `n & 1`、`n >>= 1`，而 50 的 n 保证是整数。x 是 float 也只是让 `ans *= x` 和 `x *= x` 变成浮点乘法，循环结构一行都不用改。

上次给的模板直接套 float 就能跑：`fast_pow(2.1, 3)` 每一步都是普通的浮点乘法。

## float 真正带来的三点区别

1. **不能取模**。整数版每次乘完都要 `% MOD`，浮点版没有这一步，所以比整数版还简单。
2. **精度**。浮点乘法每次都有一点舍入误差，但快速幂只做 O(log n) 次乘法，误差反而比连乘 n 次小。LC 判题允许大约 1e-5 的误差，这一点不用担心。
3. **溢出到 inf / 下溢到 0**。最后一轮 `x *= x` 可能平方到 inf，但这时 n 已经是 0，这个值不会再乘进 `ans`，不影响结果。题目也保证了最终答案在 [-10⁴, 10⁴] 之内。

## `ans *= x` 是什么意思

`ans *= x` 就是 `ans = ans * x`：把当前的 x 乘进答案里。

这里的 x 在循环里一直在变。每轮结束时都会 `x *= x` 平方一次，所以第 k 轮开始时：

```
x = 原来的 x 的 2^k 次方
```

| 第几轮 k | 当前 x 代表 | n 的这一位 |
|---|---|---|
| 0 | x¹ | 最低位 |
| 1 | x² | 次低位 |
| 2 | x⁴ | … |
| 3 | x⁸ | … |

因此 `if n & 1: ans *= x` 的意思是：如果 n 的这一位是 1，就把对应的那一块（x 的 2^k 次方）乘进答案。还是用 3¹³ 举例，13 = `1101`，所以要把 3¹、3⁴、3⁸ 这三块乘进 ans。3² 那一块对应的位是 0，跳过。

> 所以 `x` 其实是「当前这一位对应的那一块」，`ans` 是「已经选中的块的乘积」。两个变量各管一件事。

## 指数相加 = 幂相乘

关键是这条规则：

$$x^a \cdot x^b = x^{a+b}$$

两个同底数的幂相乘，指数就相加。所以：

```
13 = 8 + 4 + 1          ← 指数这一层：是加法
x^13 = x^8 · x^4 · x^1   ← 值这一层：变成了乘法
```

代码操作的是值（`ans`、`x`），所以只看得到乘法。指数上的那个加法，是每次 `ans *= x` 时自动发生的：

| 操作 | 值这一层 | 指数这一层 |
|---|---|---|
| `ans *= x` | ans 乘上 x | ans 的指数 **加上** 当前那一块的指数 |
| `x *= x` | x 平方 | x 的指数 **翻倍**（1 → 2 → 4 → 8） |
| `ans = 1` 初始化 | 乘法的起点是 1 | 指数的起点是 0（x⁰ = 1） |

拿 3¹³ 跟着走一遍，只看 ans 的指数：

```
初始       ans = 3^0        指数 0
加 1 那块  ans = 3^0 · 3^1   指数 0 + 1 = 1
加 4 那块  ans = 3^1 · 3^4   指数 1 + 4 = 5
加 8 那块  ans = 3^5 · 3^8   指数 5 + 8 = 13  ✓
```

> 快速幂的本质：**在指数上做二进制加法，在值上表现为乘法。**

## 顺带一个对照

把乘法全换成加法，同一套代码就变成「快速乘」，用来算 a × n：

```
ans += a   ↔   ans *= x
a += a     ↔   x *= x       （a → 2a → 4a，对应 x → x² → x⁴）
ans = 0    ↔   ans = 1
```

两者结构一模一样，只是换了一种运算。这也是为什么说快速幂只依赖运算满足结合律。

## 误差从哪来

问题出在第 6 行的 `x = 1/x`。

`1/x` 这一步除法会有一点舍入误差。我用高精度算了一下，这个 x 取倒数后的相对误差大约是 **1.0 × 10⁻¹⁶**，只有最后一位不准。

但这个带误差的数接下来要自乘 |n| ≈ **1.67 × 10⁹** 次方。**底数有相对误差 δ，n 次方之后相对误差会放大到大约 n·δ**：

```
1.0e-16 × 1.67e9 ≈ 1.7e-7
```

你的输出 191.063727 和真值 191.063697 正好差了 1.6 × 10⁻⁷，和估算对得上。误差落在小数点后第 5 位，所以被判错。

## 怎么改

除法要做，但要**挪到最后做**：先用原来的 x 算出 x^|n|，最后再整体取一次倒数。这样除法的舍入误差只出现一次，不会再被放大 |n| 倍。

我在本地跑了两种写法：

| 写法 | 结果 |
|---|---|
| 先 `1/x` 再进循环（你现在的） | 191.0637**27** ✗ |
| 先算 x^\|n\|，最后 `1/ans` | 191.0637**03** ✓ |
| 真值（高精度） | 191.063697 |

具体改法：`if n < 0` 里只记下「最后要取倒数」并把 n 变成正数，第 6 行去掉，`return` 前再根据这个记号处理。你自己改一下就行。

> 浮点数的通用原则：**会被反复乘的量，进循环之前别引入额外误差。** 不可避免的除法、开方这类有误差的操作，尽量放到最后做一次。
