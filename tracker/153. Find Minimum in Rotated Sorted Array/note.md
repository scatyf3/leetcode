我们想用二分搜索在大段还是小段，sol3是标准解法，因为这里的判断是

```
下标   0  1  2  3  4  5  6
值     4  5  6  7  0  1  2
>2 ?   T  T  T  T  F  F  F
                   ↑ 第一个 F = 最小值
```

所以sol3是要找第一个F，即要找的分界点

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        # binary search ver
        l=0
        r=len(nums)-1
        mid=int((l+r)/2)
        while l<=r:
            if nums[mid] > nums[-1]:      
                l=mid+1
            else:
                r=mid-1
            mid=int((l+r)/2)
        return nums[l]
```
为啥sol3能找到第一个落到f里的，证据在哪里？
证据不在任何一次对 l 的检查上，而是在于 l 的左边和 r 的右边都已经被证过了。退出的时候这两块刚好拼满整个数组，缝就在 l。

如果当前mid在大段，缩左边的大段，反之缩右，这样，每次迭代的不变量是
```
[ 0 .. l-1 ]  全是 T      ← 每次 l = mid+1 证的
[ r+1 .. n-1 ] 全是 F     ← 每次 r = mid-1 证的
[ l .. r ]    还没看
```

感觉这里和常规二分不一样，这里好像是规律性丢掉左边和右边由顺序而定的东西，这更贴近二分的本质吗？

下标上有一个单调的判据 P，排成 T T T … F F F，要找的是 T 和 F 的分界。

每查一次 mid，靠单调性就能丢掉一整侧：

```
mid 是 T，左边一定全是 T，丢掉左边
mid 是 F，右边一定全是 F，丢掉右边
```

你说的「由顺序而定」，我想稍微改一下：决定能丢哪边的其实不是数组有序，而是判据单调。有序只是让判据单调的一种途径。153 的数组已经不是有序的了（4 5 6 7 0 1 2），但 nums[i] > nums[-1] 依然单调，所以照样能二分。
