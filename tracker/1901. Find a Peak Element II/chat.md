```python
class Solution:
    def findPeakGrid(self, mat: list[list[int]]) -> list[int]:
        m, n = len(mat), len(mat[0])
        lo, hi = 0, m - 1

        while lo <= hi:
            mid = (lo + hi) // 2

            # 选 mid 这一行的最大值所在列
            j = max(range(n), key=lambda c: mat[mid][c])

            # 越界的邻居按 -1 处理
            up = mat[mid - 1][j] if mid > 0 else -1
            down = mat[mid + 1][j] if mid < m - 1 else -1

            # 左右已经由行最大值保证，只需比较上下
            if mat[mid][j] > up and mat[mid][j] > down:
                return [mid, j]

            # 往更大的邻居那一侧走
            if up > mat[mid][j]:
                hi = mid - 1
            else:
                lo = mid + 1
```

**为什么必须选行最大值：** 假设上方邻居 `up` 比行最大值还大，那么 `up` 比 mid 行的所有格子都大。从 `up` 出发一路往更大的格子爬，数值只增不减，所以永远回不到 mid 行，只能停在上半部分。停下来的位置就是一个 peak，所以上半部分一定有答案，扔掉下半部分是安全的。

之前的 `5` 不行，就是因为 mid 行还有比 `6` 大的 `9`，爬升路径可以穿过这一行走到下面，上半部分就不一定有 peak 了。

**复杂度：** 时间 O(n log m)，空间 O(1)。

这里要区分两个概念：

行最大值的位置也不一定唯一，因为题目只保证相邻格子不相等，比如 `[5, 1, 5]` 有两个最大值。这不影响算法：无论选哪个，它都不小于这一行的所有格子，正确性证明照样成立。


1. mid 是第 1 行，行最大值是 `9`。
2. `9` 上面的 `10` 更大，于是往上走，扔掉第 1、2 行。此时 `5` 被扔掉了，尽管它是 peak。

留下的一半一定有 peak，理由有两层：

- **整个矩阵一定有 peak：** 全局最大值比所有邻居都大，它本身就是 peak。
- **留下的一半也一定有：** 还是用上面的爬升论证。假设 `up` 大于 mid 行的最大值，从 `up` 开始不断走向更大的邻居。数值严格增大，所以不会无限走下去，也回不到 mid 行，最后一定停在上半部分的某个格子上。停下时，它的四个邻居都比它小，所以它是整个矩阵的 peak，而不只是上半部分的。

往下走的情况完全对称。所以算法每一步可能丢掉一些 peak，但永远不会把所有 peak 都丢掉。

#### 🧑 我

这里的对数是max保证的吗

#### 🤖 Claude

不是。**对数来自二分，`max` 保证的是二分不出错。**

- **`log m` 来自二分行号：** 每轮把候选行砍掉一半，所以最多 O(log m) 轮。
- **`n` 来自 `max`：** 每轮扫描一行找最大值，要花 O(n)。它在复杂度里其实是成本，不是省下来的部分。
- **`max` 的作用是保证能扔掉一半：** 选了行最大值，留下的那一半才一定有 peak。

两者相乘就是 O(log m) 轮 × 每轮 O(n) = O(n log m)。

之前的 `5` 就是反例：只选行内 peak，轮数同样是 O(log m)，但可能把所有 peak 都扔掉，得到错误答案。所以 `max` 影响的是对错，不是轮数。

#### 🤖 Claude

不是每一行都选 max，那样要扫完所有行，又退回 O(mn) 了。**每轮只对 mid 这一行选 max**，然后拿它和正上方、正下方的邻居比较：

| 比较结果 | 含义 | 操作 |
|---|---|---|
| 比上下都大 | 左右也比它小，它就是 peak | 返回 `[mid, j]` |
| 上面更大 | 上半部分一定有 peak | `hi = mid - 1` |
| 否则（下面更大） | 下半部分一定有 peak | `lo = mid + 1` |

用一个 5 行的矩阵走一遍：

```text
行0:  1  2  3
行1:  4  5  6
行2:  7  8  9
行3: 10 11 12
行4: 13 14 15
```

1. `lo=0, hi=4`，所以 `mid=2`。这一行的 max 是 `9`，下面的 `12` 更大，往下走，`lo=3`。
2. `lo=3, hi=4`，所以 `mid=3`。这一行的 max 是 `12`，下面的 `15` 更大，往下走，`lo=4`。
3. `lo=4, hi=4`，所以 `mid=4`。这一行的 max 是 `15`，上面的 `12` 更小，下面越界按 -1 处理，返回 `[4, 2]`。

整个过程只看了 5 行中的 3 行，第 0、1 行从头到尾都没有扫描过。
