# 41. First Missing Positive

## pass2

依旧是双指针条件，我们需要write走到底，但这个和双指针不一样，双指针可能需要read走到底，write不需要。这里不一样的本质是什么啊

---

这版循环两个 bug，最小反例 `[1,3,2]`（期望 4，返回 2）：

1. **已归位还在换**：`nums[val-1] == val` 时交换是原地不动（自己跟自己 / 重复值互换），`write` 卡住不走。条件要加上 `nums[val-1] != val`
2. **`iterate_counter < n` 限步数**：步数上限是 2n（前进 ≤ n 次 + 交换 ≤ n 次）。`[1,3,2]` 三步全花在 1 跟自己换上，3 和 2 没被看到。删掉计数器，改成 `while write < n`

「本质是什么」：这里的 `write` 其实是**读**指针，名字起错了。双指针压缩里目的地是**相对的**（前面留了几个），
所以要一个写前沿；这里目的地是**绝对的**（v 的家就是 v-1），不需要写前沿，只剩一个扫描指针，它当然得走到底。
另外 `write` 左边**不定型**，后面还会有数被送回来 —— 这点也和双指针相反。

为什么一定走得到底：`write + 已归位个数` 每步严格 +1、上限 2n。这个模式叫 **cyclic sort**（排列拆成环，沿环扔回家）。
证明、对比表、同类题都在 [hash-table.md §8](../../blog/docs/structures/hash-table.md#8-原地哈希拿输入数组自己当桶)。

## pass1

读写分离，swap数组里的元素，让数字天生充当hash，这里的复杂度是O(n)，因为本质只遍历index.

思路对了，但是循环没写对

2. 遍历index，找应该放到这里的数

然后这个换皮的读写双指针搞不明白...

---

不是读写双指针，是**原地哈希**：只有一个 `i` 在走，目的地 `nums[i]-1` 是算出来的，而且可能在前面
（不是「丢到后面」）。错的三版全卡在「什么时候前进」—— **换了就留，没换才走；位置走完才停**。
