### 第一反应：套滑窗，套不上

刚做完 LC3，顺手就想套 [sliding-window-template.md](../notes/sliding-window-template.md) 的骨架 A。套不上，而且**为什么套不上**比这题的正解更值钱。

滑窗成立靠一条性质：**合法性向下封闭**（合法窗口的任意子串也合法）。LC3 里"无重复"满足它，所以窗口收缩一定安全、左边界单调不减、总复杂度 O(n)。

回文完全不满足：`"aba"` 是回文，子串 `"ab"` 不是。所以 l 不单调，窗口爬不动。

> 用那篇笔记里「拿到新题的 3 个问题」自检第 3 条（什么时候算不合法）就会当场露馅——收缩之后可能反而变合法，收缩条件根本写不出来。

### 换视角：枚举中心，不是枚举端点

不要问"以 r 结尾的最长回文是什么"，这个量没有好的递推。回文的定义是**关于中心对称**的，所以枚举对象应该是中心。

中心有两种：
- 奇数长度 `"aba"` → 中心是一个字符，共 n 个
- 偶数长度 `"abba"` → 中心是两个字符之间的**缝**，共 n-1 个

合计 `2n-1` 个中心。**漏掉偶中心是这题最常见的 WA。**

### 初稿的 5 个 bug（复盘）

第一版代码：

```python
for i in range(n):
    l = i; r = i
    while (l >= 1 and r <= n-2):        # bug 1
        if s[l] == s[r]:
            cout += 1                    # bug 3
            l -= 1; r += 1
        else:
            max_len = max(max_len, cout) # bug 2
            break
return max_len                           # bug 5
```

| # | bug | 后果 |
|---|-----|------|
| 1 | 边界写窄成 `l>=1 and r<=n-2` | l 够不到 0、r 够不到 n-1，两端字符被永久排除，`"aa"` 直接扩不动。应为 `l>=0 and r<=n-1` |
| 2 | 只在 `else` 分支结算 | 回文顶到字符串边界时由 while 条件正常退出，这次的结果被丢掉 |
| 3 | `cout` 定义在 `for i` 外，跨中心不清零 | 计数一路累加；而且它数的是"匹配对数"，不是长度 |
| 4 | 只有 `l=i,r=i` | 漏掉全部偶中心，`"abba"` 找不到 |
| 5 | 返回 `int` | 签名要 `str`，得维护区间端点而非 `max_len` |

**5 个里 4 个是记账 bug，只有 1 个（漏偶中心）沾算法。** 这题的难度类型是"写不干净"，不是"想不到"——思路一句话说完，痛感全来自边界和状态。这种难可以靠模板消灭，不需要靠补题量。

（对比：LC128 才是"想不到"型——想不到"只从连续段起点开始数"就只能 O(n log n)，差距是结构性的。）

### while 退出时为什么多走一格

```python
while l >= 0 and r < n and s[l] == s[r]:
    l -= 1; r += 1
return s[l+1 : r]
```

`while` 是**先测条件、再执行循环体**。循环体最后一步是移动指针，移动完必须回到条件处重测才知道新位置行不行。所以退出时指针**必然站在第一个不合法的位置上**。

这是结构性的，不是这题特有：二分里 `while lo < hi` 退出后 `lo` 停在第一个 `>= target` 的位置，同一回事。

**±1 消灭不掉，只能选择把它放在哪。** 这题有三个去处：

| 放哪 | 写法 | ±1 出现次数 |
|------|------|------------|
| 循环条件 | 向前看：`while l-1 >= 0 and r+1 < n and s[l-1] == s[r+1]` | 3 次（还要补前置守卫） |
| 返回值 | `return l+1, r-1`，返回下标对 | 2 次 |
| **语法** | `return s[l+1 : r]`，切片右端开区间白送一个 -1 | **1 次** ✓ |

选**出现次数最少**的位置，因为每多出现一次就多一个写错的机会。→ 已抄进 [off-by-one-checklist.md](../notes/off-by-one-checklist.md)。

顺带：偶中心传 `(i, i+1)` 不用先判 `s[i] == s[i+1]`，while 首轮就替你判了，失配直接返回 `""`；`i = n-1` 时 `(n-1, n)` 也会因 `r < n` 立刻退出。**让非法输入自然退化成空区间，比写 `if` 特判省心。**

### 该不该把 expand 封装成函数

[sliding-window-template.md](../notes/sliding-window-template.md) 里论证过滑窗**不该**封装成 `Window` 类，这里的 `expand` 却**该**封装。区别不在代码量，在于：

> **同一道题内它被调用了几次。**

`expand` 在一次解答里真实调用两遍（奇/偶中心），消掉的是复制粘贴；`Window.valid()` 每题只用一次，换题就得打开改，那不是抽象、只是把 8 行摊成 30 行。

判据：**调用次数 ≥ 2 且内部不随场景变**，才封装。不是"看起来该不该抽出来"。

### 四种解法的取舍

| 解法 | 时间 | 空间 | 文件 | 评价 |
|------|------|------|------|------|
| 中心扩展 | O(n²) | O(1) | [sol1.py](sol1.py) | **面试标准答案** |
| 区间 DP | O(n²) | O(n²) | [sol2.py](sol2.py) | 更差，但状态定义能迁移到 516/647/1312，值得写一遍 |
| 二分半径 + 字符串哈希 | O(n log n) | O(n) | — | 竞赛工具，杀鸡用牛刀 |
| Manacher | O(n) | O(n) | [sol3.py](sol3.py) | 收集用，面试不要求 |
| 反转求最长公共子串 | O(n²) | O(n²) | — | **是错的**，见下 |

**区间 DP 的真考点是遍历顺序**，不是转移方程。`f[i][j]` 依赖 `f[i+1][j-1]`（左下方格子），双层正序会读到还没算的值，必须按区间长度递增（或 i 倒序）。

**二分 + 哈希**能成立是因为：对固定中心，半径的可行性单调（半径 k 可行 ⟹ k-1 也可行）。用 s 和 reverse(s) 的前缀哈希 O(1) 判任意区间是否回文。

### 陷阱：反转求最长公共子串是错的

网上常见的"求 s 和 reverse(s) 的最长公共子串"**不对**。随机对拍 4000 组抓到反例：

```
s        = "abacdfgdcaba"
reverse  = "abacdgfdcaba"
最长公共子串 = "abacd"     <- 不是回文!
真正答案     = "aba"

更短的反例: s = "cacaabbcbaac"  该法给 "caab", 答案是 "cac"
```

原因：公共子串只保证"这段在两串里都出现过"，**不保证它们来自同一个位置**。要修得额外校验下标对应（s 中结束于 i 的段必须对应 reverse 中起始于 n-1-i 的段），修完并不比中心扩展简单。
