## 为什么是 BFS

从起点 `s` 出发，BFS 像水波一样一圈圈往外扩：

```
第 0 圈：s 自己
第 1 圈：走 1 步能到的点
第 2 圈：走 2 步能到的点（且前面没到过）
...
```

所以一个点**第一次被碰到时，圈数就是它到 `s` 的最短距离**。如果有更短的路，它早就在更靠前的圈里被碰到了。

DFS 没有这个保证。它一条路走到黑，第一次碰到某个点时，走的可能是绕远的路。比如这张图：

```
0 — 1 — 2 — 3
|           |
└───────────┘
```

从 0 到 3，BFS 在第 1 圈就碰到 3，距离是 1。DFS 如果先走 1，就会沿 0→1→2→3 到达，深度是 3。

这也是前面那个反例里 DFS 会漏的原因：**DFS 的 depth 是它碰巧走出来的长度，不是最短距离**。

## union find + timestamp 行不行？

| 工具 | 能告诉你 | 不能告诉你 |
|---|---|---|
| union find | 加这条边时 u、v 已连通，所以**会成环** | 环**多长**，因为它的 parent 树不是原图的路 |
| timestamp | 沿**当前这条路**绕回来的环长 | 是不是**最短**，因为有岔路时，它只记了碰巧走的那条 |

2360 能用 timestamp，是因为每个点最多一条出边，没有岔路。

你的直觉有一半能用：union find 可以**剪枝**，只对会成环的边做 BFS，因为每个环里至少有一条这样的边。但求长度还是得靠 BFS，这题不剪也能过，先别加。

## 用 DFS 会错在哪

还是前面那张图：

```
edges = [[0,1],[1,2],[2,3],[3,4],[3,0],[4,0]]
```

擦掉 `(3,4)`，从 3 走到 4，3 的邻居顺序是 `2, 0`：

- **DFS**：先走 2，路径是 3→2→1→0→4，长度 4，环长算成 **5**
- **BFS**：第 1 圈有 2 和 0，第 2 圈从 0 碰到 4，长度 2，环长 **3** ✅

按这个邻居顺序把 6 条边都用 DFS 试一遍，最小值是 **4**，但正确答案是 **3**。所以枚举所有边也救不回来。

## 完整思路

1. 枚举每条边 `(u, v)`
2. 擦掉它，从 u 做 BFS
3. 走得到 v，就用 `dist[v] + 1` 更新 `ans`；走不到就跳过
4. `ans` 没更新过就返回 `-1`
