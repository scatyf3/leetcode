## 为什么 return l

用你 blog 里那句话：**l / r 是状态量**。所以要问的是：每次赋值以后，l 和 r 各保证了什么？

- **`l = mid+1` 只在 `nums[mid] < nums[mid+1]` 时执行。**
  所以 l 被赋值以后，l 前面那一步一定是上坡：`nums[l-1] < nums[l]`。
- **`r = mid-1` 只在 `nums[mid] > nums[mid+1]` 时执行。**
  所以 r 被赋值以后，r+1 后面那一步一定是下坡：`nums[r+1] > nums[r+2]`。

**初始值也满足这两条：**
- `l = 0`：`nums[-1] = -∞`，左边是上坡 ✓
- `r = n-2`：`r+1 = n-1`，`nums[n] = -∞`，右边是下坡 ✓

这就是 `r` 的初值取 `n-2` 最自然的原因：它不只是为了防越界，还让右边那条保证从一开始就成立。

**退出时 `l == r+1`，两条保证落在同一个格子上：**
- 左边：`nums[l-1] < nums[l]`
- 右边：`nums[l] > nums[l+1]`

左边上坡、右边下坡，所以 l 就是峰。

## 一句话直觉

l 身后永远是上坡，r+1 身前永远是下坡。两人相向走，走到同一格时，这一格左边上坡、右边下坡，那就是峰。

**为什么不能 return r：** r = l-1 站在上坡那一步上，`nums[r] < nums[r+1]`，它不是峰。

**和其他题的对照：** 这和 35 返回 l 是同一件事。35 的两条保证是「l 左边全 < target，r 右边全 ≥ target」，退出时 l 落在两段的接缝上。162 只是把「全部」换成了「紧挨着的那一步」，因为数组不单调，只能保证局部。

#### 🤖 Claude

你的疑问在于「r 右侧是下坡」说的到底是哪一步。

如果它指的是 r 到 r+1 这一步下坡（`nums[r] > nums[r+1]`），那确实推不出 l 是峰，你的质疑成立。但代码保证的不是这一步，而是往右再挪一格：**r+1 到 r+2 这一步下坡**。

## 为什么是 r+1 那一步

看赋值发生的时刻：

```python
elif nums[mid] > nums[mid+1]:   # 下坡的是 mid → mid+1 这一步
    r = mid - 1                  # 于是 mid = r+1
```

把 `mid = r+1` 代回条件，得到 `nums[r+1] > nums[r+2]`。下坡的起点是 r+1，不是 r。l 那边同理：

```python
if nums[mid] < nums[mid+1]:     # 上坡的是 mid → mid+1 这一步
    l = mid + 1                  # 于是 mid = l-1
```

代回去得到 `nums[l-1] < nums[l]`。上坡的终点是 l。

所以两条保证说的都是 l 和 r 外面那一格的事：

```
   l-1 ↗ l      ...      r+1 ↘ r+2
```

## 退出时这两格合成一格

闭区间退出时 `l == r+1`。把 r+1 换成 l：

- 左边那条：`nums[l-1] < nums[l]`
- 右边那条：`nums[r+1] > nums[r+2]`，也就是 `nums[l] > nums[l+1]`

```
   l-1 ↗ l ↘ l+1
```

两条说的是同一个格子 l，它比两边都大，所以 l 是峰。

## 用 `[1, 3, 2]` 走一遍

| 步 | l | r | mid | 比较 | 动作 |
|---|---|---|---|---|---|
| 初始 | 0 | 1 | | | |
| 1 | 0 | 1 | 0 | 1 < 3，上坡 | l = 1 |
| 2 | 1 | 1 | 1 | 3 > 2，下坡 | r = 0 |
| 退出 | 1 | 0 | | | l = r+1 = 1 |

- l=1：`nums[0] < nums[1]`，即 1 < 3 ✓
- r=0：`nums[1] > nums[2]`，即 3 > 2 ✓

两条落在同一格 1 上，返回 1。

**一句话：** 右边那条保证写成 r+1 而不是 r，是因为 `r = mid - 1` 把下坡的起点放在了 r 的右边一格。退出时 r+1 正好等于 l，两条保证就夹住了同一个格子。
