这种一眼构造数据结构的能直接用吗？

能。这题 set(nums) 就是标准解，不是抄近路 —— 算法本身就是「哈希去重」，set 只是它的实现。O(n) 时间 O(n) 空间，跟你手写一个哈希表循环完全一样。

判断标准只有一条：

面试官问的，是不是这个 builtin 内部的东西？

是 → 不能用。「实现快排」不能 sorted()，「实现 strStr / KMP」不能 s.find()，「atoi」不能 int()。
不是 → 随便用。set / dict / Counter / heapq / sorted 都是公认的原语，跟你用 + 做加法一个性质。
附带的义务只有一个：你得说得出它的复杂度和里面是什么。被追问「set 是怎么实现的」要能答：哈希表，平均 O(1) 插入和查找，最坏（哈希冲突被构造）退化到 O(n)。答得出就没人管你调没调库。

不过你这个写法有个小地方值得提，跟复杂度无关但面试官爱追问：


seen = set()
for x in nums:
    if x in seen:
        return True          # 撞上第一个重复就停
    seen.add(x)
return False
set(nums) 无论如何都要建完整张表、扫完整个数组；这个版本碰到 [1, 1, 后面还有十万个数] 时第二步就返回了。最坏情况一样是 O(n)，但平均和空间上更省。两个都对，能说出这个差别就够了。

另外顺手：


return len(nums) != len(set(nums))
if 条件: return True / else: return False 这个结构里，条件本身已经是答案了，不用再包一层 —— 跟你 242 里那四个多余分支是同一类冗余。
