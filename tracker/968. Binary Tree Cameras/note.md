# 968. Binary Tree Cameras

OA 原题 2(版本存储,每个版本在 cost ≤ t 内重建)的同类题,见 [oa-recap.md](../notes/oa-recap.md)。

---

## 思路是怎么走过来的(原话)

1. 这道题不是染色吗，分成layer0组，layer1组和layer2组，然后看下在哪组安摄像头，总摄像头最少
2. 是不是mod2能cover全
3. dfs的node report 距离摄像头的距离，每个node decide是否安放？
4. 那感觉不是dp啊，还是染色，只不过不是layerwise 的mod 3，而是per node的染色

第 4 条是对的:每个节点最后都是三种颜色之一,颜色由**孩子的颜色**决定,不由深度决定。
下面按这条线整理:前两条为什么不行 → 每个节点往上报什么 → 贪心染色 → 推广成 DP。

---

## 试错 1:按深度 mod 3 分组

摄像头盖住父、自己、子,也就是深度 d−1 / d / d+1。装在深度 ≡ r 的组时,
深度 ≡ r+1 的点靠父节点盖,深度 ≡ r−1 的点**只能靠孩子盖**。有两个问题:

**问题 1:可能盖不全。** 深度 ≡ r−1 的叶子、以及 r = 2 时的根(它没有父节点)都没人管。
7 个点的满二叉树,人数最少的是第 0 组(只有根),但只装根的话 4 个叶子全漏。

**问题 2:排除盖不全的组以后,也不一定最优。** 分组等于全树统一一个相位,但不同分支想要的相位不一样:

```
          R              depth 0
        /   \
       A     B           depth 1
      / \     \
    a1   a2    C         depth 2
               |
               D         depth 3
              / \
            d1   d2      depth 4
```

| r | 摄像头 | 结果 |
|---|---|---|
| 0 | R, D | a1、a2 漏了 |
| 1 | A, B, d1, d2 | 合法,4 个 |
| 2 | a1, a2, C | R 漏了 |

最优是 3 个({A, D, R})。左边想在深度 1 装,右边想在深度 3 装,3 mod 3 = 0,凑不到同一个 r。

## 试错 2:按深度 mod 2 分组

**一定盖得全**(单节点树除外):每个点的父和子都在另一组,任选一组,另一组的非根点被父节点盖,
根有孩子就被孩子盖。所以较小的那组是合法解,最多 ⌊n/2⌋ 个。

**但不最优**:一个摄像头能管 3 层,mod 2 只让它管 2 层。6 个点的链,mod 2 要 3 个,最优 {1, 4} 只要 2 个。

| 分法 | 盖得全吗 | 最优吗 |
|---|---|---|
| mod 3 | 不一定 | 不一定(分支相位不同) |
| mod 2 | 一定 | 不是(约 n/2 对 n/3) |

> 两种都是「全树一个规则」。最优解需要每个分支各自决定 —— 所以要从叶子往上、每个节点自己定。

## 每个节点往上报什么

第 3 条的方向对(后序 DFS,往上报,本地决定),但「离摄像头的距离」一个数不够:

```
      X
     / \
    L   R        L 是摄像头,R 是没装的叶子
```

L 报 0,R 报 ∞,X 取 min 得 1,以为「我被盖住了」——但 R 还没被盖,而且 R 只能指望 X。

一般情况要报**两件事**:

1. 子树里**最近的摄像头**多远 → 能不能顺手盖住上面
2. 子树里**最远的没被盖住的点**多远 → 上面必须在几层之内来救它

覆盖半径是 1 时,这两个数合起来只剩三种有意义的组合,就是三种颜色。

## 贪心染色

| 颜色 | 含义 | 对父节点意味着 |
|---|---|---|
| `NEED` | 我没被盖住 | 父节点**必须**装 |
| `CAM` | 我装了摄像头 | 父节点被我顺便盖住 |
| `COVERED` | 被孩子盖住了,自己没装 | 不用管我,我也盖不了你 |

染色规则(看两个孩子的颜色,按顺序判断):

```
孩子里有 NEED → 我是 CAM          ① 被逼的,没得选
孩子里有 CAM  → 我是 COVERED      ② 顺便被盖住
否则          → 我是 NEED         ③ 故意拖给父节点
```

- **① 必须排在 ② 前面**:一个孩子 CAM、一个孩子 NEED 时,我虽然被盖住了,但 NEED 那个只能靠我。
- **③ 是拖延**:我没被盖,但不自己装,留给父节点装。父节点的摄像头能盖祖父 / 父 / 我三层,比装在我这更划算。

**为什么拖延不亏(交换论证)**:孩子 c 是 NEED,说明 c 和 c 的孩子都没装。任何合法解里,
盖住 c 的摄像头只能在 c、c 的孩子、或我身上。把它挪到我身上:c 照样被盖,我也被盖,
还多盖了我的父节点和另一个孩子;原来它能盖的 c 的孩子,在下面那层已经是 COVERED 了,不需要它。
所以挪完不会变差 —— 「被逼到 ① 才装」就是最优的。

> 能往上拖就拖,拖到再往上一层就有人没救了,才装。

## 推广成 DP:三种颜色都留着

贪心是每个节点**只定一种颜色**。如果证明不了哪种颜色最好,就**三种都留着**,
每种颜色记「这样染的话,子树最少几个摄像头」,到根再取 min:

```python
def dfs(node):                   # 返回 (cam, covered, need) 三种颜色各自的最小代价
    if not node:
        return (inf, 0, 0)       # 空节点不能装,也不用被盖
    L, R = dfs(node.left), dfs(node.right)
    cam     = 1 + min(L) + min(R)                  # 我装了,孩子什么颜色都行
    covered = min(L[0] + min(R[0], R[1]),          # 我没装、被盖住:
                  R[0] + min(L[0], L[1]))          #   至少一个孩子是 CAM
    need    = L[1] + R[1]                          # 我没被盖:孩子都只能是 COVERED
    return (cam, covered, need)

# 答案 = min(根的 cam, 根的 covered) —— 根不能是 need
```

### dp 存的是什么

没有数组、没有 index:状态挂在**每个树节点**上,是递归返回的三元组。后序遍历保证每个节点只算一次,不用 memo。

用自己的话说就是「如果当前 node 是 cam / covered / need,目前最少的摄像头是多少」,补全两个限定:

> **dp[node][s]** = node 处在状态 s 时,**在 node 这棵子树里**、**除 node 以外的点全部被盖住**的前提下,最少几个摄像头。

- 「目前」= 这棵子树。子树外的还没算,父节点在这个基础上接着加。
- 「其他点全被盖住」不能省:父节点只够得着 node 本身,够不着 node 的孩子,所以 node 下面的点必须在子树内解决。
  唯一能留给父节点的是 node 自己 —— 这就是 `need`。

| index | 名字 | node 自己 | 子树里其他点 |
|---|---|---|---|
| 0 | `cam` | 装了 | 全部被盖住 |
| 1 | `covered` | 没装,被某个孩子盖住 | 全部被盖住 |
| 2 | `need` | 没装,也没被盖(等父节点救) | 全部被盖住 |

### 转移怎么来的

- `cam = 1 + min(L) + min(R)`:我装了,孩子什么状态都会被我盖住(包括 need),各取最小。
- `covered`:我没装又要被盖 → **至少一个孩子是 cam**;另一个孩子必须已经被盖(cam 或 covered),
  **不能是 need**,因为我没装、救不了它。左装 / 右装两种取 min。
- `need = L[1] + R[1]`:我没被盖 → 两个孩子都没装;孩子又得已经被盖(我救不了)→ 只能都是 covered。

`need` 里孩子不能取 `NEED`:孩子是 NEED 就必须由我来救,那我就不是 need 了。这正是贪心规则 ① 在 DP 里的样子。

**边界** `(inf, 0, 0)`:空节点不能装(cam = inf,所以它永远当不了「盖住我的那个孩子」);
不用被盖、不花摄像头(covered = 0);need 其实用不上,只出现在 `min(L)` 里,而那里 covered 也是 0。

**答案** `min(dp[root][0], dp[root][1])`:根没有父节点救,不能是 need。

### 手算:7 个点的满二叉树

```
        R
      /   \
     A     B
    / \   / \
   a1 a2 b1 b2
```

| 节点 | cam | covered | need | 说明 |
|---|---|---|---|---|
| 叶子 | 1 | inf | 0 | 孩子都空:要么自己装,要么等父节点;不可能被孩子盖 |
| A / B | 1 | 2 | inf | cam:两个叶子取 need 被 A 盖;covered:一个叶子装,另一个也得自己装;need:叶子不可能是 covered |
| R | 3 | **2** | 4 | covered = A、B 都装 |

答案 min(3, 2) = 2,和贪心一致。

想写成数组也行:节点按后序编号,开 `dp[n][3]`,含义不变。多叉树时 `covered` 的「至少一个孩子 cam」改成:
先对每个孩子加 `min(cam, covered)`,如果一个 cam 都没取到,再加上最小的 `cam − covered` 把一个孩子强制改成 cam。

| | 贪心 | DP |
|---|---|---|
| 每个节点 | 定 1 种颜色 | 3 种颜色各记一个代价 |
| 什么时候拍板 | 当场 | 到根取 min |
| 正确性 | 要证「拖延不亏」 | 枚举了全部,天然对 |

> 贪心 = DP 里每一步只有一个选项不被支配,所以只留它。per node 染色是两者共同的骨架:
> DP 是给每个节点算三种颜色的代价,贪心是证明了只需要一种、直接染上去。

**贪心什么时候失效**:每个节点装摄像头的价格不一样时。比如根 r 只有一个叶子孩子 c,
cost[r] = 100、cost[c] = 1。贪心:c 是 NEED → r 被逼着装,花 100;但装在 c 上同样盖住两个点,只花 1。
「拖给父节点更划算」的前提是所有摄像头一样贵,这条一破,只能用 DP(`cam = cost[node] + ...`)。

## 推广到 OA 版本存储

delta 只能父 → 子 apply,所以一个版本只能被**祖先**盖住。「最近的摄像头」那个量用不上了,
只报一个数 `far`(子树里没被覆盖的点最远多远):

```python
def dfs(v):
    far = 0                                  # 我自己默认没被覆盖
    for c in children[v]:
        f = dfs(c)
        if f >= 0:
            far = max(far, f + w[c])
    if v == root or far + w[v] > t:          # 再往上一层就有人超 t → 被逼着存全量
        ans += 1
        return -inf
    return far
```

| | 968 | 版本存储 |
|---|---|---|
| 谁能盖我 | 父 / 自己 / 子 | 只有祖先或自己 |
| 往上报 | 3 种颜色 | 一个数 far |
| 被逼着装 | 有孩子 NEED | far + 父边 cost > t |
| 根 | 还 NEED 就补一个 | 一定存全量 |

如果原题 delta 可以双向 apply,就回到 968 的情况,要报两个数。

## 坑

- 空节点必须是 `COVERED`:报 `NEED` 会让每个叶子都被逼着装;报 `CAM` 会让叶子以为自己被盖住,于是叶子报 COVERED,叶子的父节点就不知道要救它。
- 根要单独收尾:dfs 返回 `NEED` 时 `ans += 1`。单节点树答案是 1。
- 比较颜色用 `==`,不要用 `is`。`is` 比的是对象身份,能跑只是因为 CPython 缓存了小整数。
