### 问题 1：选出来的那组可能根本盖不全

摄像头能盖住父节点、自己和孩子，也就是深度 d−1、d、d+1。把摄像头放在深度 ≡ r 的那组时，深度 ≡ r+1 的点靠父节点盖住，深度 ≡ r−1 的点只能靠**孩子**盖住。所以深度 ≡ r−1 的叶子没人能盖到。根节点同理，它没有父节点。

拿一棵 7 个点的满二叉树试：

```
        R          depth 0   (1 个)
      /   \
     A     B       depth 1   (2 个)
    / \   / \
   a1 a2 b1 b2     depth 2   (4 个)
```

人数最少的是第 0 组，只有 R 这 1 个点。但只在 R 上装摄像头的话，4 个叶子都盖不到。所以至少要先排除盖不全的组，在剩下的组里选最小的。

### 问题 2：排除掉盖不全的组，结果也不一定最优

这个更要命。分组等于让**整棵树用同一个相位**，可是不同分支想要的相位不一样。下面这棵树你自己 trace 一下：

```
          R              depth 0
        /   \
       A     B           depth 1
      / \     \
    a1   a2    C         depth 2
               |
               D         depth 3
              / \
            d1   d2      depth 4
```

- r = 0 时摄像头是 {R, D}，a1、a2 盖不到。
- r = 1 时摄像头是 {A, B, d1, d2}，能盖全，一共 **4 个**。
- r = 2 时摄像头是 {a1, a2, C}，R 盖不到。

但 3 个就够了，比如 {A, D, R}。左边那支希望摄像头在深度 1，右边那支希望在深度 3，而 3 mod 3 = 0，所以没有任何一个全局的 r 能同时满足两边。

#### 🤖 Claude

对，按 mod 2 分组，**两组都一定能把树盖全**。唯一的例外是整棵树只有一个节点：这时深度为奇数的那组是空的。

### 为什么一定盖得全

分组以后，每个点的父节点和孩子都在另一组。任选一组装摄像头：

- 本组的点自己就有摄像头。
- 另一组里不是根的点，父节点在本组，被父节点盖住。
- 如果根落在另一组，它的孩子在本组。只要根有孩子，就能被孩子盖住。

所以人数少的那组肯定是合法解。用的数量最多 ⌊n/2⌋ 个，因为两组加起来是 n。

### 但它不是最少的

一个摄像头最多能管 3 层（父、自己、子），mod 2 只是让它管 2 层，所以浪费了。最简单的反例是一条 6 个点的链：

```
0 - 1 - 2 - 3 - 4 - 5      (depth)
```

- mod 2 分组：{0, 2, 4} 和 {1, 3, 5} 各 3 个，最少要用 **3** 个。
- 最优解是 {1, 4}，只要 **2** 个：1 盖住 0、1、2，4 盖住 3、4、5。

链越长差距越大：mod 2 大约用 n/2 个，最优大约 n/3 个。

### 小结

| 分法 | 能不能盖全 | 最不最优 |
|---|---|---|
| mod 3 | 不一定，叶子和根可能漏掉 | 不一定，不同分支想要的相位不同 |
| mod 2 | 一定能（只有单节点树除外） | 不是，大约 n/2 对 n/3 |

两种分法都是「全树统一用一个规则」，问题就出在这里。最优解需要每条分支各自决定摄像头装在哪，这又回到了上次的提示 2：从叶子往上，每个节点把自己的状态报给父节点。

## 968 Binary Tree Cameras

```python
class Solution:
    def minCameraCover(self, root: Optional[TreeNode]) -> int:
        NEED, CAM, COVERED = 0, 1, 2      # 没被盖住 / 自己装了摄像头 / 被孩子盖住了
        ans = 0

        def dfs(node):
            nonlocal ans
            if not node:
                return COVERED            # 空节点当成已覆盖：不需要别人管，也盖不了别人
            l, r = dfs(node.left), dfs(node.right)
            if l == NEED or r == NEED:    # ① 有孩子没被盖住 → 必须在这装
                ans += 1
                return CAM
            if l == CAM or r == CAM:      # ② 有孩子装了摄像头 → 我被盖住了
                return COVERED
            return NEED                   # ③ 两个孩子都是 COVERED → 我没被盖住，交给父节点

        if dfs(root) == NEED:             # 根没有父节点可以交，只能自己装
            ans += 1
        return ans
```

### 三种状态从哪来

上一轮说要往上报两件事：子树里最近的摄像头有多远，以及子树里最远的、还没被盖住的点有多远。覆盖半径是 1 的时候，真正有用的只剩三种情况：

| 状态 | 含义 | 对父节点意味着什么 |
|---|---|---|
| `NEED` | 我没被盖住 | 父节点必须装摄像头 |
| `CAM` | 我装了摄像头 | 父节点被我顺便盖住 |
| `COVERED` | 我被孩子盖住了，自己没装 | 父节点不用管我，我也盖不了父节点 |

### 判断顺序为什么是 ① → ② → ③

- **① 必须排第一。** 孩子是 `NEED` 时，能盖住它的只剩它自己、它的孩子和它的父节点（也就是当前节点）。它自己和它的孩子在之前那层已经决定不装了，所以只能当前节点装。这一步没有选择余地。
- **② 不能排在 ① 前面。** 一个孩子是 `CAM`、另一个孩子是 `NEED` 时，当前节点虽然已经被盖住，但还是得装摄像头，因为那个 `NEED` 的孩子只能靠它。
- **③ 是在拖延。** 当前节点没被盖住，但它故意不装，留给父节点装。原因是父节点处的摄像头能盖住三层（祖父、父、当前节点），比在当前节点装更划算。贪心的思路就是：能往上推迟就推迟，被逼到 ① 才装。

### 几个坑

- 空节点必须返回 `COVERED`。如果返回 `NEED`，每个叶子都会被逼着装摄像头；如果返回 `CAM`，叶子的父节点会以为自己被盖住了。
- 根节点处理完还要再检查一次。比如只有一个节点的树，`dfs` 返回 `NEED`，最后答案要补成 1。
- 用来自测的几个用例：
  - 单节点，答案 1
  - 6 个点的链，答案 2
  - 7 个点的满二叉树，答案 2
  - 上一轮那棵 9 个点的树，答案 3

## 推广：OA 版本存储

版本存储和摄像头有一个关键区别：delta 只能从父版本往子版本应用，所以一个版本只能被祖先盖住，不能被后代盖住。这样「最近的摄像头」这个量就用不上了，每个节点只需要往上报一个数：子树里还没被盖住的点里，离我最远的有多远。

```python
import math

def min_full(children, w, root, t):
    """children[v] = v 的子版本；w[v] = 从父版本 apply 到 v 的 delta cost；
    返回最少存多少个全量，使得每个版本从最近的全量祖先重建的 cost ≤ t"""
    ans = 0

    def dfs(v):
        nonlocal ans
        far = 0                               # v 自己默认还没被覆盖，距离 0
        for c in children[v]:
            f = dfs(c)
            if f >= 0:                        # 孩子子树里还有没被覆盖的
                far = max(far, f + w[c])
        if v == root or far + w[v] > t:       # 再往上推一层就有人超 t → 被逼着存全量
            ans += 1
            return -math.inf                  # 整棵子树都被覆盖了
        return far

    dfs(root)
    return ans
```

### 和 968 对照

| | 968 | 版本存储 |
|---|---|---|
| 谁能盖住我 | 父节点、自己、孩子 | 只有祖先或自己 |
| 往上报什么 | 3 种状态 | 一个数 `far`（没覆盖的点里最远的距离） |
| 什么时候被逼着装 | 有孩子是 `NEED` | `far + 到父节点那条边的 cost > t` |
| 根 | 还是 `NEED` 就补一个 | 一定是全量（没有父版本可以 apply） |

两题的贪心内核是一样的：能往上拖就往上拖，拖到再往上一层就有点要超标的时候才装。

> 这类树上覆盖的问题，统一的写法是：后序遍历，每个节点往上报「下面还有多少债没还」，被逼到不得不还的时候才还。

如果版本是一条链，就是这个模板退化成一个循环：从后往前累加 cost，超过 t 就存一个全量。

另外，如果 OA 原题的 delta 其实可以双向 apply，也就是子版本也能用来重建父版本，那就回到 968 的情况，要报两个数，「最近的摄像头」那个量又用得上了。我对拍用的是单向 apply 的版本，原题面你可以再对一下。

#### 🤖 Claude

对，「per node 染色」这个理解很准。每个节点最后都会落到 `NEED / CAM / COVERED` 三种颜色里的一种，**颜色由两个孩子的颜色决定，跟深度无关**。所以它和 mod 3 的区别就在这里：mod 3 是按深度一刀切，这里是每个节点看自己的局部结构来定。

需要更正的是：我那份模板严格说是**贪心**，不是 DP。我之前在 OA 分析里写「树形 DP」，指的是另一种写法。两种写法的区别如下。

### 贪心：每个节点只定一种颜色

模板里，每个节点拿到孩子的颜色以后，**确定地**选一种颜色就往上报。这就是一个从下往上的染色规则，跟你说的一样：

```
孩子里有 NEED  → 我是 CAM
孩子里有 CAM   → 我是 COVERED
否则           → 我是 NEED
```

### DP：每个节点三种颜色都留着，各记一个代价

如果不确定哪种颜色好，就三种都算，每种记「这样染的话，子树里最少要几个摄像头」：

```python
def dfs(node):                       # 返回 (cam, covered, need) 三种颜色各自的最小代价
    if not node:
        return (inf, 0, 0)           # 空节点不能装摄像头，也不需要被盖
    L, R = dfs(node.left), dfs(node.right)
    cam     = 1 + min(L) + min(R)                         # 我装了，孩子随便什么颜色都行
    covered = min(L[0] + min(R[0], R[1]),                 # 我没装、被孩子盖住：
                  R[0] + min(L[0], L[1]))                 #   至少一个孩子是 CAM
    need    = L[1] + R[1]                                 # 我没被盖：孩子都只能是 COVERED
    return (cam, covered, need)

# 答案 = min(根的 cam, 根的 covered)，根不能是 need
```

### 两者的关系

| | 贪心 | DP |
|---|---|---|
| 每个节点 | 只定 1 种颜色 | 3 种颜色都留着，各记一个代价 |
| 做决定的时机 | 当场定 | 到根才取 min |
| 正确性靠什么 | 要证明「能拖就拖」永远不亏 | 枚举了所有情况，天然正确 |
| 什么时候用 | 能证明贪心对的时候 | 证不出来，或者有权重让贪心失效（比如每个节点装摄像头的价格不一样） |

> 贪心 = DP 里每一步都只有一个选项不被支配，所以只留那一个。

对 968 来说，「被孩子逼着才装、否则推给父节点」永远不亏，所以 DP 的三列可以压成一种颜色。但如果每个节点装摄像头的价格不一样，推给父节点可能更贵，这时贪心就不对了，只能用 DP。

所以你说的「per node 染色」是对的。更完整的说法是：**DP 版本是给每个节点算三种颜色的代价，贪心版本是证明了只需要一种，直接染上去。**

这道题的 DP 没有数组，也没有按 index 存。**状态挂在每个树节点上**：每个节点存一个长度为 3 的元组，由递归的返回值往上传。后序遍历保证每个节点只算一次，所以不需要额外的 memo。

## 每个位置的含义

`dp[node] = (cam, covered, need)`，三个值都是「**node 这棵子树里**最少要几个摄像头」，区别在于对 node 自己的要求不同：

| index | 名字 | node 自己 | 子树里的其他点 |
|---|---|---|---|
| 0 | `cam` | 装了摄像头 | 全部被盖住 |
| 1 | `covered` | 没装，但被某个孩子盖住 | 全部被盖住 |
| 2 | `need` | 没装，**也没被盖住**（等父节点来救） | 全部被盖住 |

三种状态都要求「子树里除了 node 以外的点全被盖住」。原因是 node 一旦返回给父节点，它下面的点就再也没人能盖了：父节点只能盖到 node 本身，盖不到 node 的孩子。只有 node 自己还可以留到父节点那里处理，这就是 `need` 存在的意义。

## 转移

```python
cam     = 1 + min(L) + min(R)
```
我装了摄像头，两个孩子不管处在哪种状态都会被我盖住，包括 `need`，所以各取三个里最小的。

```python
covered = min(L[0] + min(R[0], R[1]),
              R[0] + min(L[0], L[1]))
```
我没装，又要被盖住，所以**至少一个孩子是 `cam`**。另一个孩子必须已经被盖住，取 `cam` 或 `covered`，**不能取 `need`**，因为我没装摄像头，救不了它。两种情况分别是左孩子装或者右孩子装，取较小的。

```python
need    = L[1] + R[1]
```
我没装也没被盖，说明两个孩子都没装（否则我会被盖住）。孩子又必须已经被盖住（我救不了它们），所以两个孩子都只能是 `covered`。

## 边界和答案

```python
if not node: return (inf, 0, 0)
```
- `cam = inf`：空节点上不能装摄像头。这样空孩子永远不会被当成「盖住我的那个孩子」。
- `covered = 0`：空节点不需要被盖，也不消耗摄像头，当成已经盖好了。
- `need = 0`：其实用不上，只在 `cam` 的 `min(L)` 里出现，而那里 `covered` 也是 0，不影响结果。

答案是 `min(dp[root][0], dp[root][1])`。根没有父节点可以救它，所以不能取 `need`。

## 手算一遍：7 个点的满二叉树

```
        R
      /   \
     A     B
    / \   / \
   a1 a2 b1 b2
```

**叶子**（两个孩子都是空节点 `(inf, 0, 0)`）：
- cam = 1 + 0 + 0 = **1**
- covered = 需要一个孩子装摄像头，但空节点的 cam 是 inf，所以是 **inf**
- need = 0 + 0 = **0**

所以叶子是 `(1, inf, 0)`：要么自己装，要么等父节点救，不可能被孩子盖住。

**A**（两个孩子都是 `(1, inf, 0)`）：
- cam = 1 + 0 + 0 = **1**：A 装了，叶子都取 need，被 A 盖住
- covered = 1 + min(1, inf) = **2**：一个叶子装了，另一个叶子也得自己装
- need = inf + inf = **inf**：叶子不可能是 covered

所以 A = B = `(1, 2, inf)`。

**R**（两个孩子都是 `(1, 2, inf)`）：
- cam = 1 + 1 + 1 = 3
- covered = 1 + min(1, 2) = **2**：A、B 都装
- need = 2 + 2 = 4

答案 = min(3, 2) = **2**，和贪心的结果一致。

## 补充

如果想写成数组形式：把节点按后序编号，开一个 `dp[n][3]` 就行，含义完全一样。但树形 DP 一般直接用返回值传，更省事。

如果是多叉树，`covered` 的「至少一个孩子是 cam」写法会变。常用的做法是先对每个孩子取 `min(cam, covered)` 加起来；如果没有任何一个孩子取到 cam，就再加上把某个孩子强制改成 cam 的最小代价，也就是所有孩子里 `cam - covered` 最小的那个差值。
