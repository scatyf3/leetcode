# 416. Partition Equal Subset Sum

怎么理解，首先切两半是个投机操作，其次怎么从若干数字找sum of target？

用一个reachable的set迭代，每一个数都迭代增加这个set，当然为了复杂性，我们只把小于target的丢到这个set里

这是最终版的sum of n吗，2sum和3sum都是特化吗？
不是耶，这个返回t/f，2 sum和3sum返回index，区别见表

| | 2Sum / 3Sum | 416 子集和 |
|---|---|---|
| 选几个数 | **固定 k 个** | **任意个** |
| 要返回什么 | 具体下标 / 所有不重复组合 | 只要回答能不能 |
| 数值 | 可以为负，范围很大 | 非负，和不超过 2×10⁴ |
| 工具 | 哈希 / 排序 + 双指针 | reachable set（背包） |
| 复杂度 | O(n^{k-1}) | O(n · target) |

所以这个家族应该按约束来分，不是一条特化链：

- 固定 k 个，要输出组合：排序 + 双指针（1、15 3Sum、18 4Sum）
- 任意个，每个数最多用一次，只问能不能 / 有几种：0/1 背包，也就是 reach set（416；494 Target Sum 是它的计数版）
- 任意个，每个数可以重复用：完全背包（322 Coin Change、518 Coin Change II、279 Perfect Squares）

> 看到这类「凑和」的题，先问两件事：个数固定吗？每个数能重复用吗？ 这两个答案定了，用哪个工具也就定了。

---

### 为什么不能互相套

- **416 用不了双指针**：个数不固定，子集有 2ⁿ 个，没有「固定 k 个再收缩两端」的结构可利用
- **3Sum 用不了 reach set**：set 不记选了几个（保证不了恰好 3 个）、不记怎么凑的（输出不了组合），
  数值范围大时 set 还会炸。硬套得把状态换成 `(已选个数, 和)` 再记路径，比排序 + 双指针慢得多

### 但 2Sum 的哈希表本身就是 reach set

```python
seen = set()          # 扫过的数 = 「只选 1 个」能凑出的和
for x in nums:
    if target - x in seen: ...
    seen.add(x)
```

2Sum = 「只选 1 个」的子集和 + 一次查询。416 把「选 1 个」放开成「选任意个」，
所以每步要把整个集合平移 x 再并回去，而不是只加一个数。
