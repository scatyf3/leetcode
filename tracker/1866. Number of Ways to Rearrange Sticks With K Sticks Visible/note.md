# 1866. Number of Ways to Rearrange Sticks With K Sticks Visible


用dp递推。
## pass1
**想法**：看有几根被挡住，把遮盖关系组织成组，再排。方向对：每根看得见的和它后面被它挡住的打包成一组，k 根看得见 ⇔ 分成 k 组。但两处是被迫的：
- 组内最高的必须站第一个，其余随便排 → s 根一组 (s-1)! 种，不是 s!
- 组之间只能按组头从矮到高排 → 不能再乘 k!

**分组直接数不好算 → DP，盯最矮那根**（代码在 sol.py）：
- 单独一组：组头最矮，一定在最左边，看得见 → `dp[i-1][j-1]`
- 插在别人后面：被挡住，有 i-1 个位置 → `(i-1) * dp[i-1][j]`

填空踩的坑：
- `dp[0][0] = 1`，不是 0（空排列算一种，`dp[1][1]` 靠它）
- 内层 `range(1, min(k, sticks) + 1)`，漏了 `seen == sticks`
- 两个分支存的是**排法数**（查表），不是木棍数；整段没读过 dp 旧值就不是 DP
- `return dp[n][k]`，不是 `[n+1][k+1]`

**c(n, k) 是第一类斯特林数**，不是组合数 C(n, k)：n 人坐 k 张圆桌，一组 = 一张桌。c(4,2) = 11，C(4,2) = 6。
- 没有公式：组的大小怎么分会影响数量，c(4,2) 里 3+1 有 8 种、2+2 只有 3 种，只能分情况加
- 特殊 k 有：c(n,n) = 1，c(n,1) = (n-1)!，c(n,n-1) = C(n,2)
- 也是 x(x+1)…(x+n-1) 展开后 x^k 的系数，一个括号一个括号乘开就是这个 DP

## 讨论(2026-11-20)

**初始状态只有 `dp[0][0] = 1`**,别的都不用手设:
- `dp[0][j]`(j ≥ 1)是第 0 **行**:0 根木棍看不见 j 根 → 0,建表时已经是 0
- `dp[i][0]`(i ≥ 1)是第 0 **列**:有木棍时最左那根一定看得见 → 0;内层 `seen` 从 1 开始,这列不会被改写
- `dp[1][1]` 是推出来的:`dp[0][0] + 0 * dp[0][1] = 1`
- 判断是不是 base case:看递推会不会读到算不出来的格子。每格只读上一行,第 0 行只有 `dp[0][0]` 非零

**`sticks` 是根数,不是木棍编号**:`dp[i][j]` 只看相对高矮,任意 i 根互不等高的都一样。想象成**从高往低插**:0 = 空,1 = 最高,n = 最矮。
- 必须从高往低:新来的比场上都矮,不会挡住任何人,只需要管它自己看不看得见
- 反过来从矮往高插,新来的最高,会挡住身后的,j 怎么变说不清

**`(i-1) ×` 乘的是位置数,数值上 = 插入前的木棍数**:i-1 根木棍有 i 个空位,最左那个让它看得见(左上);其余 i-1 个空位每个都紧跟在某根木棍后面 → "插非最左" = "选一根站到它正后面",一定被挡。
- 例 `dp[3][2]`:`dp[2][2]` 只有 `2 3`,1 插 `2 _ 3 _` 两个空位 → `2 1 3`、`2 3 1`;`dp[2][1]` 只有 `3 2`,1 插最左 → `1 3 2`。共 3

**自己写的版本**:`j` 跑到 `k` 不限 `min(k, i)` 也对(`j > i` 读到的都是 0);但 `dp[i][j] = dp[i-1][j-1] + (i-1) * dp[i-1][j] % MOD` 返回值会超过 MOD(n=20, k=11 → 3647427971)。坑在 `%` 的优先级:和 `*` 同级、比 `+` 高,只作用在乘积项上。
