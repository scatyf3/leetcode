#### 🤖 Claude

这道题的递推是在"删掉最矮那根"上展开的。关键就一句话：**最矮的木棍挡不住任何人，它自己能不能被看见，只看它是不是排在最左边。**

### 为什么挑最矮的
假设 `i` 根木棍已经排好了，把最矮的那根（高度 1）拿掉：

- **它挡不住别人**：别人能不能被看见，只取决于左边有没有比自己高的。它比所有人都矮，在不在都一样。所以拿掉以后，剩下 `i-1` 根里谁看得见、谁看不见都不变。
- **它自己能不能被看见，只看位置**：排在最左边，左边没人，就看得见；排在其他任何位置，左边总有人比它高，就被挡住。

剩下的 `i-1` 根高度是 `2..i`，不是 `1..i-1`。但"看得见"只跟相对大小有关，所以这些排法跟 `i-1` 根木棍的排法一一对应，可以直接查 `dp[i-1][·]`。

### 递推
反过来，把它**插回**一个 `i-1` 根木棍的排列里，一共有 `i` 个空位：

| 插在哪 | 它自己 | 别人 | 方案数 |
|---|---|---|---|
| 最左边（1 个空位） | 看得见，`+1` | 不变 | `dp[i-1][j-1]` |
| 其他位置（`i-1` 个空位） | 被挡住，`+0` | 不变 | `(i-1) * dp[i-1][j]` |

```
dp[i][j] = dp[i-1][j-1] + (i-1) * dp[i-1][j]
```

### 用 n=3, k=2 验证一下
答案应该是 3 种：`[1,3,2]`、`[2,1,3]`、`[2,3,1]`。

- 从"2 根木棍、看得见 1 根"的 `[3,2]` 出发，把 1 放最左边 → `[1,3,2]`
- 从"2 根木棍、看得见 2 根"的 `[2,3]` 出发，把 1 插进 2 个非最左的空位 → `[2,1,3]`、`[2,3,1]`

`dp[3][2] = dp[2][1] + 2·dp[2][2] = 1 + 2 = 3` ✓

### 换成最高那根为什么不行
最高的那根会把右边所有人都挡住。它插在哪，会改变一大片别人的可见性，状态就拆不开了。**选一个对别人没影响的元素来拆，是这类排列计数 DP 的通用套路。**

不对。真正的初始状态只有一个：**`dp[0][0] = 1`**。另外两个都不用手动设。

**`dp[0][j]`（j ≥ 1）**：这是 sticks=0 的那一**行**，不是一列。0 根木棍不可能看见 j ≥ 1 根，所以都是 0。建表时已经全填了 0，不用再写。

**`dp[i][0]`（i ≥ 1）**：这才是 seen=0 那一列。只要有木棍，站最左边那根一定看得见，所以 seen 至少是 1，这一列全是 0。内层循环 `seen` 从 1 开始，这列不会被改写，保持初始的 0，正好对。

**`dp[1][1]`**：这是递推算出来的，不是初始状态：
```
dp[1][1] = dp[0][0]       + (1-1) * dp[0][1]
         = 1              + 0
         = 1
```
这也是笔记里那条坑的意思：`dp[0][0]` 写成 0 的话，`dp[1][1]` 就算成 0，后面整张表都变成 0。

判断某格是不是 base case，可以看递推式会不会读到表外，或者读到算不出来的格子。这里每一格只依赖上一行，第 0 行又只有 `dp[0][0]` 非零，所以只要给它一个值，其余都能推出来。

0是最大的stick，n是最小的stick，对吗

#### 🤖 Claude

不太对。`dp` 的第一维 `sticks` 是**根数**，不是木棍的编号。0 表示一根都没有，不对应任何一根木棍。

`dp[i][j]` 只看相对高矮：随便拿 i 根高度互不相同的木棍，结果都一样。所以没有"第 0 根是哪根"这种说法。

不过你想的方向是对的，这个递推确实可以理解成**从高往低一根根插进去**：
- `sticks = 0`：空排列
- `sticks = 1`：放进最高的那根
- `sticks = i`：插入第 i 高的那根
- `sticks = n`：最后插入最矮的那根

这样纠正一下就对了：1 是最高，n 是最矮，0 是空。

**为什么必须从高往低插**：每次新插的那根比已经在场的都矮，所以它不会挡住任何已有的木棍，原来看得见几根还是几根，只需要考虑它自己：
- 插在最左边：前面没人挡，看得见，对应 `dp[i-1][j-1]`
- 插在其余 i-1 个空位：前面一定有更高的，被挡住，对应 `(i-1) * dp[i-1][j]`

要是反过来从矮往高插，新来的是最高的，会把它身后原本看得见的木棍挡住，j 怎么变就说不清了。这跟 sol.py 注释里"盯最矮那根"是一回事：最后插入的就是最矮的。


- 插空位 A：`2 1 3`，1 被 2 挡住，看得见的还是 2 和 3，共 2 根 ✓
- 插空位 B：`2 3 1`，1 被 3 挡住，还是 2 根 ✓

**左上 `dp[2][1]` = 1**：只看得见一根的排法是 `3 2`。1 只能插最左边，得到 `1 3 2`，看得见 1 和 3，共 2 根 ✓

**推广**：i-1 根木棍之间和两头一共有 i 个空位。最左边那个让 1 看得见，归到左上那一项；剩下 **i-1** 个空位里，1 前面一定有更高的木棍，必定被挡住，而且 1 最矮，也不会挡住别人，所以 j 不变。旧的每一种排法都能对应出 i-1 种新排法，于是正上那一项要乘 (i-1)。

#### 🤖 Claude

对，数值上就是插入前场上的木棍数，也就是 `sticks - 1`，代码里写的是 `(sticks - 1) * dp[sticks - 1][seen]`。

之所以刚好等于木棍数，是因为每根木棍的右边恰好有一个空位：

```
 _ 2 _ 3 _
     ↑   ↑
  2 的右边  3 的右边
```

除了最左边那个空位，其余每个空位都紧跟在某根木棍后面。所以"插到非最左的空位"就等于"选一根木棍，站到它正后面"。有几根木棍就有几种选法。

这也说明了 1 为什么必定被挡：它紧贴在选中的那根后面，而那根一定比 1 高。

#### 🧑 我

```python
class Solution:
    def rearrangeSticks(self, n: int, k: int) -> int:
        MOD=10**9+7
        dp = [[0 for i in range(k+1)] for i in range(n+1)]
        dp[0][0]=1
        for i in range(1,n+1):
            for j in range(1,k+1):
                # dp[i-1][j-1] new stick is seen
                # dp[i-1][j] new stick not seen
                dp[i][j]=dp[i-1][j-1] + (i-1) * dp[i-1][j] % MOD
        # print(dp)
        return dp[n][k]
```

规则是**按数组顺序，一个一个插进 BST**：

1. 第一个数当根。
2. 之后每来一个数，都从根开始往下走：比当前节点小就往左，比它大就往右。
3. 走到空位就停下，挂在那里。

已经放好的节点不会再移动，新来的数只能挂在最底下。

**用 `[3,4,5,1,2]` 走一遍**：

| 插入 | 怎么走 | 结果 |
|---|---|---|
| 3 | 树是空的，当根 | `3` |
| 4 | 4 > 3，往右，空位 | 3 的右孩子 |
| 5 | 5 > 3 往右 → 5 > 4 往右，空位 | 4 的右孩子 |
| 1 | 1 < 3，往左，空位 | 3 的左孩子 |
| 2 | 2 < 3 往左 → 2 > 1 往右，空位 | 1 的右孩子 |

```
    /   \
```

1. 根必须第一个：只有 1 种选择。
2. 左右子树内部各自有自己的合法顺序：分别有 `ways(左)` 和 `ways(右)` 种。

$$

#### 🤖 Claude

`left` 和 `right` 是两个**列表**，各自是左右子树的**插入序列**：

```python
root  = 3
left  = [1, 2]       # 比 3 小的数，保持原来的先后顺序
right = [5, 4, 6]    # 比 3 大的数，保持原来的先后顺序
```

它们和 `nums` 是同一种东西：一个插入顺序，能建出一棵 BST，只是规模更小。`right = [5,4,6]` 单独拿出来，就能建出那棵以 5 为根的子树。

所以要求"右子树内部有几种合法顺序"，问的就是"`[5,4,6]` 能建出的这棵 BST 有几种排法"。这个问题 `ways` 本来就会算，对 `right` 再调用一次就行。所以是的，这里要**递归**：

| 调用 | 根 | 左组 | 右组 | 结果 |
|---|---|---|---|---|
| `ways([3,1,2,5,4,6])` | 3 | `[1,2]` | `[5,4,6]` | C(5,2) × ways([1,2]) × ways([5,4,6]) |
| `ways([1,2])` | 1 | `[]` | `[2]` | C(1,0) × 1 × 1 = 1 |
| `ways([5,4,6])` | 5 | `[4]` | `[6]` | C(2,1) × 1 × 1 = 2 |
| `ways([])` | | | | base case，返回 1 |

最外层算出来是 10 × 1 × 2 = 20，减 1 得 19。

返回值里要把 `ways(left)` 和 `ways(right)` 乘上去，每次相乘后都取一下模。还有之前说的递归深度：有序输入会让这个递归一路往下深入 1000 层，Python 默认上限会不够用。

这一组是**组合计数**的题，放在一起是因为它们共用一套工具，而且这套工具有先后依赖。它对应 blog 的 [组合计数](blog/docs/advanced/combinatorics.md) 那一页，也就是 [plan.json:142](tracker/dashboard/plan.json#L142) 里「ACM 进阶」下的一节。

**共同点**：题目都问"有多少种方式"，答案大到必须对 10⁹+7 取模。不能把方案一个个列出来，要用公式或递推直接算个数。

**依赖链**：前面是工具，后面是应用。

```
50  快速幂 ──► 372 快速幂 + 取模 ──► 模逆元 pow(x, MOD-2, MOD)
                                          │
                                          ▼
                              2400 组合数取模模板 C(n,k) mod p
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    ▼                     ▼                     ▼
             2929 隔板法 + 容斥    1866 第一类斯特林数    1569 递归里套组合数
```

- **为什么 50 和 372 也在这组**：它们本身不是计数题，是前置工具。$C(n,k) = \frac{n!}{k!(n-k)!}$ 要在模下做**除法**，除法得换成乘逆元，而逆元要靠快速幂来求。这正是今天 1569 闭式 `n!/∏size` 碰到的问题。
- **2400 是模板**：把组合数取模练熟。之后的题都是"先把问题化成 C(n,k) 或类似的式子，再套这个模板"。
- **后三道是三种不同的化法**：
  - 2929：分东西的问题，用隔板法化成 C，有上限的部分用容斥减掉。
  - 1866：化不成闭式，只能 DP。表的形状和杨辉三角一样，今天对比过。
  - 1569：在树结构上递归，每层乘一个 C。

标签从 L1.5 到 L4，大致按这条链从工具到应用越来越难。

今天做下来还有两个共性：
- **`%` 的优先级坑**：1866 和 1569 你都遇到了。这类题每一步都要取模，`a + b * c % MOD` 这种写法最容易出错。
- **杨辉三角形状的 DP**：1866 和 1569 里的组合数都是"每格只读上一行两格"。

另外有个关联可以留意：「构造 / 思维」组里的 **1916 Count Ways to Build Rooms in an Ant Colony** 和 1569 是同一个问题的推广版，都是数一棵树的拓扑序个数。区别是 1569 是二叉树，1916 是任意多叉树，要直接用 `n!/∏size(v)` 加逆元来算。1569 做完以后可以接着做它。
