### 这是啥算法

不属于 DP / 二分 / 滑窗这些通用范式，是一个**专门的经典算法**：字典序下一个排列（Narayana Pandita，14 世纪），C++ `std::next_permutation` 就是它。第一次见基本想不出来，面试默认你见过。

### 直觉：手算 `1342` 的下一个

> 用 1、2、3、4 各一次，找比 `1342` 大的数里最小的那个。

**1. 前面能保留多少位就保留多少位**（越靠左越不想动）

| 尝试保留 | 剩下的数 | 剩下最大能排成 | 结论 |
|---|---|---|---|
| `134` | `2` | `2` | 就是自己 ✗ |
| `13` | `4 2` | `42` | 已经到顶 ✗ |
| `1` | `3 4 2` | `432`，现在才 `342` | 还有空间 ✓ |

所以要改的是第二位的 `3`。

> **尾巴是从大到小排的 = 已经到顶。** 这就是「降序后缀」。第 1 步从右往左扫，就是在找「从哪开始尾巴还没到顶」。

**2. 这一位只变大一点点**：从后面的 `4 2` 里挑比 `3` 大的最小数 → `4`，得到 `14 _ _`。

**3. 后面排成最小**：第二位已经变大了，后面怎么排都比原数大，所以排成最小 `23`。答案 **`1423`**。

核对一下，以 1 开头的排列按顺序是 `1234, 1243, 1324, 1342, 1423, 1432`，`1342` 后面就是 `1423` ✓

> **尽量保留左边 → 找第一个「后面还有空间」的位置 → 把它换大一点点 → 后面排成最小。**

### 和「数字 +1」是一回事

`1299 + 1 = 1300`：右边的 `99` 到顶了，所以动 `2`；`2` 只加 1 变成 `3`；右边重置成 `00`。排列只是多了一条限制：只能用手上这几个数。

| +1 | 排列 |
|---|---|
| 到顶的 `99` | 降序后缀 |
| 最右能变大的那一位 | 降序后缀左边紧挨着的 `i` |
| 只加最小的量 | 和后缀里「比它大的最小数」交换 |
| 右边重置成 `00` | 后缀排成升序 |

另一个视角：字典序里**前缀相同的排列排在一起，形成一块**。后缀降序，就说明当前排列已经是这一块的最后一个，只能退到更短的前缀，进入下一块的第一个排列。

### 填空版的三个 bug

| | 我写的 | 应该是 | 为什么 |
|---|---|---|---|
| 1 | `nums[i] < nums[i+1]` | `nums[i] >= nums[i+1]` | 循环意思是「还在降序后缀里就往左走」，条件反了；用 `>=` 是因为相等也算到顶（`[1,1]`） |
| 2 | `nums[j-1] < nums[j]` | `nums[j] <= nums[i]` | 要找的是比 **`nums[i]`** 大的，不是后缀内部相邻比较；`<=` 跳过相等的（`[1,5,1]` → `[5,1,1]`） |
| 3 | `l = i` | `l = i + 1` | `nums[i]` 是刚换上去的那一位，不属于后缀；全降序时 `i = -1`，`l = 0` 正好反转整个数组，不用特判 |

拿 `[1,3,5,4,2]` 跑原版：第 1 步停在 `i=3`（应该是 1）；修好后第 2 步又把 `3` 和 `2` 换了（应该换 `4`）。

### 代码

```python
class Solution:
    def nextPermutation(self, nums: list[int]) -> None:
        n = len(nums)

        # 1. 从右往左跳过降序后缀，停在第一个 nums[i] < nums[i+1] 的位置
        i = n - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1

        # 2. 在后缀里从右往左找第一个比 nums[i] 大的数，就是「比它大的最小数」
        if i >= 0:
            j = n - 1
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]

        # 3. 后缀仍是降序，反转成升序；i = -1 时正好反转整个数组
        l, r = i + 1, n - 1
        while l < r:
            nums[l], nums[r] = nums[r], nums[l]
            l += 1
            r -= 1
```

时间 O(n)，空间 O(1)。

- **为什么从右往左第一个比它大的就是最小的**：后缀是降序，越往右越小。
- **为什么交换后后缀还是降序**：`nums[j]` 左边都 ≥ 它，右边都 ≤ `nums[i]`，把 `nums[i]` 放进 `j` 这个位置，顺序不会乱。所以第 3 步反转就行，不用 sort。

测试用例：`[1,3,5,4,2]` → `[1,4,2,3,5]`，`[1,5,1]` → `[5,1,1]`，`[1,1]` → `[1,1]`，`[3,2,1]` → `[1,2,3]`，`[1]` → `[1]`。可以再手算一遍 `1432` → `2134`，这个例子要一直退到第一位。

### 可迁移

> 「求下一个 / 恰好大一点」类问题都问这三句：**哪一位是最右边还能变大的？它最少变大多少？它右边怎么重置成最小？**

同一个套路：[556. Next Greater Element III](https://leetcode.com/problems/next-greater-element-iii/)（几乎原题）、[60. Permutation Sequence](https://leetcode.com/problems/permutation-sequence/)（逐位确定第 k 个）、二进制计数、按字典序生成下一个组合。

分类见 [paradigms/lexicographic-greedy.md](../../blog/docs/paradigms/lexicographic-greedy.md):字典序比较 = 高位优先,31 / 556 / 670 / 738 / 402 / 60 都是「改哪一位、改成什么、其余怎么办」三问。

树的视角(降序后缀 = 一路都是最后一个孩子,往上爬 → 下一个兄弟 → 最左路径,和 BST 中序后继、二进制 +1 同形)见 [lexicographic-greedy.md §1.5](../../blog/docs/paradigms/lexicographic-greedy.md#15-树的视角next-permutation--排列树上的下一个叶子)。

### pass2：智力版看不懂 → 先在 46 的那棵树上理解

> 46 的回溯树，每层分支**从小到大**画，叶子从左到右 = 字典序。**下一个排列 = 右边紧挨着的那片叶子。**

```
   1          2          3        ← 第 0 位
  / \        / \        / \
 2   3      1   3      1   2      ← 第 1 位
 |   |      |   |      |   |
 3   2      3   1      2   1
123 132    213 231    312 321
```

从一片叶子走到下一片 = 模拟 DFS 的一步（像送快递：本单元没下一户 → 下一个单元的第一户）：

1. **往上退**，直到某个节点右边还有兄弟（退得越高，改的位越靠左、跳得越远，所以能少退就少退）
2. **往右一格**，到紧挨着的兄弟
3. **往下靠左走到底**（进了新分支，要里面最小的）

不用递归：递归是为了走很多条路、记住回来从哪继续；这里只走一条确定的路。递归栈里的东西在叶子上都能读出来 —— 第 i 层选的是 `nums[i]`，第 i 层能选的是 `nums[i:]`。

#### 傻版：直接翻译这三步，O(n²)

```python
class Solution:
    def nextPermutation(self, nums: List[int]) -> None:
        n = len(nums)
        pool = []                           # 回溯时退回来的数 = 这一层还能选的数
        for i in range(n - 1, -1, -1):      # 从叶子往上退，一层一层退
            pool.append(nums[i])            # 退出第 i 层：把这一位用的数放回候选池
            bigger = [x for x in pool if x > nums[i]]
            if bigger:                      # 这一层还有没走过的、更大的分支
                pick = min(bigger)          # 选右边紧挨着的那个分支
                pool.remove(pick)
                nums[i] = pick
                nums[i + 1:] = sorted(pool) # 往下走，每层都选最小的
                return
        nums.sort()                         # 退到 root 都没有分支 → 回到第一片叶子
```

`[1,3,5,4,2]` 走一遍：

| i | nums[i] | pool | 比它大的 | |
|---|---|---|---|---|
| 4 | 2 | [2] | 无 | 往左 |
| 3 | 4 | [2,4] | 无 | 往左 |
| 2 | 5 | [2,4,5] | 无 | 往左 |
| 1 | 3 | [2,4,5,3] | **[4,5]** | 停：换成 4，后面 sorted([2,5,3]) → `[1,4,2,3,5]` |

`x > nums[i]` 用严格大于，相等的不算右边的兄弟，所以输入有重复（`[1,5,1]`、`[1,1]`）也对。对拍过长度 1–5、含重复的全部排列。

#### 往上退的数值规律 → 智力版

退过的后缀一定**从左到右递减**：能继续退 = `nums[i]` 是 `nums[i:]` 里最大的，每层都这样，后缀就一个比一个小。

| 傻版 | 因为 pool 是降序，所以… | 智力版 |
|---|---|---|
| `bigger` 非空 | 只跟右边一个比 | `nums[i] < nums[i+1]` |
| `min(bigger)` | 从右往左第一个比它大的就是 | `while nums[j] <= nums[i]` |
| `sorted(pool)` | 降序反过来就是升序 | 反转后缀 |

三个版本是同一件事越做越省：全量 DFS 生成所有排列再找下一个 O(n!·n) → 傻版从当前叶子走一步 O(n²) → 智力版 O(n)、O(1) 空间。全量版只适合拿来对拍。
