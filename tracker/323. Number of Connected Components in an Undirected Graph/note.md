可以，而且这就是它的正式名字：disjoint-set forest（不相交集合森林）。

每棵树是一个连通块。
树根就是组长。
有几棵树，就有几个连通块。
这些树有三个特点：

指针只往上指。 每个点只记自己的父亲，不记孩子。所以只能从下往上走，没法从根往下遍历整棵树。不过求连通块用不着往下走，只需要 find 往上找根。
树的形状不是图的形状。 前面 1 — 0 — 2 那个例子里，树长成 0 → 1 → 2，1 和 2 在图上根本没有边。树只说明「这些点在一组」，不保留图的结构。
树会被压扁。 路径压缩每次都把走过的点往根那边挂，树越来越矮，最后差不多是所有点直接挂在根下面。
换个角度会更有意思。 树里的指针不是图的边，但「让 ra != rb 成立、真的合并了两组」的那些边，挑出来正好是原图的一棵生成森林：每个连通块一棵生成树，用到的边数是 n - 连通块数。

这就是 Kruskal 最小生成树：按边权从小到大读边，用并查集决定这条边要不要。
你做过的 261 Graph Valid Tree 也能从这个角度理解：所有边都让 ra != rb 成立（没有一条边形成环），并且最后只剩一棵树，图就是一棵树。
一句话： 你在建一片森林，每棵树代表一个连通块；树的形状是合并过程留下来的，不是图本身的形状。
