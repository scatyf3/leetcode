```python
class Solution:
    def countComponents(self, n: int, edges: list[list[int]]) -> int:
        parent = list(range(n))        # 每个点一开始自成一组, 组长是自己

        def find(x):                   # 找 x 所在组的组长
            while parent[x] != x:
                parent[x] = parent[parent[x]]   # 路径压缩: 顺手把 x 挂到爷爷上
                x = parent[x]
            return x

        count = n                      # 一开始 n 组
        for a, b in edges:
            ra, rb = find(a), find(b)
            if ra != rb:               # 两头在不同组 -> 合并, 少一组
                parent[ra] = rb
                count -= 1
        return count
```

**和你原来写法的对应关系：**

| 你的写法 | 并查集 |
|---|---|
| `res` 里一个 set 是一组 | 同一个组长下面的所有点是一组 |
| 遍历所有 group，看 `edge[0] in group` | `find(a)`，直接找到组长，不用逐组去查 |
| 两头都在组里时，各加一个点（bug 就在这） | `ra != rb` 时把一个组长挂到另一个下面，两组真的合成一组 |
| 最后补孤立点的那个循环 | 不需要了。`count` 从 `n` 开始，孤立点本来就各算一组 |
| `edges.sort()` | 不需要了。并查集跟边的顺序无关 |

**两个细节：**
- **路径压缩**就是那行 `parent[x] = parent[parent[x]]`。不写也能过，但树可能长成一条链，`find` 会退化成 O(n)。写上以后基本是常数时间。
- **`count -= 1` 只能放在 `ra != rb` 里面。** 两头已经在同一组时，这条边是一条环边，不会减少组数。261 Graph Valid Tree 判断环，用的就是这个分支。

**复杂度：** 时间约 O(E·α(n))，α 是一个增长极慢的函数，可以当成常数。空间 O(n)。你原来的写法每条边都要扫一遍所有 group，是 O(E·n)。

### 为什么不直接存 set

关键在合并。

- **用 set：** 两组合并时，要把一个 set 的元素全部拷进另一个，还要更新所有「这个点在哪个 set」的记录，代价是组的大小。
- **用指针：** 合并只改一个数。第 2 步里，`{0,1}` 和 `{2}` 合并，只执行了 `parent[1] = 2`。0 不用动，因为它往上走会经过 1，自然就走到 2 了。

**一句话：** 每个人只记自己的上级是谁，组长的上级是自己。要判断两个人是不是一组，就各自往上找到老大，看是不是同一个人。

**补充：** 如果点不是 `0..n-1` 的整数（比如字符串、坐标），把 list 换成 dict 就行：`parent = {}`，第一次见到某个点时设 `parent[x] = x`。

**set 的写法也能优化，优化到最后又走回了并查集：**
1. 查找慢，就加一个 `dict`：点 → 它所在的 set，查找变成 O(1)。
2. 合并时，要把被合并那组里每个点的 dict 记录都改掉。改动量等于组的大小，所以总是把小组并进大组，总代价降到 O(n log n)。

**什么时候 set 反而更方便：** 题目要你把每组的成员都列出来时，比如 721 Accounts Merge。不过并查集也能做到：最后对每个点算一次 `find(i)`，按组长分桶就行，所以平时仍然用 parent 指针。

**一句话：** set 显式存成员，查找和合并都要搬数据；parent 指针只存「上级是谁」，合并只改一个指针。

为啥这样是组长是valid的啊

#### 🤖 Claude

这里说的「valid」，是要证明一件事：

> **`find(a) == find(b)` 当且仅当 a 和 b 在已经读过的边里是连通的。**

靠的是一条不变式：每读完一条边，「同一个 root」和「图上连通」这两件事都完全对应。用归纳法分三步看。

### 1. 开始时成立

`parent = [0, 1, ..., n-1]`，每个点自己是 root。这时还没读任何边，每个点也确实是孤零零一个。两边对得上。

### 2. 读一条边 (a, b) 以后仍然成立

先求 `ra = find(a)`、`rb = find(b)`，分两种情况：

- **`ra == rb`：** a 和 b 本来就连通，这条边没有连起任何新的东西。我们什么都不改，对应关系不变。
- **`ra != rb`：** 执行 `parent[ra] = rb`。
  - **ra 那组的每个点**，原来往上走最终到 ra。现在 ra 多了一步指向 rb，所以它们都走到 rb。
  - **rb 那组的点**：路径没变，还是到 rb。
  - **其他组**：一个指针都没动。

  结果是两组合成一组，其他组不变。图上也正好是这样：a 所在的连通块和 b 所在的连通块被这条边连成一块，别的块不受影响。两边还是对得上。

### 3. find 一定能停下，而且只有一个答案

- **只有一个答案：** 每个点只有一个指针，往上走的路是唯一的，所以 root 唯一。
- **一定停得下：** 不会出现环。合并时，我们只把一个 root 挂到另一棵树的 root 下面，两棵树接成一棵，不会绕回来。路径压缩是把 x 改挂到爷爷上，爷爷还在同一条往上的路上，所以 root 不变，也不会产生环。

三步合起来，root 就是一个合格的组名：同组同 root，不同组不同 root。

### 反过来看：为什么必须挂 root，不能直接挂端点

第 2 步成立，关键在于改的是 `parent[ra]`，不是 `parent[a]`。如果直接写 `parent[a] = b`：

`n = 3`，已经读了边 (0,1)，`parent = [1, 1, 2]`，0 和 1 一组。再读边 (0,2)：

| 写法 | parent | 结果 |
|---|---|---|
| 错：`parent[0] = 2` | `[2, 1, 2]` | 0 的旧指针 0→1 被覆盖，1 被甩出去，自己成了一组。返回 2 组，答案是 1 |
| 对：`parent[find(0)] = find(2)`，即 `parent[1] = 2` | `[1, 2, 2]` | 0 → 1 → 2，三个点一组。返回 1 组 ✓ |

**原因：** 改一个非 root 点的指针，会把它和原来的上级断开，整组被劈成两半。改 root 的指针不会断开任何东西，因为 root 本来就没有上级。

**一句话：** 每次合并都是「root 挂到另一个 root 下」，只会把两棵树接成一棵，不会拆树，也不会成环。所以从头到尾，「同 root」和「连通」始终是一回事。

#### 🧑 我

这个能理解成build若干tree吗

#### 🤖 Claude

可以，而且这就是它的正式名字：disjoint-set forest（不相交集合森林）。

- 每棵树是一个连通块。
- 树根就是组长。
- 有几棵树，就有几个连通块。

**这些树有三个特点：**

1. **指针只往上指。** 每个点只记自己的父亲，不记孩子。所以只能从下往上走，没法从根往下遍历整棵树。不过求连通块用不着往下走，只需要 `find` 往上找根。
2. **树的形状不是图的形状。** 前面 `1 — 0 — 2` 那个例子里，树长成 `0 → 1 → 2`，1 和 2 在图上根本没有边。树只说明「这些点在一组」，不保留图的结构。
3. **树会被压扁。** 路径压缩每次都把走过的点往根那边挂，树越来越矮，最后差不多是所有点直接挂在根下面。

**换个角度会更有意思。** 树里的指针不是图的边，但「让 `ra != rb` 成立、真的合并了两组」的那些边，挑出来正好是原图的一棵生成森林：每个连通块一棵生成树，用到的边数是 `n - 连通块数`。
- 这就是 Kruskal 最小生成树：按边权从小到大读边，用并查集决定这条边要不要。
- 你做过的 261 Graph Valid Tree 也能从这个角度理解：所有边都让 `ra != rb` 成立（没有一条边形成环），并且最后只剩一棵树，图就是一棵树。

**一句话：** 你在建一片森林，每棵树代表一个连通块；树的形状是合并过程留下来的，不是图本身的形状。
