# 261. Graph Valid Tree

边数 == n − 1 且连通 → 是树。先判边数，再从 0 BFS 数能到几个点。

## 思路：树 = n − 1 条边 + 连通

n 个点的树正好 n − 1 条边。**边数 = n − 1 的前提下**，下面三个只要成立一个，另外两个自动成立：

- 无环
- 连通
- 是树

所以只要 `len(edges) != n - 1` 直接 False，剩下只查**连通**，环都不用判。

为什么够：

- 连通至少要 n − 1 条边。正好 n − 1 条 → 每条都是连通必需的，没有多余的边去成环
- 反过来：n − 1 条边又有环 → 去掉环上一条边仍然连通，只剩 n − 2 条，比连通的下限还少，矛盾

> 只判连通不够：三角形 `[[0,1],[1,2],[0,2]]`、n = 3 连通但不是树 —— 边数 3 ≠ 2，第一步就拦掉。

## 讨论：能不能定向成「小 → 大」再拓扑排序判环？

> 直接规定单向，从小往大，然后拓扑排序吗？还是非要严格按照题目的语义做单向排序

不行。**按编号从小指向大，得到的有向图一定无环** —— 沿边走编号只增不减，永远绕不回来。拓扑排序永远说「无环」。

Example 2 `[[0,1],[1,2],[2,3],[1,3],[1,4]]` 定向后 `0→1, 1→2, 2→3, 1→3, 1→4`，Kahn 能排出全部 5 个点，但 1-2-3 明明是环。

根本原因：**无向环定向后不一定是有向环**。三角形 1-2-3 变成 `1→2→3` + `1→3`，在有向图里只是两条路汇合到 3。有向环要求方向首尾相接，比无向环严格得多。

> 拓扑排序是**有向图**的工具，无向图判环要换方法。

## BFS 从哪开始

> 建了 graph 之后咋 bfs，start 是哪里

随便，用 0。查的是「所有点是不是连在一起」：连通的话从哪出发都能走到全部 n 个点，不连通的话从哪出发都走不全。题目保证 n ≥ 1，0 一定在。

两个坑：

- `g` 用 dict 建的话，没边的点不在里面。`n = 1, edges = []` 时 `g` 是空的，`g[0]` 会 KeyError → 用 `g.get(cur, [])`(或者直接 `g = [[] for _ in range(n)]`)
- `visited` **入队时**就加，不要出队才加，否则同一个点会被多个邻居重复入队

## visited：这里要，Kahn 不要

| | 261(无向图普通 BFS) | [210](../210.%20Course%20Schedule%20II/note.md)(Kahn) |
|---|---|---|
| 要不要 visited | **要** | **不要** |
| 为什么 | 无向边两头都能看到，同一个点会被多个邻居发现 | 入队条件是入度从 1 减到 0，只会发生一次 → 每个点天然只入队一次 |
| 判环 / 判树 | 边数 n − 1 + `len(visited) == n` | `len(path) == n` |

## 其它写法(不先判边数，直接判环)

- **BFS/DFS 带 parent**：走到邻居 v，v 是父节点就跳过(同一条边反着看到)；不是父节点却已访问过 → 有环。最后还要查连通
- **并查集**：逐条加边，加之前 a、b 已在同一集合 → 成环。最后集合数应为 1
- **剥叶子**(无向版 Kahn)：反复删度数为 1 的点，树能剥光，有环的话环上的点剩下来

最省事的还是「判边数 + 一次 BFS」。
