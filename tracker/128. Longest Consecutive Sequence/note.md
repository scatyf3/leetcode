**仓库里的同门：347 Top K Frequent Elements**（`347. Top K Frequent Elements/sol3.py`）。你在那边已经写过一模一样的推导："堆和排序都是比较出来的，比较排序下界就是 O(m log m)，想突破必须找不靠比较的性质 —— 频次一定落在 [1, n] 这个有界小整数区间里，于是拿 key 当数组下标。"

两题的对应关系：

| | 128 | 347 |
|---|---|---|
| 要排的 key | 元素值本身 | 频次 |
| key 的值域 | 无界（int 全域） | 有界 `[1, n]` |
| 用的结构 | hash set（散列寻址） | bucket 数组（直接寻址） |
| 拿到的是 | 只要**相邻关系** `x+1 in s` | 要**全序**，所以必须是数组下标 |

区别就在最后一行，也是我上面说"set 不能替代桶"的原因：128 的值域无界，开不出数组，只能散列——但它也只需要问"x+1 在不在"，散列够用；347 的 key 有界所以能开数组，而它需要"从高到低扫一遍"的全序，dict 给不了，必须靠下标白送的顺序。

一句话概括这个 pattern：**当排序的 key 是有界整数时，用寻址代替比较**（桶排序/计数排序/基数排序）；**当只需要邻接而非全序时，用散列代替排序**（128）。两者都是拿 O(n) 空间换掉 log n。

同族但仓库里还没做的：41 First Missing Positive（值域 `[1, n+1]`，原地哈希，把 `x` 换到下标 `x-1`）、268 Missing Number、448 Find All Numbers Disappeared、164 Maximum Gap（桶 + 抽屉原理，真正意义上打破 n log n 的排序题）。

### 你需要多少"有序"？

上面那句"只 care 链内有序、不 care 链之间有序"是这三题真正的共同点，比"打破 n log n"更本质。**排序是一个过度满足的操作**：它交付全序，而全序在复杂度上是要付钱的（比较排序 Ω(n log n)）。绝大多数题需要的有序度都严格小于全序，少要一点就能换一个更便宜的结构。

按"要求的有序度"从强到弱排：

| 需要的有序度 | 结构 | 代价 | 仓库里的题 |
|---|---|---|---|
| 全序 + 按 rank 随机访问 | 有序数组 | build O(n log n)，**insert O(n)** | 295 的 naive 解 |
| 只要一个极值 | 堆（堆序：只保证父 < 子，兄弟之间不管） | build O(n)，op O(log n) | 347 heap 版 |
| 只要前 k，k 名之后不管 | 大小 k 的堆 | O(m log k) | 347 sol2 |
| 只要**一个分割点**两侧的极值 | 双堆 | op O(log n) | **295** |
| key 有界，要全序但不想比较 | 桶数组（顺序由下标白送） | O(n) | **347 sol3** |
| 只要**邻接关系**，不要全局位置 | hash set | O(n) | **128** |
| 只要存在性 | set | O(n) | 217 |

**串起来的那条线：维护不变式的代价 ∝ 不变式的强度。**

这正好回答了你在 295 note 末尾的疑问"insert 的复杂度差在哪"：有序数组的不变式是"n 个元素两两有序"，太强了，插一个元素要花 O(n) 去修复（二分找位置只要 O(log n)，但**挪元素**是 O(n)，瓶颈在修复不在查找）。堆的不变式只是"每条根到叶的路径有序"，弱得多，修复只要 O(log n)。295 的双堆更进一步：它连"哪个数排第 3"都不知道，全局只有**中位那一刀**是精确的——而题目要的恰好只有这一刀。

128 是这条线的极端：它连链内有序都不需要维护。因为**元素值自带 successor 函数**——`x` 的下一个一定是 `x+1`，不用比较就知道是谁。排序交付的是"比较得来的顺序"，而 128 的顺序是值本身白送的，set 只负责回答"这个 successor 在不在"。所以它需要的不是排序，是**成员资格查询**。

面对新题时可以先问一句：**我到底需要多少有序？** 默认伸手去 sort 往往是 over-delivery，而 over-delivery 是要付钱的。
