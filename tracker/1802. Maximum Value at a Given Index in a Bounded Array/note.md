### 结构：外层二分峰值，内层 O(1) 算最小和

峰值定为 `v` 时，最省的数组是「往两边每格减 1，减到 1 就一直是 1」：

```
总和 = v + side(v, 左边格数) + side(v, 右边格数)
```

`total(v)` 随 `v` 单调递增 → 闭区间二分找**最后一个** `total(v) <= maxSum` 的 `v`，`l` 从 **1** 开始（元素都是正整数），返回 `r`。

sim 版本（逐格累加）每次 O(n)，n 到 1e9 会 TLE，所以 `side` 必须是公式。

### 公式速查卡

**数格子（0-indexed）**

| 要数的 | 个数 |
|---|---|
| 闭区间 `[a, b]` | `b - a + 1` |
| 半开 `[a, b)` | `b - a` |
| 位置 `i` 左边 | `i` |
| 位置 `i` 右边（长 n） | `n - 1 - i` |
| 校验 | 左 + 右 + 1 = n |

只记闭区间那一行，其余都能推：右边 = `[i+1, n-1]` → `(n-1)-(i+1)+1`。更多见 [off-by-one 清单](../notes/off-by-one-checklist.md)。

**等差数列**

| 要算的 | 公式 |
|---|---|
| 求和 | `(first + last) * count // 2` |
| 1 + … + m | `m * (m + 1) // 2` |
| 第 count 项（公差 d） | `last = first + (count - 1) * d` |
| 项数 | `count = (last - first) // d + 1` |

**先乘再 `// 2`**：`(first + last) * count` 一定是偶数，先除会丢 0.5。

### side(v, k)：从 v-1 往下减、最小为 1、共 k 格

两种情况：

| 情况 | 样子 | 和 |
|---|---|---|
| `k <= v-1` 减不到 1 就到边界 | `v=5,k=3 → [4,3,2]` | `(v-1 + v-k) * k // 2` |
| `k > v-1` 减到 1 后补 1 | `v=4,k=6 → [3,2,1,1,1,1]` | `(v-1)*v//2 + (k-(v-1))` |

不分情况的写法（等差部分的项数被 `k` 和 `v-1` 中较小的那个卡住）：

```python
def side(v, k):
    cnt = min(k, v - 1)                              # 等差部分几项
    return (v - 1 + v - cnt) * cnt // 2 + (k - cnt)  # 等差 + 剩下的 1
```

> 求和别背公式：写出 `first / last / count` 三个变量 → 套 `(first+last)*count//2` → 用 3~4 个元素的小例子手算核对。

### 这次踩的坑

| 写错的 | 应该是 | 根因 |
|---|---|---|
| 多了一行 `max(index-dist_bound,0) * value//2` | 删掉 | 那些 1 后面的循环已经加过了 |
| 右边界 `min(index+dist_bound, n)` | `n-1` | 最后一个下标是 `n-1` |
| `l = 0` | `l = 1` | 元素是正整数 |
| 首项写成 `v` | `v-1` | **峰值不属于两侧**，侧边从 `v-1` 开始 |
| `k*((2v-k)//2)` | `(...) * k // 2` | 先除丢精度 |
| `v*v`、`v//2` 当 1..v-1 的和 | `(v-1)*v//2` | 同上，项数是 `v-1` 不是 `v` |
| 剩余 1 的个数 `k-v` | `k-(v-1)` | 同上 |
| 格子数写成 `index±v` | `index`、`n-1-index` | 格子数只看位置，和峰值无关 |

一半的错都是同一个原因：**侧边从 `v-1` 数起，不是 `v`**。
