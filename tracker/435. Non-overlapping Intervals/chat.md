#### 🤖 Claude

先换个角度：**删掉最少的区间，就等于保留最多的互不重叠区间。** 这是经典的「活动安排」问题：一个会议室，排尽量多的会。

## 为什么按 end 排序

只用问一个问题：**第一个保留哪个区间？**

答案是**结束最早的那个**。它最早把时间让出来，给后面留的空间最大。

这句话可以证明，用的是交换论证：

- 随便拿一个最优解，看它里面第一个区间 X。
- 把 X 换成全局结束最早的区间 E。因为 E 的结束不晚于 X，X 后面那些区间原本和 X 不冲突，和 E 也一定不冲突。
- 换完以后，区间个数不变，结果仍然合法。所以「先选结束最早的」不会让答案变差。

选定 E 之后，把和它重叠的区间都扔掉，剩下的就是同一个问题，规模更小。照这个规则一直选下去就行。按 end 排序，只是为了让「每次挑结束最早的」变成从左往右扫一遍。

## 另外两种排法为什么不行

- **按 start 排**：`[1,100], [2,3], [4,5]`。开始最早的是 `[1,100]`，选了它，后面两个都被挡住。开始早不代表结束早。
- **按长度排**：`[1,5], [4,7], [6,10]`。最短的是 `[4,7]`，可它和另外两个都重叠，只能保留 1 个；最优是保留 `[1,5]` 和 `[6,10]`，共 2 个。区间短也可能正好卡在中间。

关键是：后面还能放什么，**只取决于你在哪里结束**，跟从哪里开始、有多长都没关系。

> 补充一点：按 start 排其实也能做对，只要遇到重叠时**留下 end 小的那个**。本质还是同一个原则：end 越小越好。

## 一句话原则

文档里的说法是：每处理一个区间，都要做两件事。

- **触发**：现在轮到它了吗？它和已有的部分接得上吗？这个判断看 `start`。
- **后果**：收下它以后，资源被占到什么时候？这个后果由 `end` 决定。

所以：

- **合并（56/57）**：没有选或不选，来一个就吸收一个，只关心接不接得上，所以按 start 排。排好以后 start 只增不减，一旦开了一个新区间，前面的就再也不用回头看。
- **删区间（435/452）**：每一步都要决定留不留，代价是这个区间占到什么时候，所以按 end 排。上一条回答里的交换论证，就是在证明「先留结束最早的」不会错。

文档的原话：**合并关心「在哪里」，调度关心「到什么时候」**。

## 两个容易踩的坑，文档里都有

1. **光背「调度按 end」会出错（§2.5）。** 「用最少的区间盖满 [0,T]」（1024、45）也是贪心，但要**按 start 排**，然后在接得上的区间里挑 **end 最大**的。两个端点各管一件事，正好验证了上面的原则。文档里有反例：直接套 435 的模板会输出 5，正确答案是 3。
2. **端点相碰算不算重叠，每题不一样（§4）。** 56 算，435 不算，452 又算。

## 有一处说得稍微绝对了

文档开头说「调度类用错键是**直接算错**」。如果是**照搬那个模板**（遇到不冲突就收下），按 start 排确实会错，`[1,100] [2,3] [4,5]` 就是反例。但 435 按 start 排**也能做对**，只要遇到冲突时**留下 end 小的那个**：

```python
intervals.sort()
end, removed = float('-inf'), 0
for s, e in intervals:
    if s >= end:
        end = e
    else:
        removed += 1
        end = min(end, e)   # 冲突时留 end 小的
```

所以更准确的说法是：**调度题每一次取舍都选 end 更小的**。按 end 排序只是把这个规则变成从左往右扫一遍；按 start 排就得在冲突时手动选一次。两种写法背后是同一个原则。
