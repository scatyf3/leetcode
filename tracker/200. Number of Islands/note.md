# 200. Number of Islands

## Q：DFS 为什么不用像 BFS 那样“入队前就置 0”？

关键是“决定访问”和“标记已访问”之间有没有空隙。

**DFS**：检查到 `== "1"` 后马上调用 `dfs(new_x, new_y)`，函数一进去第一件事就是 `grid[x][y] = "0"`。中间没有任何代码会去读这个格子，之后从哪条路绕回来看到的都是 `"0"`。所以“进入即标记”本身就是入队即标记。

```python
if 0<=new_x<m and 0<=new_y<n and grid[new_x][new_y]=="1":
    dfs(new_x, new_y)        # 立刻进入
        grid[x][y] = "0"     # 第一件事就是标记
```

例子：A、B 相邻。`dfs(A)` 先把 A 置 0，再去 `dfs(B)`；B 置 0 后回头看 A，A 已经是 `"0"`，不会再进去。

**BFS**（sol2.py）：从入队到出队要排很久。如果等出队时才置 0，它在队列里的这段时间仍然是 `"1"`，别的邻居会把它再入队一次，同一个格子会被重复入队很多次。所以 BFS 必须在入队时就置 0（`grid[nr][nc] = "0"` 写在 `q.append` 前面）。

**一句话**：标记必须发生在“别人可能再看到它”之前。DFS 的递归是同步的，进入就等于立刻标记；BFS 的队列有延迟，所以要提前到入队时标记。

**DFS 的反例**：如果把 `grid[x][y] = "0"` 挪到 for 循环之后（后序标记），就会无限递归：A 进入 B，B 回头看 A 时 A 还是 `"1"`，又进入 A……所以 DFS 也必须在展开邻居之前标记。

> 小点：调用前已经检查过 `== "1"`，所以 `dfs` 开头的 `if grid[x][y]=="0": return` 是多余的，留着当保险也行。
