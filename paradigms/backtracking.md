# 回溯 通用 trick

**信号**：题目要「**所有**方案」（全部子集 / 组合 / 切法 / 摆法），或者问「**能不能**凑出一个合法方案」。
答案个数本身就是指数级的，没有比"一个个试"更快的办法 —— 只能**有序地**枚举，再尽量剪枝。

> 回溯 = 在一棵**决策树**上做 DFS。每层做一个决定，往下走，回来时把这个决定撤销。
> 「回溯」这个名字指的就是撤销那一行 `pop()`。

和 [网格 DFS](../structures/grid.md) 是同一个东西：网格 DFS 的"树"是格子之间的邻接，
回溯的"树"是你自己定义出来的决策顺序。79 Word Search 正好是两者的桥。

---

### 一、怎么 formulate：先画树，再回答三个问题

拿到题先别写代码，按顺序回答：

**0. 一层 = 一个什么决定？**（最关键的一步，定错了后面全白干）

决定必须**从左往右、做完不回头改**。顺序一固定，同一个结果就只有一条路径能走到，
重复从根上就没了。

> 踩过：131 第一版从下往上想 —— 先全切成单字符，再找能 merge 的合并。
> 不同的 merge 顺序会走到同一个切分（`aabb` 先并 `aa` 还是先并 `bb`），重复指数级涨，
> 而且「奇 merge / 偶 merge」的规则越补越复杂（`a,bb,a` 两种都不是）。
> 换成「每层决定**下一刀切在哪**」，两个问题一起消失。

**然后三问**（骨架都一样，每题真正要想的只有这三件事）：

| | 问自己 | 对应代码 |
|---|---|---|
| ① | 每层**枚举什么**？ | `for` 循环的范围 |
| ② | 什么时候**结算**？ | 函数开头的 `if` |
| ③ | 什么时候**不用往下走**？ | 循环里的剪枝 / `continue` |

再加两个只有部分题才有的问题：

| | 问自己 | 对应代码 |
|---|---|---|
| ④ | 同一个元素能不能**重复用**？ | 递归传 `i` 还是 `i + 1` |
| ⑤ | 输入里有没有**重复值**？ | 要不要 sort + 同层去重 |

### 二、唯一的骨架

只认这一种写法：**for 循环 + `start`**。不用「选或不选」那种每层两个分支的写法 ——
两套混着用，就会写出 78 第一版那种半边一套的东西（见第六节）。

```python
res, path = [], []

def dfs(start, ...):
    if 结算条件:                     # ② 
        res.append(path[:])          #    拷贝！path 是同一个 list 被反复改
        return
    for i in range(start, n):        # ① 本层的选项
        if 剪枝 / 去重:               # ③ ⑤
            continue                 #    (排过序时可以 break)
        path.append(nums[i])         # 做选择
        dfs(i + 1, ...)              # ④ i+1 不复用 / i 可复用
        path.pop()                   # 撤销

dfs(0, ...)
```

`start` 的含义：**本层只能从 `start` 往后挑**。它保证组合里的下标单调递增，
`[1,2]` / `[2,1]` 这种"顺序不同的同一个组合"根本不会生成。

### 三、分类：按「每层枚举什么」分

| 类型 | 每层枚举 | 题 | 结算时机 |
|---|---|---|---|
| **选元素（组合型）** | 从 `start` 往后挑下一个元素 | 78 · 90 · 39 · 40 | 78/90 每个节点；39/40 `remain == 0` |
| **排列型** | 还没用过的元素里挑一个放这一位 | 46 | 候选用完 |
| **按位填（笛卡尔积）** | 当前这一位的所有选项 | 17 · 22 | 填满 `len(digits)` / 左右括号都用完 |
| **切分型** | 下一刀切在哪（这一块到哪结束） | 131 | `start == len(s)` |
| **路径搜索** | 往哪个方向走 | 79 | `k == len(word)` → 返回 True |
| **约束放置** | 这一行的皇后放哪一列 | 51（还没做） | 放满 n 行 |

前四类本质一样：都是 for 循环挑一个，区别只在**挑的范围**。
排列型没有 `start`（顺序本身就是答案的一部分），靠"已用集合"防止同一个元素用两次。

#### 组合型的四道题，只差两个开关

| 题 | 输入有重复值？ | 每个数用几次 | 递归传 | 同层去重 | 结算 |
|---|---|---|---|---|---|
| 78 Subsets | 没有 | 1 次 | `i + 1` | 不用 | 每个节点 |
| 90 Subsets II | **有** | 1 次 | `i + 1` | **要** | 每个节点 |
| 39 Combination Sum | 没有 | 无限次 | **`i`** | 不用 | `remain == 0` |
| 40 Combination Sum II | **有** | 1 次 | `i + 1` | **要** | `remain == 0` |

### 四、结算：什么时候往 res 里放

> **结算条件 = 「这条路径已经是一个完整答案」的那一刻。**

| 题 | 结算条件 | 为什么 |
|---|---|---|
| 78 / 90 | 每个节点都收（一进函数就 append） | 每个前缀选择本身就是一个合法子集，空集就是根 |
| 39 / 40 | `remain == 0` | 凑够目标和了 |
| 17 | `pos == len(digits)` | 每个数字都选了字母 |
| 22 | 左右括号都用完 | 括号串放满了 |
| 46 | 候选集合空了 | 每个元素都放进去了 |
| 131 | `start == len(s)` | 整个串切完了，没有剩余部分 |
| 79 | `k == len(word)` | 单词全匹配上了 —— 这题要的是 bool，不是收集 |

注意两件事：

- **只在叶子结算的题，结算完要 `return`**。79 漏了 `return`，接着往下读 `word[len(word)]` 越界。
- **结算时机决定了"剩余部分"要不要管**。131 用 `start == len(s)` 结算，那一刻剩余部分是空的，
  所以根本不需要检查剩余部分（见第六节）。

### 五、去重：两种重复，两个手段

重复有两个**来源**，所以要两个手段，缺一个都不行：

| 重复的来源 | 例子 | 手段 |
|---|---|---|
| **顺序**不同 | `[1,2]` 和 `[2,1]` | `start`：只往后挑 |
| 输入里**值本身重复** | `[1,1,2]` 里两个 1 各挑一次，都得到 `[1,2]` | 先 sort，再**同层去重** |

同层去重只有这一行：

```python
nums.sort()
...
for i in range(start, n):
    if i > start and nums[i] == nums[i - 1]:
        continue
```

**`i > start` 说明什么**：本层的 for 循环已经试过至少一个兄弟分支了，当前这个不是本层第一个选择。
这时 `nums[i-1]` 是**本层**刚试过的值，相同就说明再开一棵子树会和前面那棵一模一样。

三种错写，都是真的错（40 题 `[10,1,2,7,6,1,5], 8` 实测）：

| 写成 | 后果 | 原因 |
|---|---|---|
| 整行不加 | **少去重**：`[1,2,5]`、`[1,7]` 各出现两次 | 值重复的那份没人管 |
| 去掉 `i > start` | **多去重**：`[1,1,6]` 丢了；`[1,1,1,1], 2` 输出 `[]` | 把"往下一层再选一个 1"也跳了；`i = 0` 时 `nums[-1]` 还会比到末尾 |
| `i > 0` | **多去重**：同上丢 `[1,1,...]` | `i > 0` 只说明不是整个数组的第一个，不说明不是**本层**第一个 |
| 和 `cur[-1]` 相同就跳 | **两头错**：丢了 `[1,1,6]`，`[1,2,5]`、`[1,7]` 却还是各两次 | `cur[-1]` 是**上一层**选的：禁掉的是合法的"下一层再选一个"，真正该禁的同层重复反而没管 |

> 判断"同层"只能看循环自己（`i` 和 `start`），跟 `path` 无关。

**用 set 去重能 AC 吗？** 能（90 第一版），但必须先 sort，否则 `str([1,2]) != str([2,1])`，
`[4,4,4,1,4]` 这种用例照样出重复。而且重复的分支照样整棵跑完，只是在收集时扔掉，
每次还要 `str(cur)` 花 O(n)。同层去重是在**入口**就把整棵子树剪掉。

### 六、踩过的坑（今天一天全踩了一遍）

| 题 | 写成了 | 症状 | 根因 |
|---|---|---|---|
| 78 | `dfs(cur, idx)` | 死循环 → RecursionError | 选了 `nums[idx]` 之后下一层还从 `idx` 开始，`cur` 一直 append 同一个数，depth 永远不涨 |
| 78 | for+start 的循环 + `depth == len(nums)` 才收 | 只收到含最后一个元素的子集，`[]` 都没有 | 两种写法混了：循环是写法 B，结算条件是写法 A |
| 90 | `str(cur)` 进 set 去重，没 sort | `[1,2,1]` 出现 `[1,2]` 和 `[2,1]` | `str` 比的是顺序，题目要的是多重集合 |
| 131 | 从单字符往上 merge | 重复 + 规则写不全 | 决策顺序没固定（第一节） |
| 131 | path 里同时 push「切下来的块」和「剩余部分」 | 输出 `['aa','b','b','']` | 剩余部分是**下一层的事**，靠参数 `start` 传下去，不该进 path |
| 131 | 要求剩余部分也是回文 | `"aab"` 丢了 `['a','a','b']` | 剪枝只该检查**这一刀**切出来的块。单字符一定是回文，剩下的总能切完 |
| 79 | `else: return False` 写在 for 里 | 全部返回 False | 一个方向不通就放弃了整个节点，剩下三个方向没试 |
| 79 | `dfs(...)` 不接返回值 | True 传不上来 | 找到了也没人往上交 |
| 79 | `visited = set(pair)` | 起点没被标记 | `set((0, 2))` 会把元组拆开，得到 `{0, 2}`；要 `{pair}` |
| 79 | 嵌套函数里 `find = True` | 外层 `find` 一直是 False | 赋值会新建局部变量，要 `nonlocal find`。（`visited.add` / `res.append` 是改对象，不用声明） |
| 79 | `find = True` 后不 return | IndexError | 匹配完了还继续读 `word[len(word)]` |
| 17 | `str(cur)` 想把字符列表变字符串 | 得到 `"['a', 'd']"` | 要 `"".join(cur)` —— 见语法卡 [str.md](../syntax/str.md) |

两个出现在**每一道**题里、今天没踩但必须一直盯着的：

- `res.append(path)` ✗ → `res.append(path[:])` ✓。存引用的话，回溯结束后 res 里全是同一个空列表。
- `append` 和 `pop` 必须成对。46 有两份状态（`cur` 和 `cand`），**选的时候两份一起改，撤的时候两份一起还原**。
  还有：别一边迭代 `cand` 一边改它 —— `for num in list(cand)` 先拷一份快照。

### 七、结果怎么交上去：res / 返回值 / nonlocal

递归深处得到的东西，怎么交给最外层？**看父节点需要子树告诉它的，是不是就是最终答案**：

| 情况 | 例子 | 用什么 |
|---|---|---|
| 要**所有**解 | 78 / 90 / 39 / 40 / 17 / 22 / 46 / 131 | 外部的 `res` 列表，dfs 不返回值 |
| 要判断**有没有**解，子树的结论就是答案 | 79 | dfs **返回 bool**，`if dfs(...): return True` 一层层往上传，找到就停 |
| 父节点要的东西 ≠ 最终答案 | 124 二叉树最大路径和：父要"单边最大和"，答案是"穿过当前节点的双边和" | 返回值传前者，外部变量记后者 |

79 现在的 [sol.py](../79.%20Word%20Search/sol.py) 用的是 `nonlocal find`，能 AC，但比返回 bool 多两件要记的事：
① 必须声明 `nonlocal`；② 找到后不会自动停，得自己加 `if find: return` 剪枝，否则所有起点、所有方向全搜一遍。
返回 bool 的写法这两件都自带。

> 惯性陷阱：连做三道"收集所有解"（78 / 39 / 40）之后，到 79 会顺手把 `res` 换成 `find`。
> 答案的**形状**变了（所有解 → 是否存在），交答案的**渠道**也该跟着换。

路径本身怎么传（共享 `path` + 撤销 / 传不可变值 `path + [x]` / 每层返回结果集），
三种的对比表在 [22 的 note](../22.%20Generate%20Parentheses/note.md#细节)。本文统一用第一种。

### 八、复杂度

| 类型 | 叶子数 | 每个叶子的代价 | 总时间 |
|---|---|---|---|
| 子集 78 | 2ⁿ | 拷贝 O(n) | O(n · 2ⁿ) |
| 排列 46 | n! | O(n) | O(n · n!) |
| 按位填 17 | 最多 4ⁿ | O(n) | O(n · 4ⁿ) |
| 切分 131 | 最多 2ⁿ⁻¹（每条缝切不切） | 判回文 O(n) | O(n · 2ⁿ) |
| 网格 79 | m·n 个起点，每步最多 3 个方向（不回头） | | O(m·n · 3ᴸ) |

空间：递归深度 + path，都是 O(答案长度)，不算输出。

组合和、去重题没法给出紧的界，剪枝和去重都是**常数级别看不出、实际差很多**的优化。
