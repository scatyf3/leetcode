# sliding-window

我感觉可以分两类
1. 自己用 sliding window 解问题
2. sliding window 就是题目语意本身（定长窗口：567 / 239）

骨架 A（最长）/ 骨架 B（最短）的填空位、起始状态怎么想，见
[notes/sliding-window-template.md](../notes/sliding-window-template.md)。这篇只记 protocol：
**区间怎么写、枚举谁、为什么。**

## 三层「两个写法」，三层答案不同

| 层 | 两个选项 | 结论 | 理由 |
|---|---|---|---|
| 区间记法 | 闭 `[l,r]` / 半开 `[l,r)` | **滑窗一律闭区间** | 由形状决定，不是自由选择（见文末） |
| 骨架 | A（最长）/ B（最短） | **两个都要**，肌肉记忆 | 解的是不同的问题 |
| 形状 | 枚举 r / 枚举 l | **主记枚举 r，枚举 l 要能现推** | 同一个算法，证明负担不同 |

二分那句「记一套就好」对应的是第一层（同一算法的两种坐标系），不是第三层。
但第三层的混淆风险也低：两个形状长得完全不一样（`for` vs `while`，收缩 vs 扩张，`+1` vs `-1`），
不像二分两套模板只差边界规则。

## 两个骨架

```python
# 形状 2:枚举 r,收缩 l  —— 默认
state = init(); l = best = 0
for r, x in enumerate(arr):          # r 无条件推进
    add(state, x)                    #   state 覆盖 [l, r]
    while not valid(state):          #   非法才缩
        remove(state, arr[l]); l += 1
    best = max(best, r - l + 1)      #   此刻必合法

# 形状 1:枚举 l,扩张 r  —— 对照用,见 424/sol3.py
state = init(); l = r = 0; best = 0
while r <= n and l < n:
    while r <= n and valid(state):   # state 覆盖 [l, r),合法就继续扩
        if r < n: add(state, arr[r])
        r += 1
    best = max(best, r - l - 1)      #   停在第一个非法,退一格
    remove(state, arr[l]); l += 1    # l 无条件推进
```

两个形状把「无条件」和「有条件」分给了不同的指针，外层那个是主角：

```
形状 2: r 无条件推进(for)   + l 有条件修复(while)   → 停在最后一个 valid
形状 1: l 无条件推进(while) + r 有条件扩张(while)   → 停在第一个 invalid
```

> **加入是探索性的，移除是确定性的。探索必须多走一步才知道停，所以谁负责探索，谁就带一格误差。**

形状 2 让 l（确定性的移除）当配角，误差没了：while 退出 ⟺ 窗口合法，单一命题，结算 `r-l+1` 不加不减。
形状 1 让 r（探索）当配角，退出条件是「非法 **或** 撞边界」，一个 `r-l-1` 要为两种退出原因负责，
于是需要三个补丁：`max(..., default=0)`、撞边界时空推 `r`（`if r < n`）、`l < n` 守卫。
424 第一版就死在这些补丁上（`A`/k=2 → 0，`ABBB`/k=0 → 2）。

## 复杂度一样，信息量也一样

| | 形状 2 | 形状 1 |
|---|---|---|
| 指针总移动 | ≤ 2n | ≤ 2n+1 |
| 实测（35735 字符）`max()` 调用 | 64647 | 65247 |

一样不是巧合。两个形状算的是**同一条单调阶梯**：

```
f(l) = 使 [l,r] 合法的最大 r        g(r) = 使 [l,r] 合法的最小 l
```

`f`、`g` 都单调不减、互为逆函数，知道一个等于知道另一个。O(n) 是走完这条阶梯的代价，
两个形状都走完了整条，所以**能回答的问题也相同**：

| | 全局最优 | 按 r 索引（以 r 结尾） | 按 l 索引（以 l 开头） |
|---|---|---|---|
| 形状 2 | ✓ | **免费**，结算那行就是 | 收缩处挂一行 `ans[l] = r - l` + 循环后补尾巴 |
| 形状 1 | ✓ | 多两笔 | **免费**，结算那行就是 |

（两个方向都对拍过，5000 组零错。）

**「枚举 l 才能给每个 i 开头的最优」是错的** —— 曾经这么写过，作废。差别只在哪个方向顺手，
是人体工学差异，不是能力差异。

形状 1 唯一的真陷阱是 **r 不回退**这条不变式要自己守：`for` 物理上保证 r 单调，`while` 不保证。
守不住就是朴素的 `for l: for r in range(l, n)`：

```
输入全 'A', k=0     形状 1(r 不回退)        朴素(每换 l 就把 r 重置回 l)
n=1600              1602 步 ≈ 1.0n          1280800 步 ≈ 0.50n²
```

O(n²) 来自「r 回退」，不来自「枚举 l」。

## 什么时候枚举 l

1. state 可删时，枚举 r：内层是 remove（修复），修复只会让窗口变好，
   所以停在「最后一个 valid」，后置条件单一，零特判，O(n)。
2. state 不可删时，**两个形状都写不出来**（形状 1 换左端点也要 `remove(arr[l])`）。
   出路按优先级：
   ① 换数据结构把它变成可删 → 回到形状 2，O(n)
        max/min → 单调队列（239）；任意结合律聚合（OR/AND/gcd）→ 双栈队列
        （OR ≤ limit 最长子数组，双栈队列 vs 暴力 3000 组零错；n=4000 时 4000 步 vs 朴素 800 万步）
   ② 合法性对长度单调 + 有可查询的区间结构 → 枚举 l + 二分，O(n log n)  ⚠️ 未验证
   ③ 朴素重建（r 回退）→ O(n²)，是兜底不是选择

判定顺序：

```
0. 窗口是定长吗?      是 → 问题不存在, l = r-k+1, 连 l 都不用存(567/239)
1. 同向还是相向?      相向 → 另一族, 见 two-pointer.md
2. state 删得掉吗?    删不掉 → 先换数据结构回到枚举 r; 换不动才 ② ③
   以上都不是        → 枚举 r
```

到目前为止，**没有任何一条已验证的理由需要枚举 l**。仓库里 8/8 都是枚举 r。

## 为什么滑窗写闭区间

先缩小问题：**闭/半开之争只关于右端点。** 第 `i` 个元素和它前面那条缝编号都是 `i`，
所以 `l` 指元素还是指缝，数值一样。分叉只在右端：元素 `r` 后面的缝是 `r+1`。

右端点的记法由**它是怎么来的**决定，不按算法家族分配：

| 右端点 | 怎么来的 | 记法 |
|---|---|---|
| 滑窗 `r`、121/53/239 的 `i` | `for` 给的，刚吃进去的元素 | 闭 |
| 二分闭区间 `r` | 候选集合的最大下标，还可能是答案 | 闭 |
| 切片 `a[l:r]`、前缀和 `P[r]`、读写指针 `w`、二分半开 `r=n` | 你放的边界，不在集合里 | 半开 |

**被循环消费的元素 → 闭；你放的边界 → 半开。** 形状 2 的 `r` 必然是 `for` 变量
（「无条件纳入每个元素恰好一次」就是 `for` 的语义），所以滑窗闭。形状 1 的 `r` 是 `while` 手动推的，
推完指向「下一个要吃的」= 缝，所以 sol3 半开。同一道题两种形状记法相反，规律照样成立。

不硬统一成半开，是因为 ±1 守恒，只能选它落在哪：

```
闭  :  cnt[x] += 1          best = r - l + 1    ← ±1 在长度公式, 一题 1 次
半开:  cnt[s[r-1]] += 1     best = r - l        ← ±1 在元素访问, 一题 2 次, 且 enumerate 用不了
```

滑窗每轮访问元素两次、算长度一次，±1 关在出现少的那一侧。切片/前缀和相反 —— 那里元素访问是主体，
长度几乎不算，所以关在另一侧。同一条原则，两种结论。全项目的记法约定见
[structures/array.md](../structures/array.md) §约定、
[notes/off-by-one-checklist.md](../notes/off-by-one-checklist.md) 第 0 步。
