# Hash Table 通用 trick

哈希表在这批题里只做一件事：**把一次 O(n) 的查找压成 O(1)，代价是丢掉顺序**。
所以拿到一道题只要回答两个问题：

1. **我要查的到底是什么** → 决定表里存什么（§1）
2. **键的值域长什么样** → 决定这张表是 `dict` 还是一个数组（§2）

剩下的都是这两条的推论。数组当哈希用的那一面见
[array.md](array.md) §和其他结构的联系 1，那边是「array 能替代 hash」，
这边是「hash 什么时候必须是 hash」。

## 0. 哈希表是怎么实现的

### 骨架：一个数组 + 一个哈希函数

数组按下标取是 O(1)，但 key 不是下标。哈希函数做的就是**把任意 key 翻译成一个下标**：

```
桶号 = hash(key) % m          m 是底层数组（「桶」）的长度
```

拿 m = 8 依次放入 3、11、6（Python 里小整数的 `hash(x)` 就是 `x` 本身，可以自己验证）：

```
hash:  3 % 8 = 3      11 % 8 = 3      6 % 8 = 6

桶号    0    1    2    3    4    5    6    7
       [ ]  [ ]  [ ]  [3]  [ ]  [ ]  [6]  [ ]
                       ↑
                       11 也想进 3 号桶 —— 碰撞
```

### 碰撞躲不掉，只能处理

key 的可能取值无穷多，桶只有 m 个，鸽巢原理保证一定有两个 key 落进同一个桶。两种处理办法：

```
拉链法（chaining）：每个桶挂一条链，碰撞了就往链上追加
桶号    0    1    2    3          4 ...
       [ ]  [ ]  [ ]  [3 → 11]   [ ]

开放寻址（open addressing）：桶里只放一个，被占了就按固定规则去找下一个空桶
桶号    0    1    2    3    4    5    6    7
       [ ]  [ ]  [ ]  [3]  [11] [ ]  [6]  [ ]        3 号被占 → 试 4 号（线性探测）
```

- 拉链法好写好懂，Java 的 `HashMap` 用它。
- 开放寻址省掉链表指针、内存连续、cache 友好，Python 的 `dict` / `set` 用它，细节见 [python/dict-set.md](../python/dict-set.md)。
- 开放寻址**删除不能直接清空**：查 11 时是从 3 号桶开始往后找的，如果把 3 清空，查找走到空桶就会以为 11 不存在。
  所以删除只留一个「墓碑」标记，意思是「这里有过东西，接着往后找」。

### 查找：先比 hash，再比 `==`

`key in table` 的完整流程：

1. 算 `hash(key)`，定位到桶（开放寻址则是一串候选桶）。
2. 在桶里逐个比较：**hash 值相同、并且 `==` 也相等**，才算找到。
3. 碰到空桶（拉链法：链走完）还没找到，就是不存在。

由此推出两条规矩：

- **hash 相同 ≠ key 相同**。上例中 3 和 11 在 m = 8 时落进同一个桶，所以第 2 步一定要再比 `==`。
- **相等的 key 必须有相同的 hash，而且 hash 不能变**。要是一个 list 放进表之后又被 `append` 改了，
  它的 hash 就变了，按新 hash 去找会找错桶，再也找不回来。所以 Python 干脆规定可变对象不可哈希，
  这就是 §5 里「list 要转 tuple」的根源。

### 为什么是 O(1)：负载因子 + 扩容

**负载因子** α = 元素个数 n / 桶数 m，可以理解为平均每个桶里有几个元素。α 是常数，单次查找就是常数次比较。

元素越塞越多，α 就会涨，所以 α 超过阈值（Java 是 0.75，CPython `dict` 约 2/3）时：

1. 开一个大约 2 倍大的新数组。
2. **所有元素按新的 m 重新算桶号**，因为 `% m` 变了，原来的位置全部作废。

一次扩容是 O(n)，但它每翻倍才发生一次，摊到每次插入上是 O(1)，和 `list.append` 的倍增是同一个道理。

最坏情况是所有 key 都撞进同一个桶，表退化成一条链，查找 O(n)。正常数据碰不到这种情况。
Python 对 `str` 的 hash 加了随机种子（每个进程不同），就是为了防止有人专门构造会全部碰撞的输入。

### 自己写一个（拉链法，约 20 行）

```python
class HashMap:
    def __init__(self, m=8):
        self.buckets = [[] for _ in range(m)]     # 每个桶是一条「链」，这里用 list 代替链表
        self.n = 0

    def _bucket(self, key):
        return self.buckets[hash(key) % len(self.buckets)]

    def get(self, key):
        for k, v in self._bucket(key):            # 桶里逐个比 ==
            if k == key:
                return v
        raise KeyError(key)

    def put(self, key, value):
        b = self._bucket(key)
        for i, (k, _) in enumerate(b):
            if k == key:                          # 已存在：覆盖 value，个数不变
                b[i] = (key, value)
                return
        b.append((key, value))
        self.n += 1
        if self.n > len(self.buckets) * 3 // 4:   # 负载因子 > 0.75 就扩容
            self._resize()

    def _resize(self):
        old = [kv for b in self.buckets for kv in b]
        self.buckets = [[] for _ in range(2 * len(self.buckets))]
        for k, v in old:                          # m 变了，每个元素都要重新算桶号
            self._bucket(k).append((k, v))
```

对应的练习题是 LC 705 Design HashSet 和 LC 706 Design HashMap，就是让你写这个。

### map 和 set 是同一张表

- **hash map**（`dict`）：桶里存 `(key, value)`，按 key 找、带出 value。
- **hash set**（`set`）：桶里只存 key。可以看成 value 恒为空的 map，只回答「在不在」。

下面的 §1 讲的就是「到底该用哪个、value 里存什么」。

## 1. 存什么：五档阶梯

从弱到强，**存的东西应该正好等于题目要返回的东西**：

| 存什么 | 长什么样 | 题 |
|---|---|---|
| 见过没有 | `set` | LC 217 / 128 / 139(wordDict) |
| 见过几次 | `Counter` / `dict[k] += 1` | LC 242 / 169 / 347 / 424 / 36 |
| 在哪见过 | `value -> index` | LC 1(补数→下标) / 3(char→上次位置) |
| 归到哪一组 | `范式 -> list` | LC 49 / 36 |
| 到得了吗 | `visited` / memo | LC 139 |

多存一档不会算错，但**会挡住别的解法**：LC 1 之所以必须存下标，是因为它要返回下标 ⇒
不能排序；同一道题给有序数组（LC 167）就能夹逼，O(1) 空间，一张表都不用。
**「能不能排序」这个判断要在建表之前做**，建完表就想不起来问了。

反过来，少存一档就答不出来：LC 3 如果只存 `set` 就只能 `l++` 逐格收缩，
存了「上次出现在哪」才能让 `l` 直接跳过去（见 array.md 的 reset 三档表）。

## 2. dict 还是桶：看键的值域

**键有界且连续 → 开数组，别开 dict。**

| 值域 | 怎么存 | 题 |
|---|---|---|
| 26 个小写字母 | `[0] * 26` | LC 242 / 424 |
| 1..9 | 长度 9 的 bool 数组 / 位掩码 | LC 36 |
| 频次 ∈ [1, n] | 下标当频次开桶 | LC 347 |
| 值 ∈ [1, n] 且要求 O(1) 空间 | **输入数组自己当桶**（§8） | LC 41 |
| 值域大或不连续 | 老实用 `dict` / `set` | LC 1 / 128 / 3 |

桶不只是常数快，有时是**复杂度上的降级**：LC 347 拿「下标 = 频次」开桶，
O(n) 直接突破了比较排序的 O(m log m) 下界，也不需要堆的 O(n + m log k)。
能开桶的前提写死在题面里：**频次不可能超过 n**。

## 3. hash 省掉的是排序 —— 但排序有两种用途，只能省掉一种

| 排序在干嘛 | hash 能不能替 | 题 |
|---|---|---|
| 造**单调性**（好夹逼 / 好扫端点） | **不能**，顺序正是要用的东西 | LC 15 / 167 / 56 / 57 / 435 |
| 造**范式**（同类同形，好归组） | 能，而且能更快 | LC 49 |
| 只是想要「存在性」 | 能，整个排序都不用做 | LC 128 |

- **LC 49**：`sorted(s)` 当 key，排序在这里和顺序无关，只是求一个「同一组必然相同」的
  代表元。既然只要范式，26 位计数元组一样是范式，于是 O(k log k) → O(k)。
- **LC 128**：想找最长连续段，本能是排序 O(n log n)。但整个过程只需要「x-1 在不在」
  这一个查询 —— 需要的是**存在性不是全序**，扔进 `set` 就够了。

> 判据：**先问「我需要的是顺序，还是只是存在 / 计数」。**
> 只要不是前者，排序就是买贵了。

## 4. 摊还 O(n)：两个不做就退化的动作

哈希查找 O(1) 只保证单次，整体 O(n) 还得靠这两条：

1. **入口剪枝**（LC 128）：只从 `x - 1 not in s` 的链头出发往上数。
   不加这一条，每个元素都从自己开始数一遍，是 O(n²)——**表本身没错，遍历方式错了**。  这个和hash关系不大，类似如何高效迭代剩下一些查hash的时间。
   共性写法是「每条链 / 每组只走一次」。
2. **一趟扫描：先查后存**（LC 1）：

   ```python
   seen = {}                       # value -> index
   for i, x in enumerate(nums):
       if target - x in seen:      # 先查
           return [seen[target - x], i]
       seen[x] = i                 # 后存
   ```

   顺序反了，`target == 2 * x` 时会**自己和自己配对**，返回 `[i, i]`。
   这是这一类最经典的错法，比越界还常见，因为它只在特定数据上炸。

## 5. 复合键与范式键

key 不必是单个值：

- **LC 36**：一个格子记三笔账 —— 行、列、宫。宫号一行算出 `(r // 3) * 3 + c // 3`，
  于是三张表可以合成一张，key 写成 `(kind, idx, val)`。不过这玩意写三个set也没毛病
- **LC 49**：key 是 `tuple(cnt)`（26 位计数）或 `''.join(sorted(s))`。
  **Python 里 list 不可 hash，必须 tuple** —— 这是范式键最常见的报错。

## 6. hash 给不了的：顺序

统计完之后要「前 k 个 / 最近用的 / 按序输出」，哈希表帮不上忙，得再叠一层结构：

- **LC 347**：Counter 只负责统计，选 k 那步靠**堆**（O(n + m log k)）或**桶**（O(n)）。
- **[LC 146 LRU](https://github.com/scatyf3/leetcode/blob/main/tracker/146.%20LRU%20Cache/note.md)**：hash 给 O(1) 定位，**双链表**补回「谁最近用过」。双向链表的四根指针见 [linked-list.md](linked-list.md)。
  这道题就是「哈希表 + 一个顺序结构」这个组合的标准形。

## 7. hash 常常只是基线解

它花 O(n) 空间买 O(1) 查找。题目一旦额外给了结构，这份空间往往能退掉：

| 题 | hash 基线 | 更优 | 靠的是什么 |
|---|---|---|---|
| LC 169 | 计数取最大 | Boyer-Moore 投票，O(1) 空间 | 「多数元素」的定义（> n/2 ⇒ 两两抵消后必剩它） |
| LC 1 | value → index | 有序版 LC 167 夹逼，O(1) 空间 | 输入有序 |
| LC 217 | set 比长度 | 允许改数组就排序后比邻居 | 不要求保留原序 |
| LC 347 | Counter + 堆 | Counter + 桶 | 频次值域有界 |

所以「我用了哈希表」不是终点，**是一个提醒：去看看题面还给了什么没用上**。

## 8. 原地哈希：拿输入数组自己当桶

§2 的极端情况：值域刚好对上下标域（1..n ↔ 0..n-1），题目又卡 O(1) 额外空间、不让开 set ——
那就**把 `nums` 本身当哈希表**，值 v 放进 v-1 号桶。2Sum 的 `seen` 是「开一个 set 当表」，
这里是「借输入数组当表」。

```python
i = 0
while i < n:
    j = nums[i] - 1
    if 0 <= j < n and nums[j] != nums[i]:
        nums[i], nums[j] = nums[j], nums[i]   # 换了：i 不动，继续处理换过来的数
    else:
        i += 1                                 # 没得换（越界 / 已归位 / 重复）：前进
```

> **换了就留，没换才走；所有位置走完才停。** 循环条件、要不要计数器，全从这一句推出来。

- `nums[j] != nums[i]` 一个条件同时管两件事：已归位（j == i）和重复值（不然死循环，试 `[1,1]`）
- 下标 j 要先存下来再交换，`nums[i], nums[nums[i]-1] = ...` 会用新的 `nums[i]` 算下标，写错位置
- O(n)：每次交换至少让一个数到达最终位置、之后再不动，所以交换最多 n 次

### 长得像读写指针，但不是

| | 读写指针（[array.md §读写指针](array.md)，LC 283 / 26） | 原地哈希（LC 41） |
|---|---|---|
| 指针 | `r` 扫、`w` 写，两个都在动 | 只有 `i` 在动，`j = nums[i]-1` 每次**算出来** |
| 目的地由谁定 | **顺序**：留下的依次排到 `w` | **值本身**：v 的家是 v-1 |
| 方向 | 只往前搬（`w ≤ r`） | **前后都可能**（`[3,4,-1,1]` 里 1 从 3 号被送回 0 号） |
| 每个元素动几次 | ≤ 1 | 可能被换走多次，但每次交换有一个数落定 |
| 本质 | 压缩 / 过滤 | 建哈希表 |

脑子里如果是「把元素丢到后面」，就会默认 `i` 左边已经定了 —— 但这里左边还会被送回来的数改写。
LC 41 连着三版循环都错在「什么时候前进」，根子就是这个。

### 同一套循环

| 题 | 映射 | 建完表后看什么 |
|---|---|---|
| LC 41 First Missing Positive | v → v-1 | 第一个 `nums[i] != i+1` → `i+1`，全对上 → `n+1` |
| LC 448 Find All Numbers Disappeared | v → v-1 | 所有 `nums[i] != i+1` 的 `i+1` |
| LC 442 Find All Duplicates | v → v-1 | 所有 `nums[i] != i+1` 的 `nums[i]` |
| LC 268 Missing Number | v → v（值域 0..n） | 第一个对不上的下标 |
| LC 287 Find the Duplicate | v → v-1 | 允许改数组才能用；不许改 → 快慢指针 |

> **判据：值域 = 下标域（或差一个偏移）+ 要 O(1) 空间 → 下标当哈希桶。**

## 空缺

- **前缀和当 key**（LC 560 / 523）：`前缀和 -> 出现过没有 / 在哪出现`，把「枚举所有子数组」
  的 O(n²) 压成 O(n)。这是哈希表在数组上的**第二大用途**，目前只做了 [560](https://github.com/scatyf3/leetcode/blob/main/tracker/560.%20Subarray%20Sum%20Equals%20K/note.md) 一道 ——
  上面全是「拿元素本身当 key」，那类是「拿一段的聚合值当 key」。
