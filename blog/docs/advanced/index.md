# 算法竞赛进阶

L3 的套路熟了以后再往上走一层。题都来自看板上的 **ACM 进阶** 题单，全是 LC 上竞赛味比较重的题。
每篇还是 L3 那个形状（怎么认 → 模板 → 栽过的坑），只是认题的信号变了。

## 和 L3 面试题的核心区别

| | L3 面试题 | 竞赛题 |
|---|---|---|
| **第一眼看什么** | 题面：给了树 / 区间 / 字符串 | **数据范围**：n 多大，直接决定能用什么复杂度 |
| **题面和结构** | 题面直接告诉你是什么结构 | 题面是个故事，**先翻译成**图、函数图或计数模型，才轮得到套路 |
| **答案** | 构造出答案本身（一条路径、一个子数组） | 常常「对 1e9+7 取模」：答案大到没法枚举，只能**数**出来 |
| **结构** | NeetCode 那十几类 | 多出几种面试基本见不到的：函数图、轮廓线、组合恒等式 |
| **构造题** | 几乎没有 | 有：没有搜索空间，靠观察直接给出一个合法答案 |
| **对错** | 思路对、能讲清楚就有分 | 只有 AC 和不 AC，边界、溢出、常数（Python 尤其）都得对 |

### 1. 数据范围就是提示

竞赛题的数据范围是**故意卡的**，基本可以从它倒推出要用的算法：

| n 的上限 | 能跑的复杂度 | 通常意味着 |
|---|---|---|
| ≤ 10 ~ 12 | O(n!) | 全排列暴搜 |
| ≤ 15 ~ 20 | O(2ⁿ · n) | **状压**：集合当成一个整数 |
| ≤ 500 | O(n³) | 区间 DP、Floyd |
| ≤ 5000 | O(n²) | 二维 DP |
| ≤ 2 · 10⁵ | O(n log n) | 排序、堆、二分、线段树 |
| ≤ 10⁹ | O(√n) 或 O(log n) | 二分答案、数学 |
| ≤ 10¹⁸ | O(log n) | **快速幂**、矩阵快速幂、倍增 |

还有一种情况：某一维特别小。比如 1931 的 m ≤ 5，意思就是让你把这一维压成状态。

> 面试题也给数据范围，但很少靠它出题。到了这一层，**先看数据范围再读题**。

### 2. 「取模」等于「这是计数题」

题目要求答案取模，说明答案是指数级的，不可能一个一个列出来。能走的路只有两条：
组合数学直接算，或者计数 DP 一层一层数。模意义下加、减、乘都可以随时取模，
**除法不行**，要换成乘逆元。这一套在 [快速幂与取模](./modular) 里。

### 3. 建模比套模板难

L3 的难点在于「认出是哪个套路」，这一层的难点在**前面那一步**：
把「石头」「员工」「颜色」翻译成点、边和状态。
翻译完通常就落回 L3 的东西了（并查集、拓扑排序、DP），所以每篇都会标它建在哪个 L3 套路上。

## 怎么读

- 每篇下面都有题单。**加粗的是代表题**，时间不够就只做那几道。
- 现在每篇都是占位（坑先挖好）：做完一道题，把真栽过的坑填进去，再把 status 改成 `draft`。
- 给题打 tag 和 L3 一样，写在 meta.json 的 `paradigms` 字段，值是这一层的文件名（如 `functional-graph`）。
