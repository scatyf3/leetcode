# DFS

**一条路走到底，走不通再退回上一个岔口。** 写成代码就是递归：先处理孩子，再回到自己。

仓库里挂在这一页的题分三种场合，要想的事各不相同：

| 场合 | 主要想什么 | 题 | 见 |
|---|---|---|---|
| **树** | 信息往哪个方向流：参数往下传，还是返回值往上交 | 98、104、105、114、124、236、297、437、543 | §1–§4 |
| **图 / 网格** | 有环，`visited` 什么时候标、标在哪 | 133、200、695、827 | §5 |
| **决策树** | 每层做一个决定，回来时撤销 | 17、39、46、78、79、131 | 子页 [回溯](backtracking.md) |

树没有环，所以树上的 DFS 不用 `visited`；图有环，不标就会绕圈。这是前两行最大的区别。

## 1. 树上：先问信息往哪流

每个节点要的信息，要么来自**祖先**（从上往下），要么来自**子树**（从下往上）。
先回答这个问题，参数和返回值就跟着定了：

| 信息从哪来 | 怎么传 | 在哪一步用 | 题 |
|---|---|---|---|
| 祖先 | **参数**往下传 | 前序：进节点就用 | 98（上下界）、1448（路径最大值）、437（剩余目标和） |
| 子树 | **返回值**往上交 | 后序：两个孩子都返回了才用 | 104、110、543、124、236、114 |
| 都不要 | 只靠副作用，不返回 | 哪一步都行 | 226（原地交换左右） |
| 两棵树对着看 | 两个节点**一起**递归 | 前序 | 100（同位置配对）、101（镜像配对：外侧配外侧、内侧配内侧） |

### 往下传：参数是「祖先们给我的约束」

98 验证 BST 是最典型的例子。只和父节点比是错的：一个节点必须落在**所有祖先**一起划出来的区间里，
这个区间只能沿路径往下传：

```python
def dfs(node, lo, hi):                 # (lo, hi)：祖先们给这棵子树划的开区间
    if node is None:
        return True
    if not (lo < node.val < hi):
        return False
    return dfs(node.left, lo, node.val) and dfs(node.right, node.val, hi)

dfs(root, float('-inf'), float('inf'))
```

往左走，上界收紧成 `node.val`；往右走，下界收紧成 `node.val`。1448 同理，参数是「从根到这里的最大值」。

### 往上交：返回值是「子树报告给父节点的东西」

104 最大深度是最简单的版本：`return max(左深度, 右深度) + 1`。难的是下面这种情况。

### 返回值 ≠ 答案（543、124）

543 直径、124 最大路径和都有一个坑：**答案路径可以在任何节点拐弯**，但拐了弯的路径没法再往上延伸 ——
父节点只能接一条从孩子出发、一路向下的单边路径。所以要拆成两件事：

- **返回值**：从这个节点出发、往下的**单边**最好成绩，给父节点用。
- **答案**：在这个节点**拐弯**的路径（左单边 + 自己 + 右单边），只能记到一个全局变量里，不能往上交。

```python
def max_path_sum(root):
    best = float('-inf')

    def gain(node):                        # 返回：从 node 往下的单边最大贡献
        nonlocal best
        if node is None:
            return 0
        l = max(gain(node.left), 0)        # 负贡献的分支直接不要
        r = max(gain(node.right), 0)
        best = max(best, node.val + l + r) # 在 node 拐弯的路径：只记账
        return node.val + max(l, r)        # 往上交：只能是单边

    gain(root)
    return best
```

543 是同一个形状：返回单边深度，`best = max(best, l + r)`。
`nonlocal best` 要写在**内层函数里面**，声明「这里改的是外层那个变量」（543 的 note）。

### 返回多个值（236、114）

一个返回值不够用时，就返回一个元组：

- **236 最近公共祖先**：后序返回「子树里有没有 p、有没有 q」。在某个节点上第一次两样都凑齐，它就是 LCA。
  有 BST 性质的 235 不用这么做，比大小就知道往哪边走，所以 236 只能先递归到底再把信息带上来（236 的 note）。
- **114 拉平成链表**：后序返回拉平后的 `(头, 尾)`，按 `node → 左链 → 右链` 拼起来。
  **要把 `node.left` 置成 `None`**，右指针串对了但左孩子还挂着，就不算链表（踩过）。

## 2. 前序 / 中序 / 后序：在哪一步处理自己

三种遍历的区别只有一个：**处理当前节点的那一行，放在递归两个孩子之前、中间还是之后。**

| 顺序 | 处理自己的时候 | 适合 |
|---|---|---|
| 前序 | 孩子还没访问，只有祖先的信息 | 往下传（§1 第一行）、序列化（297） |
| 中序 | 左子树访问完、右子树还没开始 | **只在 BST 上有特别的意义**：中序 = 升序（94、98 的另一种解、230 第 k 小） |
| 后序 | 两个孩子都返回了 | 往上交（§1 第二行），绝大多数「求子树的某个量」的题 |

所以拿到一道树题，与其先想「用哪种遍历」，不如先想 §1 的「信息往哪流」，遍历顺序就自然定了。

## 3. 两层递归：外层枚举起点，内层从起点往下

有些题的答案不一定从根开始，比如 437 路径总和 III 的路径可以从任何节点出发。那就拆两层：

- **外层**：遍历每个节点，把它当起点。
- **内层**：从这个起点往下 DFS，参数是「还差多少」。

**换起点只能在外层做**。如果内层也能「换个起点重新开始」，同一条路径会被不同的起点数好几次（437 踩过）。
572 另一棵树的子树也是这个形状：外层枚举挂载点，内层用 100 的同步递归比较。

这种写法最坏是 O(n²)。437 有 O(n) 的解：把「从根到当前节点的前缀和」存进哈希表，
和 560 是同一招（[hash.md](hash.md) §2）。

## 4. 建树：反过来比压扁难

| 题 | 输入 | 关键 |
|---|---|---|
| 108 | 有序数组 | 中点当根，左右两半递归，天然平衡 |
| 105 | 前序 + 中序 | 前序第一个是根，在中序里找到根切出左右；**再按左子树的节点数切前序** |
| 297 | 自己序列化出来的前序串（带 `#` 占位） | 递归时返回「我吃到了哪里」 |

### 105：别忘了第三刀

```python
def build_tree(preorder, inorder):
    idx = {v: i for i, v in enumerate(inorder)}   # 预存中序下标，查根 O(1)

    def build(pl, pr, il, ir):             # 都是左闭右开
        if pl >= pr:
            return None
        root = TreeNode(preorder[pl])
        k = idx[root.val]                  # 根在中序里的位置
        nl = k - il                        # 左子树有几个节点 —— 切前序全靠它
        root.left = build(pl + 1, pl + 1 + nl, il, k)
        root.right = build(pl + 1 + nl, pr, k + 1, ir)
        return root

    return build(0, len(preorder), 0, len(inorder))
```

第一遍漏了 `nl` 这一步：只有最外层的时候，前序和中序的起点才对得上，往下就对不上了（105 的 note）。
终止条件写 `pl >= pr`：左闭右开时 `l == r` 就是空区间，写 `>=` 顺便兜住 `l > r`。

### 297：返回值里带上「吃到了哪」

序列化很直接：前序遍历，空节点写 `#`。反序列化难在**不知道左子树在串里占多长**，
而右子树必须从左子树结束的地方开始读。所以让递归把这个位置报回来：

```python
def build(start):                          # 返回 (这棵子树, 我吃完之后的第一格)
    if vals[start] == '#':
        return None, start + 1             # 空树也要吃掉一格
    node = TreeNode(int(vals[start]))
    node.left, right_start = build(start + 1)   # 跳过根自己
    node.right, end = build(right_start)        # 从左子树吃完的地方接着读，不再 +1
    return node, end
```

为什么递归「能」报出这个位置：前序串里每棵子树都占一段**连续**区间，
区间的嵌套关系和树的嵌套关系一模一样，就像一个括号串。所以解析和测量长度是同一次遍历，长度是顺带算出来的。
任何递归下降解析器（JSON、表达式）的函数都返回 `(解析出的东西, 吃到了哪)`，是同一个形状。
推导细节见 [297 的 note](https://github.com/scatyf3/leetcode/blob/main/tracker/297.%20Serialize%20and%20Deserialize%20Binary%20Tree/note.md)。

只有中序加 `#` 是还原不出来的：不同的树可以写出同一个中序串。前序（或层序）加占位才能唯一还原。

## 5. 图和网格：有环，要 visited

树上不会走回头路，图上会。所以图 / 网格的 DFS 多一件事：**标记走过的点**。

### 什么时候标：入栈时就标

```python
def fill(r, c, iid):                       # 迭代 flood fill，返回这座岛的面积（827）
    grid[r][c] = iid
    stack, cnt = [(r, c)], 0
    while stack:
        r, c = stack.pop()
        cnt += 1
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < n and 0 <= nc < n and grid[nr][nc] == 1:
                grid[nr][nc] = iid         # 入栈时就标，不要等出栈
                stack.append((nr, nc))
    return cnt
```

如果等出栈才标，同一个格子在出栈前可能被几个邻居分别压进栈，被数好几遍。200 的第一版就是出队才标，后来改成了入队即标。
BFS 也是一样的规矩（[grid.md](../structures/grid.md)）。

### 递归写成「进函数再检查」，不算出栈才标

递归还有一种常见写法：邻居不检查、直接递归，在函数开头判断自己合不合法（694 用的就是这种）：

```python
def dfs(x, y):
    if not (0 <= x < m and 0 <= y < n) or grid[x][y] != 1:
        return
    grid[x][y] = 0                 # 进来立刻标
    cur_island.append((x, y))
    for dx, dy in DIRS:
        dfs(x + dx, y + dy)        # 邻居交给下一层判断
```

看起来像是「晚标」，其实不会重复。出栈才标之所以出问题，是因为格子**在栈里排队时还没被标**，这段时间里别的邻居会再压它一次。
递归调用不会让格子排队：`dfs(b)` 一调用就立刻执行，第一件事就是标 b。父层 for 循环里还没轮到的邻居，只是还没发起的调用，不是一个躺在容器里、还没标记的格子。

| 写法 | 有没有「已排上、还没标」的窗口 | 结果 |
|---|---|---|
| 显式栈 / 队列，**出栈才标** | **有**，格子在容器里等着 | 重复入栈 → TLE（200）、面积算多（827） |
| 显式栈 / 队列，入栈就标 | 没有 | ✓ |
| 递归，父层检查邻居、标完再调用 | 没有 | ✓，起点没有父层，要在外面单独标 |
| 递归，进函数再检查 | 没有，调用即执行 | ✓，起点不用特殊处理；代价是每格最多多 4 次立刻 return 的调用，常数大一点 |

> **判断标准不是「标记写在哪一行」，而是「格子有没有可能在没被标记的状态下排着队」。** 只有显式容器会让格子排队。

两种递归写法真正共同的风险是**递归深度**（见 §6），和在哪里检查无关。

BFS 照搬这种写法（无脑入队、出队时检查）也能走遍，但数层数会多一层；
和「出队才标、出队不检查」那种指数爆炸的写法放在一起的实测对比，见 [bfs.md](bfs.md) §1「能不能照搬 DFS 的『进来再检查』？」。

### 标在哪

| 写法 | 什么时候用 | 题 |
|---|---|---|
| 原地改 grid | 允许改输入 | 695 走过的陆地改成 0；827 把每座岛写成编号（从 2 开始，0 = 水，1 = 还没编号的陆地），编号本身就是 visited；79 的 optimal 把当前格改成 `'#'`，回溯时改回来 |
| `set` | 不想改输入 | 200；79 的 sol（回溯时要 `remove`） |
| 映射表兼任 visited | 克隆类题 | 133：`old → new` 的映射表里有 key，就说明访问过，可以不另开 set |

### 先把不变的部分算成表（827）

827 的暴力是每个 0 都翻成 1、再重新 DFS 算面积，每次都把没变过的岛重数一遍。
改成两遍：第一遍给每座岛编号、记下面积；第二遍对每个 0 看上下左右是哪几座岛，`1 + 这几座岛的面积和`。
邻居编号收进 `set`，连起两座岛还是只贴着一座，用同一个公式就算对了。
细节见 [827 的 note](https://github.com/scatyf3/leetcode/blob/main/tracker/827.%20Making%20A%20Large%20Island/note.md)。

### 隐式图（139）

图不一定画在题面上。139 Word Break 的节点是字符串里的「缝」（位置 0..n），
`s[i:j]` 在字典里就连一条 `i → j` 的边，问题变成「0 能不能走到 n」。

## 6. 递归还是显式栈

Python 默认递归深度上限是 1000。树很深、或者网格很大（比如 500×500 全是陆地）时，递归会爆栈。
这时改成显式栈：把「递归调用」换成 `stack.append`，把「函数开头」换成 `stack.pop()`（133、139、827 都这么写）。

代价是后序不好写：返回值要从孩子流回父亲，显式栈里没有这一步，需要自己记状态。
所以**树上的后序题照常递归**，图 / 网格上只需要「走遍」的题再用显式栈。

## 7. 坑

- **先确认定义**：110 平衡二叉树说的是「每个节点的左右子树高度差不超过 1」，第一遍理解错了（110 的 note）。
- 235：递归调用要传 `root.left` / `root.right`，写成 `root` 就原地打转了。
- 1448：「路径上没有比它大的」用 `>=`，相等也算好节点。
- 102 层序：孩子先判 `None` 再入队。
- 437：路径必须连续，不能跳过中间节点（437 的 note）。
