# 栈 通用 trick

「用栈」不是一个范式，是好几个 —— 栈里**存的东西不一样**，弹栈的时机和写法就完全不一样。
混起来最容易出错的是上下文栈（LC 394），因为它的写法看着像别的栈，脑子里的模型却是递归。

先按「栈里存的是什么」定位：

| 栈里存的是 | 子类 | 什么时候弹 | 题 |
|---|---|---|---|
| **还没配对的符号 / 下标** | §1 配对 | 遇到能和栈顶配上的 | LC 20；[LC 32](https://github.com/scatyf3/leetcode/blob/main/tracker/32.%20Longest%20Valid%20Parentheses/note.md)（存下标，栈底垫 -1） |
| **还没用上的操作数** | §2 求值 | 遇到运算符，弹两个算完压回 | LC 150 |
| **还没找到答案的下标** | §3 单调栈 | 新元素打破单调性，栈顶的答案当场确定 | LC 739、84 |
| **外层的现场** | §4 上下文栈 | 遇到 `]` / `)`，恢复外层、合并内层结果 | **LC 394**、224 / 227 / 772 |
| 元素 + 附带状态 | §5 辅助栈 | 和普通栈一样 | LC 155（每层顺带存「到这为止的最小值」） |

> 拿到一道栈题先问：**栈里每一格代表什么？** 答出来，什么时候压、什么时候弹就跟着定了。

### 1. 配对

栈顶 = 最近一个还没配上的左边。来一个右边，只可能和栈顶配。
LC 32 把「符号」换成「下标」，栈底垫一个 `-1` 当「上一个断点」，`i - stack[-1]` 就是当前合法长度。

### 2. 求值

LC 150 逆波兰：操作数压栈，运算符弹两个。注意弹出顺序：先弹的是**右**操作数（`b = pop(); a = pop(); a - b`）。

### 3. 单调栈

栈里是「还在等答案」的下标，保持单调。新元素一来，凡是被它打破单调的栈顶，答案就是它 —— 弹出并结算。
每个下标进出各一次，O(n)。LC 739 等「下一个更大」，LC 84 等「左右第一个更矮」。

### 4. 上下文栈 = 手写的递归调用栈

嵌套结构（括号套括号）天然是递归。**先写递归版，再逐行翻译成栈**，就不会乱：

```python
def decodeString(self, s):
    def decode(i):                    # 从 i 开始解析，返回 (这一层的结果, 停在哪)
        res, num = "", 0              # 这一层自己的局部变量
        while i < len(s):
            c = s[i]
            if c.isdigit():
                num = num * 10 + int(c)
            elif c == "[":
                inner, i = decode(i + 1)    # 进入里层，拿回里层结果
                res += num * inner
                num = 0
            elif c == "]":
                return res, i               # 这一层结束
            else:
                res += c
            i += 1
        return res, i
    return decode(0)[0]
```

递归版里每层的 `res` / `num` 互不干扰，所以不会「外层的数字混进里层」。栈版只是把这件事手动做了：

| 递归版 | 栈版 |
|---|---|
| 当前层的局部变量 `res`、`num` | `cur_str`、`cur_counter` |
| 调用 `decode(...)`：系统替调用方保存局部变量，被调函数拿到一套全新的 | `[`：**把 cur 压栈（存档），再把 cur 清空** |
| `return`：调用方的局部变量自动恢复，返回值拼进它的 `res` | `]`：**弹栈（读档），和刚结束的那层合并，结果写回 cur** |

> **`[` 存档 + 清空，`]` 读档 + 合并。栈里只放「外层的」，cur 永远只代表「当前这一层」。**

这句话的两半各管一类 bug（都是 LC 394 上真踩过的）：

| 违反了哪半句 | 写法 | 后果 |
|---|---|---|
| `[` 时没清空 → 外层的东西留在 cur | 压栈后没写 `cur_str, cur_counter = "", 0` | 外层字符混进里层；`3[a]2[b]` 的第二个数字读成 32 |
| `]` 时把弹出的值写回 cur 变量 → 外层的东西又混进 cur | `cur_counter = num_stk.pop()` | 用完没清零，下一个数字接在后面：`3[a]2[bc]` 输出 `aaa` + 32 个 `bc` |

**弹出来的东西只在合并那一行用，用完就丢**：`k = num_stk.pop()` 用局部变量接，别塞回 `cur_counter`。

同一个套路：

- **LC 224 / 227 / 772 Basic Calculator**：每层的局部变量多了「当前结果」「上一个运算符」，遇 `(` 存档清空、遇 `)` 读档合并
- 遇到任何嵌套结构（嵌套列表、子表达式），先问「**每一层的局部变量是什么**」—— 答案就是栈里要存的东西

### 5. 辅助栈

LC 155 Min Stack：每压一个元素，顺带压「到这一格为止的最小值」，弹的时候一起弹，`getMin` 就是 O(1)。
栈每一格存的是「元素 + 截至此处的聚合值」，和 §4 存「外层现场」是两回事。
