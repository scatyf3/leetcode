# 状态机

**信号**：输入一个一个读进来，同一个输入该怎么处理，**取决于之前处在什么阶段**，而且这样的阶段只有有限几种。

845 最长山脉是样板：同样是「这一步在下降」，如果之前在爬坡，那就是开始下山；
如果之前在平地上，那这段下降什么都不算。这里起作用的不是数值，而是**身份**（平地 / 上坡 / 下坡）。

写的时候感觉「要维护一堆状态、分支很多」，通常就是这类题。解法也是固定的：**先把状态和转移表列出来，代码就是照着表逐格翻译。**

## 1. 和 DP、scan、模拟的边界

最容易混的是 DP。两者都在「状态」之间转移，区别只在于**有没有选择**：

| | 确定性状态机（本页） | 状态机 DP（[1d-dp.md](1d-dp.md) §3） |
|---|---|---|
| 每一步 | 当前状态 + 输入 → **唯一**的下一个状态 | 可以从好几个状态转过来，**取最优** |
| 转移里有 `max` / `min` 吗 | 没有（`res = max(...)` 只是记全局答案，不属于转移） | 有 |
| 例子 | 845 山脉、8 atoi | 股票买卖（121、122）、198 打家劫舍 |

```python
# 股票：「持股」可以来自两条路，要比较 → DP
hold = max(hold, cash - price)

# 845：上升时只有一种走法，不用比 → 状态机
if arr[i] > arr[i-1]:
    up += 1
```

和其他邻居的区别：

- **scan**（[1d-dp.md](1d-dp.md) §4）：转移也是纯函数、没有选择，但**没有身份**，每一步的处理方式都一样（前缀和、前缀 max）。状态机是带身份的 scan。
- **模拟**（[simulation.md](simulation.md)）：题面直接把过程讲清楚了，照着做就行。状态机的状态要**自己从题意里提炼**，题面不会告诉你一共有哪几个阶段。

> 状态机是一种建模方式（列出状态和转移），DP 是在状态之间做选择。
> 状态机 + 转移里要取最优 = 状态机 DP；状态机 + 转移是唯一的 = 本页。

## 2. 先列表，再写代码

845：找最长的「严格上升再严格下降」的连续子数组，长度至少 3。

**第一步：列状态。**问自己「读到一个新元素时，我得知道之前处在什么阶段，才知道怎么处理它？」

| 状态 | 含义 |
|---|---|
| 平地 | 还没开始爬，或者山刚断开 |
| 上坡 | 正在爬 |
| 下坡 | 爬过山顶，正在往下走，这时就是一座完整的山 |

**第二步：列转移表。**行是当前状态，列是输入（相邻两个元素是升、降还是平）：

| 当前状态 | 上升 ↗ | 下降 ↘ | 相等 → |
|---|---|---|---|
| 平地 | → 上坡 | 留在平地，**不计数** | 留在平地 |
| 上坡 | 留在上坡 | → 下坡 | → 平地 |
| 下坡 | → 上坡，**这是一座新山，重新计数** | 留在下坡 | → 平地 |

表里两个加粗的格子，正好是最容易写错的两处（见 §4）。

**第三步：逐格翻译。**每个状态顺便带上一个计数（上坡几步、下坡几步），答案就是 `上坡 + 下坡 + 1`：

```python
def longestMountain(arr):
    res = 0
    up = 0        # 当前这座山：上坡走了几步
    down = 0      # 当前这座山：下坡走了几步
    for i in range(1, len(arr)):
        if arr[i] > arr[i-1]:          # 上升
            if down > 0:               # 下坡状态遇上升 → 新山
                up = 0
                down = 0
            up += 1
        elif arr[i] < arr[i-1]:        # 下降
            if up > 0:                 # 平地遇下降不计数
                down += 1
        else:                          # 相等：任何状态都回到平地
            up = 0
            down = 0

        if up > 0 and down > 0:        # 处在下坡状态 = 完整的山
            res = max(res, up + down + 1)
    return res
```

## 3. 状态存在哪：单独一个变量，还是藏在计数器里

845 的代码里没有 `state` 这个变量，三个状态是从两个计数器推出来的：

| 状态 | 对应的计数器取值 |
|---|---|
| 平地 | `up == 0` |
| 上坡 | `up > 0, down == 0` |
| 下坡 | `up > 0, down > 0` |

两种写法都可以：

- **藏在计数器里**（845）：代码短。前提是每个状态都能从计数器的取值**唯一**判断出来。
- **单独一个 `state` 变量**（8 atoi 那种「读空格 / 读符号 / 读数字」）：状态多、或者状态和计数没有对应关系时更清楚，可以直接写成 `transition[state][input]` 查表。

> 拿不准时先显式写 `state`，跑通以后再看能不能并进计数器里。反过来就很难：一开始就藏起来的话，漏了哪个状态很难看出来。

## 4. 坑

845 前后写错过好几版，每一处都能在转移表里找到对应的格子：

| 写法 | 后果 | 对应转移表里的哪一格 |
|---|---|---|
| 下坡遇上升时不清零，接着累加 | `[1,2,1,2,1]` 返回 5，应该是 3：两座山被连成一座 | 下坡 → 上坡（新山） |
| 下降时不管前面有没有上坡，都给 `down` 计数 | `[3,2,1]` 被当成山 | 平地遇下降 |
| 相等时不清零 | `[1,2,2,1]` 被当成山 | 相等那一列 |
| 题意看成 `len > 3` | 漏掉最小的山 `[1,3,2]` | —— |

还有一个方向性的坑：**845 不是单调栈**。单调栈回答的是「往左第一个比我小 / 大的在哪」，可能隔着很远；
这题的上坡必须连续，只用和相邻元素比，一个计数器就够了。
拿 pop 次数当下坡步数也不对：一个很小的元素会一次弹出整段上坡（`[1,2,3,4,0]` 里 0 一次弹出 4 个），
而且山两边一般不一样长，`2 * cnt + 1` 这种对称公式不成立。

> 判断标准：答案只依赖**相邻**元素 → 计数器 / 状态机；要找**隔着若干元素**的第一个更大 / 更小 → 单调栈（[stack.md](stack.md)）。

## 5. 计算器：状态是「还没结算的那个运算符」

227 Basic Calculator II：字符串里只有非负整数和 `+ - * /`，没有括号。

先套第一句的信号检查：读到一个 `+` 时，该怎么处理手上刚读完的数？
**取决于这个数前面的运算符**：前面是 `+` 就单独成一项，前面是 `*` 就得乘进上一项里。
同一个输入、处理方式看之前的身份 —— 这就是状态机，身份就是 `op`，一共 4 种。

### 为什么结算的是「上一个」运算符

读 `3+5*2`，读到 `+` 时你还不知道 5 会不会被乘。一个运算符的右操作数，
要等到**下一个**运算符出现才算读完。所以代码的节奏是：

```
读完一个数 → 按它前面那个 op 结算 → 把当前字符记成新的 op
```

`op` 初值设成 `'+'`，等于在开头补了一个 `0 +`，第一个数不用特判。

### 转移表

状态 = 上一个 `op`，触发 = 读到运算符或者到了字符串末尾：

| 上一个 op | 对手上的 `num` 做什么 |
|---|---|
| `+` | 作为新的一项压进去 |
| `-` | 作为新的一项 `-num` 压进去 |
| `*` | 栈顶 `*= num` |
| `/` | 栈顶 `= int(栈顶 / num)` |

然后 `op = 当前字符`、`num = 0`。最后把栈里所有项加起来。

### 栈其实可以压掉

看转移表：栈**只动栈顶**，从来不往下翻。`+` / `-` 压进新的一项以后，下面那些项再也不会被改了。
所以栈里真正「活着」的只有一项，其余的可以直接加进一个累加器：

| 变量 | 角色 |
|---|---|
| `op` | 状态（身份） |
| `num` | 正在读的数字（缓冲区） |
| `last` | 当前这一项，还可能被后面的 `*` / `/` 改 |
| `res` | 已经定死的项之和 |

```python
def calculate(s):
    res = last = num = 0
    op = '+'
    for i, c in enumerate(s):
        if c.isdigit():
            num = num * 10 + int(c)
        if c in '+-*/' or i == len(s) - 1:      # num 读完了，按上一个 op 结算
            if op in '+-':
                res += last                      # 上一项定死了
                last = num if op == '+' else -num
            elif op == '*':
                last *= num
            else:
                last = int(last / num)
            op, num = c, 0
    return res + last
```

5 万组随机表达式和栈版对拍，结果一致。

> 判断栈是不是真的需要：**只看栈顶、从不往下翻 → 压成一个变量。**

### 坑

| 写法 | 后果 |
|---|---|
| 除法用 `//` | `-3 // 2 == -2`，题目要向零截断，应该是 `-1`。用 `int(a / b)` |
| 第二个判断写成 `elif` | 最后一个字符是数字时，只累加不结算，最后一个数丢了 |
| 漏掉 `i == len(s) - 1` | 同上，最后一个数没人结算 |

空格不用特殊处理：它既不是数字也不是运算符，两个 `if` 都不进。

## 6. 状态入栈：括号把外层状态打断了

224 Basic Calculator 多了括号（只有 `+ -`）。读到 `(` 时要开始算一个新的子表达式，
但外层算到一半的状态（已经定死的和、括号前面的符号）不能丢，括号结束后还得接着用。

一个变量存不下「嵌套了好几层的外层状态」，所以要把**整个状态**压进栈：

```
遇到 (  → 把当前状态压栈，状态清零，开始算括号里面
遇到 )  → 括号里面算完了，弹出外层状态，把结果并回去
```

394 Decode String 是同一个形状：遇到 `[` 把「外面已经拼好的串 + 重复次数」压栈，遇到 `]` 弹出来拼回去。
394 卡在 L3 的话，可以从这个角度再看一遍：它不是「栈题」，是「括号打断了状态机，栈负责存档」。

> 两类题里栈的角色不一样：
> 227 的栈存的是一项一项的数，只动栈顶，可以压掉；
> 224 / 394 的栈存的是**被括号打断的外层状态**，嵌套几层就得存几份，压不掉。

772 Basic Calculator III（会员题）= 227 + 224：四则运算加括号，两招一起用。

## 7. 不是状态机的：162 找峰值

162 和 845 都在说上坡下坡，但 162 不是状态机。

状态机的前提是**一个一个按顺序读**，处理方式取决于之前读过什么。
162 是二分：每一步直接跳到 `mid`，只看 `nums[mid]` 和 `nums[mid+1]` 这一对，
跟之前看过哪些格子没关系，没有「之前的阶段」这回事。见 [binary-search.md](binary-search.md) 的「统一视角」一节。

> 判断标准：有没有一个**按顺序推进的读指针**，并且处理方式依赖**它身后**读过的东西。
