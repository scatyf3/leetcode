# 字典序贪心 通用 trick

31 Next Permutation 做完最难受的是**找不到分类** —— 不是 DP、不是二分、不是滑窗。
它属于一个很小但很固定的家族：**比较的是字典序，所以高位说了算**。

> **越靠左的位权重越大。要「刚好大一点」→ 保留最长前缀，改最右边能改的位，后缀重置成最小；
> 要「尽可能大 / 小」→ 改最左边能改的位。**

数和字符串都是从左往右逐位比的，第一个不同的位置决定胜负，右边全部无关。
所以这类题的思考顺序永远是三问：

1. **改哪一位**：最右边能改的（刚好大一点），还是最左边能改的（最大 / 最小）？
2. **改成什么**：刚好比它大的最小值？还是能拿到的最大值？
3. **其余部分怎么办**：前面已经定了胜负，后面调成最小 / 最大 / 照抄

### 1. 31 的三步就是这三问

| 三问 | 31 的答案 | 为什么 |
|---|---|---|
| 改哪一位 | 降序后缀左边那一位 `i`（第一个 `nums[i] < nums[i+1]`） | 降序后缀已经是这几个数的最大排列，内部怎么换都不会更大，必须动它左边那位 |
| 改成什么 | 后缀里**比 `nums[i]` 大的最小数** | 要变大，但要尽量小；后缀降序，从右往左第一个 `> nums[i]` 的就是它 |
| 后缀怎么办 | 反转成升序 | `i` 已经变大，后缀越小越好；交换后后缀仍是降序，反转即升序，不用 sort |

例：`1342` → 改 `3`（后缀 `42` 降序）→ 换成 `4` 得 `1432` → 后缀 `32` 反转 → `1423`。

### 1.5 树的视角：next permutation = 排列树上的下一个叶子

把所有排列画成树：根 = 空前缀，第 k 层定第 k 位，孩子按数值从小到大排，叶子 = 完整排列。
按孩子从小到大 DFS，**叶子出现的顺序就是字典序**（LC 46 回溯走的就是这棵树）。

```
                    1
        ┌───────────┼───────────┐
        2           3           4
      ┌─┴─┐       ┌─┴─┐       ┌─┴─┐
      3   4       2   4       2   3
      │   │       │   │       │   │
      4   3       4   2       3   2
    1234 1243   1324 1342   1423 1432
                       ↑      ↑
                     当前    下一个
```

下一个排列 = DFS 顺序里的下一个叶子：

| 算法步骤 | 树上的动作 | `1342` 上 |
|---|---|---|
| 第 1 步：从右往左跳过降序后缀 | **往上爬**，直到自己不是父节点的最后一个孩子 | 「2」是「134」的最后一个孩子，「4」是「13」的最后一个孩子 → 爬到「3」，它后面还有兄弟「4」 |
| 第 2 步：和后缀里比它大的最小数交换 | **走到下一个兄弟** | 「3」→「4」，前缀变成「14」 |
| 第 3 步：反转后缀成升序 | **沿最左孩子一路走到叶子** | 「14」子树的第一个叶子 `1423` |
| 整个降序（`i = -1`） | 爬到根 = 整棵树走完 → 回到第一个叶子 | `4321` → `1234` |

> **「后缀降序」⇔「一路都是最后一个孩子」**：后缀每长一位就往上爬一层，降序说明这棵子树已经走完。
> 找降序后缀，就是在算要往上爬几层。爬到的是真实的祖先节点（前缀 `nums[0..i-1]`），不是虚拟节点。

这个形状（往上爬到能往右 → 右移一步 → 一路往左到底）是**树上找后继**的通用形状，见过的有：

- **BST 中序后继**：没有右子树就往上爬，直到自己是某个祖先的左孩子
- **二进制 +1**：末尾连续的 1 变 0（往上爬），第一个 0 变 1（走到兄弟），右边全 0（最左路径）

next permutation 的好处是**不用真的建树、不用回溯栈**，只看数组本身就知道要爬几层。

### 2. 家族

| 题 | 目标 | 改哪一位 | 其余部分 |
|---|---|---|---|
| **LC 31** Next Permutation | 刚好大一点 | **最右边**能变大的位 | 调到最小（反转成升序） |
| **LC 556** Next Greater Element III | 同 31，对象是整数的各位 | 同 31 | 同 31，外加两种 -1：已是最大排列 / 超 `2**31 - 1` |
| **LC 670** Maximum Swap | 只换一次，换到最大 | **最左边**那个「右侧有更大数」的位 | 和右侧最大值的**最右一次出现**换 |
| **LC 738** Monotone Increasing Digits | ≤ n 的最大单调递增数 | 最左边破坏单调的位（遇到相等要往回退） | 该位 -1，右边全变 9 |
| **LC 402** Remove K Digits | 删 k 位让结果最小 | 从左往右，左边的大数优先删 | 单调栈实现 |
| **LC 60** Permutation Sequence | 第 k 个排列 | 从最高位起逐位确定 | 按 `(n-1)!` 分块算每位是谁 |

两个方向要分清：

| 想要 | 改的位置 | 典型 |
|---|---|---|
| **刚好比 X 大**（下一个） | 最**右**边能改的 | 31 / 556 |
| **最大 / 最小**（一步到位） | 最**左**边能改的 | 670 / 738 / 402 |

> 「下一个」要尽量少动，所以从右边找；「最大 / 最小」要尽量多赚，所以抢最高位。

### 3. 怎么认出来

信号：题目在**比大小**（数字、字符串、排列），并且问的是

- 最小的比 X 大的 / 下一个
- 只能做一次 / k 次操作后的最大 / 最小
- 第 k 个

看到就先问：**哪一位最先决定大小？我能动的最高位 / 最低位是哪一位？**

### 4. 坑

- **等号放哪边**（31）：第 1 步跳过的是 `nums[i] >= nums[i+1]`，第 2 步跳过的是 `nums[j] <= nums[i]`。
  重复数字时等号放错会「换完没变大」，测 `[1,5,1]` → `[5,1,1]`、`[1,1,5]` → `[1,5,1]`
- **整个降序**（31）：`i = -1`，第 2 步跳过，第 3 步反转整个数组 = 回到最小排列，刚好是题目要的
- **溢出**（556）：结果要和 `2**31 - 1` 比，不是和输入比
- **最右一次出现**（670）：`1993` 应该换成 `9913`，和第一个 9 换得 `9193` 更小

### 和别的范式的关系

- 31 第 1 步找的是**最长单调后缀**，402 用**单调栈**维护「左边尽量小」—— 单调结构是这一族常用的工具，
  不是这一族本身
- 「只看高位、低位无关」和 [1d-dp.md](1d-dp.md) §4「贪心 = 退化的 DP」是一回事：字典序天然给了贪心选择性质，
  高位一旦赢了，后面不用回头比
