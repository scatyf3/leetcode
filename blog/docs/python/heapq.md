# heapq

## 一句话

**不是一个类，是一组作用在普通 `list` 上的函数**，把 list 当完全二叉树维护成**小根堆**。

## 底层长什么样

下标 `i` 的孩子是 `2i+1` 和 `2i+2`，父亲是 `(i-1)//2`。只保证「父 ≤ 子」，兄弟之间、不同子树之间没有顺序：

```
          1                 list: [1, 3, 2, 7, 4, 5]
        /   \                       0  1  2  3  4  5
       3     2
      / \   /
     7   4 5
```

`heappush` 放到末尾再往上浮，`heappop` 把末尾挪到根再往下沉，都只走一条根到叶的路径，O(log n)。下面拆开讲。

### 先记住两条规矩

堆要同时守住两件事，push 和 pop 的每一步都是在想办法同时守住它们：

1. **形状**：树必须从上到下、从左到右**排满**，中间不能有空位。这样整棵树才能紧凑地存进一个 list，
   靠 `2i+1` / `2i+2` 算出孩子在哪。
2. **顺序**：每个父节点 ≤ 它的孩子。所以最小的一定在根上，也就是 `h[0]`。

### `heappop`：把末尾挪到根，再往下沉

要弹出根上的最小值 1。直接把根拿走，根上就空出一个洞，**形状**就坏了。

能「免费」拿走、不破坏形状的位置只有一个：**list 的最后一格**（`list.pop()` 是 O(1)，后面也没有别的元素要挪）。
所以先拿最后一个元素 5 去填根上的洞：

```
弹出 1，末尾的 5 挪到根上               形状对了，但顺序坏了：5 比孩子 3、2 都大
          5                             list: [5, 3, 2, 7, 4]
        /   \
       3     2
      / \
     7   4
```

现在形状没问题，但 5 比它的孩子大，**顺序**坏了。修法就是**往下沉**：和孩子比，跟**较小的那个孩子**交换。

```
5 和较小的孩子 2 交换                   5 已经没有孩子了，停
          2                             list: [2, 3, 5, 7, 4]
        /   \
       3     5
      / \
     7   4
```

为什么一定要换**较小的**那个：换上来的孩子会成为另一个孩子的父亲。如果把 3 换上来，3 就成了 2 的父亲，3 > 2，
顺序又坏了。只有两个里较小的那个，才比另一个也小。

一直往下比、往下换，直到比两个孩子都小，或者已经到了叶子，就停下。

### `heappush`：放到末尾，再往上浮

和 pop 反过来。新元素先 `append` 到 list 末尾，也就是树的下一个空位，**形状**自动是对的。
然后只可能是它和祖先之间的**顺序**出问题，所以和父亲比，比父亲小就交换，一直往上，直到不比父亲小或者到了根。

在上面的 `[2, 3, 5, 7, 4]` 里 push 一个 0：

```
0 放到末尾（下标 5，父亲是下标 2）     比父亲 5 小，换         比父亲 2 小，换，到根了，停
          2                                 2                        0
        /   \                             /   \                    /   \
       3     5                           3     0                  3     2
      / \   /                           / \   /                  / \   /
     7   4 0                           7   4 5                  7   4 5

list: [2, 3, 5, 7, 4, 0]           [2, 3, 0, 7, 4, 5]        [0, 3, 2, 7, 4, 5]
```

### 为什么是 O(log n)

不管上浮还是下沉，每交换一次就往上或往下走一层，最多走完一条从根到叶子的路径。
排满的二叉树有 n 个节点时只有大约 log₂ n 层，所以最多换 log n 次。

> 可以在解释器里验证：`h = [1, 3, 2, 7, 4, 5]; heapq.heappop(h)` 之后 `h` 是 `[2, 3, 5, 7, 4]`，
> 再 `heapq.heappush(h, 0)` 之后是 `[0, 3, 2, 7, 4, 5]`，和上面一样。
>
> CPython 的 `heappop` 实际写法稍有不同：它先让「洞」一路沿着较小的孩子沉到叶子，再把末尾元素从那里往上浮。
> 这样每层只比一次而不是两次，比较次数更少。堆的性质一样都守住了。

## 复杂度

| 操作 | 写法 | 复杂度 |
|---|---|---|
| 建堆 | `heapify(h)` | **O(n)**，原地 |
| 插入 | `heappush(h, x)` | O(log n) |
| 弹最小 | `heappop(h)` | O(log n) |
| 看最小 | `h[0]` | O(1) |
| 先推再弹 | `heappushpop(h, x)` | O(log n)，比分两步快 |
| 先弹再推 | `heapreplace(h, x)` | O(log n)，堆不能是空的 |
| 前 k 大 / 小 | `nlargest(k, it)` / `nsmallest` | O(n log k) |

## 由此而来的坑

- **只有小根堆**：大根堆存 `-x`，取出来再取负。Python 3.14 起有了 `heappush_max` 等函数，
  但 LeetCode 的环境不一定这么新，面试里默认还是取负。
- **`h[1]` 不是第二小**：第二小在 `h[1]` 和 `h[2]` 之间，没有保证。要第 k 小就弹 k 次。
- **元组比较打平**：`(dist, node)` 里 `dist` 相等时会去比 `node`，`node` 是 `ListNode` 这种不能比大小的东西就抛 `TypeError`。
  中间垫一个自增计数：`(dist, i, node)`（LC 23）。
- **以为 `heapify` 返回新堆**：它原地改、返回 `None`。`h = heapify(nums)` 之后 `h` 是 `None`。
- **改了元素没重建**：堆里的值被外面改了，堆性质就坏了。要么 `heapify` 重来，要么懒删除（弹出时再判断过期）。

## 什么时候用

- 前 k 大：维护**大小为 k 的小根堆**，比 k 小的直接扔 —— O(n log k)（LC 215、347、973）。
- 数据流中位数：一个大根堆放较小的一半，一个小根堆放较大的一半（LC 295）。
- 多路归并：堆里放每一路当前的头（LC 23）。
