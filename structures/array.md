# Array 通用 trick

数组的能力：**随机访问 O(1)、有下标顺序**。大多数技巧都是在利用「下标」和「顺序」做文章。

下标(indexing)是这里的核心，最容易犯的错误是off-by-one，防止此错误的方法是在写index的时候想一下「我当前的index是开还是闭，当前index是即将处理的，还是最近一个已经处理的」

二维数组多出「行列对称性、邻接关系、层/圈结构」三样东西，单独一篇：[matrix.md](matrix.md)。

## 约定

### 切片

按照大部分编程语言的约定，我们的切片(slice)是左开右闭区间。如做一个cover array全部元素的切片，写作 `[0,len(lst)]`

1. **合法下标**：`0 .. len(lst)-1`。下标 `len(lst)` 根据契约，描述的是「第一个尚未处理 / 无效的尾部下标」）的下一个（虽然在array里后面无了，但在其他切片理由）
2. **切片是半开的**：`lst[0:len(lst)]` 取整个数组，右端 `len(lst)` 只是「越过末尾」的边界，不指向真实元素。记住 `[start:end)` —— 含头不含尾。

为什么要有这个契约？在这个契约里，右边界同时描述三件事：
- **下一个要写入的位置** (next element to write)
- **已有的合法元素个数** (number of valid elements)
- **要返回的值** (value to return)

同一套约定在二维上的版本见 [matrix.md](matrix.md) §0；把「缝」当成二分的搜索空间
（`r` 取 `n` 不取 `n-1`）见 [paradigms/binary-search.md](../paradigms/binary-search.md)
「另一套半开区间模板」，LC 35 / 704 就是它。

### 缝

下标可以指**元素**，也可以指元素之间的**缝**(gap)。n 个元素有 n+1 条缝，编号 `0..n`：

```
gap   0   1   2   3   4
      |   |   |   |   |
      | a | b | c | d |
idx     0   1   2   3
```

缝 `i` 卡在 `a[i-1]` 和 `a[i]` 中间，缝 `0` 在最左，缝 `n` 在最右。上面说 `len(lst)`
「不指向真实元素」，换成缝就一点都不别扭了——它就是最后那条缝，实实在在存在。

**什么时候该在缝上思考：答案是「位置」而不是「元素」的时候。**

| 场景 | 为什么是缝 | 题 |
|---|---|---|
| 切片边界 | `a[l:r]` 的 `l`、`r` 都是缝，长度直接 `r-l`，不用 ±1 | 到处都是 |
| 二分找插入位 | 插入点可能在末尾之后，所以 `r = n` 不取 `n-1` | LC 35 / 704 |
| 前缀和表 | `P[i] = sum(a[0..i))` 的下标就是缝，表开 n+1 长，`sum(l,r) = P[r] - P[l]` | LC 238 / 42 |
| 分割 / 断点 | 「在哪切一刀」问的就是缝 | LC 139(节点是缝，n+1 个，不是字符) |

> 自检一句话：**元素 n 个，缝 n+1 条。** 表开 `n` 还是 `n+1`、二分右端取 `n-1` 还是 `n`、
> 前缀和要不要写 `P[i+1]`，全是这一条在起作用。off-by-one 多半是两套编号混着用了。

二分那套模板见 [paradigms/binary-search.md](../paradigms/binary-search.md)，
前缀表为什么开 n+1 见 [paradigms/1d-dp.md](../paradigms/1d-dp.md) §5。

### 读写指针

类似in place sort，或者把不符合的swap到后面的invalid段类。一个 `w`(写/慢) 一个 `r`(读/快)，
`r` 逐格扫过全部元素，`w` 指向**下一个要写的位置**，不变式把数组切成三段：

```
    0            w          r            n
    [--- kept ---|-- junk --|-- unread --]
```

`kept` 已保留(就是结果)、`junk` 已丢弃的垃圾(可以随便踩)、`unread` 还没读到的。

`w` 正是上面切片契约里那个右边界，**三重身份**同时成立：下一个写入位 / 已保留的个数 /
要返回的值 —— 所以 LC 26、LC 27 直接 `return w`，不用另开计数变量。

**为什么原地覆盖是安全的**：`w <= r` 恒成立，要踩的格子早被 `r` 读过了。这条一旦不成立
就得掉头 —— LC 88 合并两个有序数组时从前往后写会覆盖 `nums1` 里还没读的数据，所以改成
**从后往前填**。

两种写法，选一种记死：

| 写法 | 保序 | 搬运次数 | 适合 | 题 |
|---|---|---|---|---|
| **覆盖式** `if keep(a[r]): a[w] = a[r]; w += 1` | ✓ | 保留几个搬几次 | 要保留的多 | LC 26 / 27 |
| **交换式** 把要删的和末尾 swap，`n -= 1` | ✗ | 删几个搬几次 | 要删的极少 | LC 27 第二解 |

完整 SOP(不变式怎么写、约定 A/B 的差别、返回 `w` 还是 `w+1`)见
[notes/two-pointer-array-partition.md](../notes/two-pointer-array-partition.md)；
它在范式上属于双指针的「同向·快慢」一族，见 [paradigms/two-pointer.md](../paradigms/two-pointer.md) §2。

## feature

given一个array，我们可以思考几个问题：
1. 有无顺序，或者partial顺序(有序+rotate k)，或者无序但是解题要排序
   - 全序 → 二分(LC 35/704)、夹逼(LC 167)、只比邻居(LC 26)、双序列归并(LC 88)
   - partial(rotate k) → 找仍然单调的那一半(LC 33/153)
   - 无序但可排序 → 排完才能夹逼(LC 15)、排完端点才能扫(LC 56/57/435)
2. 有无重复
   - 重复就是答案(LC 217/242/49)
   - 重复要跳过(LC 15 三元组去重、LC 26 原地去重)
   - 用 set 天然去重(LC 128)
3. index本身有无意义，如果index有意义，类似桶排序，用index做key 比naive hash更好
   - index 是答案(LC 1 返回下标 → 不能排序，必须 hash 存 index；LC 189 移位；LC 704/35)
   - index 是量纲(LC 11 宽度、LC 42 位置、LC 238 前后缀分界)
   - index 当 key(LC 347 下标=频次，O(n) 干掉堆)
   - **index 全无意义** → 退化成 multiset，只剩计数/集合(LC 217/242/49/169/128)
4. 范围
   1. 有没有0，有0导致乘法不可逆(LC 152 遇 0 重置；LC 238 不能用总积÷)
   2. 有没有负数，负数导致乘法要维护俩极值(LC 152)；负数还让前缀和不单调 → LC 53 只能 Kadane 不能滑窗
   3. 是否范围很小，能拿来桶排序(LC 3 charset、LC 242/424 26 桶、LC 347 频次≤n、LC 36 值域 1-9)
5. in place or not
   - 硬要求原地(LC 26/27/189/48/88 写回 nums1)
   - 额外约束(LC 238 不许除法)
   - 值域=下标域时原地当哈希 → §6 ⚠️ 空缺，没做过 LC 41/448
6. 是否是区间[s,e]，参见 [paradigms/intervals.md](../paradigms/intervals.md)(LC 56/57/435)
7. stream, LC 295，这里的特点是给你一个按时序的1d元素
   - 判据其实是「能不能预处理」：静态才能排序/建前缀和；流只能增量维护(LC 295 对顶堆)
   - LC 里这类归 design 分类，不会以「给你一个 nums」出现

返回：
1. 是否存在？t/f(LC 217/242/55/36)，某个 value？(LC 169 众数、LC 153 最小、LC 121/53/152 最优值、LC 42 总量、LC 11 最大面积)，某个 index？(LC 1/35/704)
2. 切片，这里都是坑
   1. 细节
      1. 切片让你返回value还是index —— 返回长度(LC 3/424/300)、返回子串本身(LC 5)、只返回聚合值不返回切片(LC 53/152)
      2. 这个切片是是否要求连续，有的会不要求连续！(subseq vs subarray)
         连续 LC 53/152/3/424/5/647 vs 可跳 LC 300 vs 顺序无关 LC 39
         → [notes/subseq-vs-substr.md](../notes/subseq-vs-substr.md) 的四档表
   2. 切片本身，切片本身的expend是否可逆
      1. substr/sum 统计，可逆(LC 3 去重、LC 424 计数都能 O(1) 撤销)
      2. 有0乘法，... 不可逆(LC 152 → 只能双状态 DP)
   3. 这个切片变化边界的时候怎么reset状态，l++？l跳转到某个index？l=r？
      - l++ 逐格收缩(LC 424)
      - l 跳到重复者的下一格(LC 3)
      - l=r 整体重启(LC 53 Kadane 前缀和转负)
      - l=r 或 l=r-1 双起点(LC 5/647 中心扩展的奇偶)


切片移动的正确性论证

「`l` 和 `r` 这么动，凭什么不漏解」——**每一族各有各的理由，混着记必错**。

| 怎么动 | 凭什么对 | 题 |
|---|---|---|
| 同向·滑窗 | **合法性向下封闭**：窗口合法 ⇒ 它的任意子窗口也合法。所以 `r` 撑到不合法时 `l` 只需前进、**永不回退**——回退不可能捡到新的合法窗口 | LC 3 / 424 |
| 同向·快慢 | **不变式**，不是排除候选：`a[0..w)` 已保留、`w <= r` 保证写指针踩不到未读数据。O(n) 来自每格只读一次 | LC 26 / 27 |
| 相向·夹逼 | **支配论证**：移动短板那一侧时，被丢掉的那批候选的上限**已经结算过了**，所以丢得起 | LC 11(宽度封顶)、LC 42(水位当场定死)、LC 15 / 167 |
| 相背·扩散 | **收缩封闭**：回文去掉两端还是回文 ⇒ 一断就能停，不必再往外试 | LC 5 / 647 |
| 归并(指针各在一条序列上) | 不排除任何候选，O(n) 纯粹来自**每个元素只读一次**，和上面四条都不是一回事 | LC 88 / 21 / 23 |

上面 2.3 那三种 reset 写法不是随便挑的，**需要的条件从弱到强**：

| 写法 | 需要的条件 | 题 |
|---|---|---|
| `l++` 逐格收缩 | 最弱，永远成立 | LC 424 |
| `l` 直接跳某个 index | 得**知道**跳过去之后立刻合法 | LC 3(跳到重复者的下一格) |
| `l = r` 整体重启 | 最强：当前前缀对未来**毫无价值** | LC 53(前缀和转负) |

能满足强条件就能少走很多格；满足不了就退回 `l++`，慢但不会错。

> 反过来是个更有用的判据：**候选丢不掉、只能汇总的，那就不是双指针而是 DP**。
> LC 152 的 `mn` 现在最差，乘个负数就翻身，永远丢不掉 —— 所以它归
> [paradigms/1d-dp.md](../paradigms/1d-dp.md)，不归这一节。

四族各自的完整论证、拿到新题的五步选型，见
[paradigms/two-pointer.md](../paradigms/two-pointer.md) §2。


## 和其他结构的联系

1. **语义替代**: hash，array可以做一个天然的以[0..n]的正int为key的hash（反过来「什么时候必须是真哈希表」见 [hash-table.md](hash-table.md)）
   - 值域小且连续 → 直接开桶(LC 242 26 字母、LC 424 窗口频次、LC 169 计数)
   - 把值当下标反着存(LC 347 下标=频次，O(n) 干掉堆的 O(n log k))
   - 值域大或不连续 → 才退回 dict(LC 1 值→下标、LC 128 用 set、LC 3 char→上次出现位置)
2. 可以拿来做别的dataset的**building blocks**
   1. 二叉树，有个二叉树序列化的题(LC 297 tree→array)；反过来 LC 105 从 preorder/inorder
      两个数组重建树，**array 的一段切片就是一棵子树**；LC 98 验 BST = 中序序列严格递增
   2. bitmap(LC 190/191 拿 int 当定长布尔数组、LC 338 用 array 存每个数的 popcount)
   3. matrix 用stride之类的表示(LC 54 螺旋、LC 48 转置+反转、LC 36 九宫格开桶)
   4. heap(完全二叉树的下标公式 2i+1 / 2i+2，heapq 底下就是个 list；LC 23 k 路归并、LC 295 对顶堆)
   5. string，本质上是array但是不可变(LC 271 array↔string 互转；LC 3/424/5/647 用的全是
      array 技巧，只有两处差别：Python str 不可变要先 list()、字符集有限所以天然能开 26 桶)
   6. graph(邻接矩阵/邻接表 = array 套 array；LC 417 二维 array 本身就是隐式图、LC 133 邻接表)


## 在array上的题型

### 1. 双指针 (two-pointer)

此类方法不限定于array，其他1d结构如string也能操作，但是以目前观测，在array里出现最频繁，根据的.

这里双指针有若干要回答的问题：
1. initial state和运动方向，分三个case
    1. 都在start ➡️➡️ (快慢 LC 26/27、滑窗 LC 3/424)
    2. 一个start 一个end ➡️⬅️ (LC 11/15/42/167)
    3. 基于某些中心扩散 ⬅️➡️ (LC 5/647)
2. 对应两者同向运动还是相向运动
    1. 相向运动 (LC 11/15/42/167)
    2. 同向怎么做iteration
        - 一个快一点一个慢一点, 外层loop l(slow)，内层loop r(fast) (LC 26/27)
        - 内层loop是skip没有意义的，还是贪婪添加，直到第一个没有意义的 (skip: LC 26/27；贪婪: LC 3/424)
    3. reset
        - l++？ (LC 424)
        - l跳转到某个index？ (LC 3)
        - l=r？ (LC 53 Kadane 整体重启)

### 2. 反转 (reversal)

> 这里只有LC 189， extend到LC 48，但感觉类似群论或者indexing体操了，考虑split到单独的note，但现在先放在这里

1. naive的解是rotate k，然而需要extra space
2. 优化的方法是：`rev(AB): rev(A),rev(B),rev(total)`

eg: 
```
        [1 2 3 4 5 6 7]    n = 7, k = 3
         └──A──┘ └─B─┘     手上是 AB, 要的是 BA

(1)     [7 6 5 4 3 2 1]    反转全部    rev(AB) = B'A'  两段位置对了, 但各自是倒的
         └─B'┘ └──A'─┘
(2)     [5 6 7 4 3 2 1]    反转前 k    B' → B
         └─B─┘
(3)     [5 6 7 1 2 3 4]    反转后 n-k  A' → A          ✓
               └──A──┘
```

- 右旋 k 位：反转全部 → 反转前 k → 反转后 n-k（LC 189 Rotate Array）
  - 坑：`k` 可能大于 `n`，第一件事是 `k %= n`；`k == 0` 时三次反转恰好还原，不用特判
- O(1) 空间的「段交换」原语，字符串旋转、翻转单词同理。

同一个原语升到二维就是「转置 + 反转 = 旋转」，见 [matrix.md](matrix.md) §3 —— LC 48 Rotate Image 就是它。

### 3. 前缀 / 后缀预处理 

对每个位置预存「左边的累积量」或「右边的累积量」：前缀和、前缀最大、后缀最大…

1. 什么时候需要，接雨水 vs 最大积水 (要逐位置的左右 max: LC 42；只要一个封顶量、不用预处理: LC 11)
2. prefix 和 suffix array能否压缩成一个scalar
   1. 枚举方向和依赖方向能不能拧成一个 (LC 121 枚举卖出日只向左要 min，同向 → 一个 min_so_far)
   2. 方向必然相反时，看有没有一块白送的暂存（return 同size array）
      (有: LC 238 借 res 拆两趟 → O(1) extra；没有: LC 42 输出是标量 → 压不掉，换相向双指针)
3. 有个拆分数组，agent说要放在之类，但现在还没做过


### 4.  滚动变量压缩(rolling variable)

把转移方程右边的下标圈出来，`k = max(i − 被依赖的下标)`。**k 是常数就能压成 k 个标量，
不必存整个数组**；k 随 n 增长就必须留数组。

最常见、最好认的特例是「枚举方向」和「依赖方向」一致 —— 那一侧的极值/累加值边走边滚就行。
1. dp：LC 70 `dp[i-1],dp[i-2]` → k=2；LC 152 k=1 但两个分量 → 也是 2 个标量
2. prefix 预处理：其实是 dp 退化到底的那一档（转移是纯函数，1d-dp §4 叫 scan），见 §3


### 5. 贪心 vs DP（在数组上）

- 有**贪心选择性质**（每步赢家当场唯一确定、可加、互不牵制）→ 贪心（LC 122 吃所有上坡）。
- 候选要回头比较、依赖后续 → DP（打家劫舍）。
- 「只依赖前 k 步」决定的是能否滚动压缩空间，**与贪心/DP 无关**。

这三条的完整论证在 [paradigms/1d-dp.md](../paradigms/1d-dp.md) §4「贪心 = 退化的 DP」——
那边的口径是「贪心是候选数被压到 1 的 DP」，顺着这条还能再退一步到 scan。
状态定义的两种口径、多分量状态见同一篇 §2 / §3。
