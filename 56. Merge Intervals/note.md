# 56. Merge Intervals

范式：区间题 §1 合并/扫描 —— [paradigms/intervals.md](../paradigms/intervals.md)

## 一开始的想法

naive solution 是不断迭代直到没有 overlap，O(n^2)；判断迭代一次，这个迭代本身也 O(n)。
但是可以按 start 或者 end sort 消复杂度，idk？

## 排序消掉了哪一层循环

> 这里按 start 排序是不是消除了双重迭代里的一层，专心比邻接的切片就行，
> 而不是比当前切片和其他所有切片？

对，但有一处要拧紧：**不是「比相邻的两个原始区间」，是「比当前区间和最后一个*已合并*的区间」。**

反例 `[[1,5],[2,3],[4,8]]`：处理到 `[4,8]` 时它的原始邻居是 `[2,3]`，两者不重叠；
但正确答案是 `[[1,8]]`，因为 `[4,8]` 要比的是**已经吸收了 `[2,3]` 的那个 `[1,5]`**。
所以循环里维护的必须是 `res[-1]`，不是 `intervals[i-1]`。这是本题最容易写错的一行。

一般化：

> 排序的价值不在「有序」本身，在于它**制造了单调量**；单调性让「前面所有元素」
> 被压缩成 **O(1) 的状态**，内层循环于是消失。

这和 [structures/array.md](../structures/array.md) §4 滚动变量压缩是同一件事 ——
那里的自检三问「① 枚举哪个点 ② 向哪个方向要信息 ③ 能否让枚举方向=依赖方向」，
**排序干的就是第 ③ 步**。

| 题 | 被压成 O(1) 的「历史」 | 单调性哪来的 |
|---|---|---|
| 121 买卖股票 | `min_so_far` 标量 | 天然（时间递增） |
| 53 最大子数组 | `cur` 标量 | 天然（下标递增） |
| **56 合并区间** | `res[-1]` 一个区间 | **要靠排序买** |

反过来，[128 最长连续序列](../128.%20Longest%20Consecutive%20Sequence/) 是**故意不排序**的 ——
它要 O(n)，付不起那个 log n，改用哈希集合换「O(1) 判断某数在不在」。**排序不是免费的。**

## 按 end 排行不行

> 那按 end 排序是不是也能写啊，只是反直觉？

能写，但**不是「只是反直觉」** —— 按 end 排后 `new.start` 不再单调，
新区间可能一次吞掉前面好几个，必须把「比一次」换成 while 往回弹。

反例 `[[1,2],[5,6],[0,10]]`（按 end 排正好是这个顺序）：`[0,10]` 同时和前两个都重叠。
对拍验证：只比最后一个的 end 排版本，2 万组随机数据错 **4592** 组。

加了 while 回弹后仍是 O(n) 摊还（每个区间进一次出一次），但代码更长、更易错、
输出还不按 start 有序。**没理由选它。**

排序键的推法（能推就不用背表）见 [intervals.md §1](../paradigms/intervals.md)：

> 排序键要选「新元素身上参与判定的那个量」。判定式 `new.start <= old.end`
> 的新的一侧是 `start`，所以排 start。

## 和 435 的排序不是一回事

我一开始记的「合并类排 start / 调度类排 end」那张表能用，但掩盖了一件事：
**两处的排序在干完全不同的活。**

| | 排序为了什么 | 去掉排序会怎样 |
|---|---|---|
| 56 合并 | 让扫描只需看一个历史状态 | 答案还对，只是慢 |
| [435 调度](../435.%20Non-overlapping%20Intervals/) | 让**贪心选择本身成立** | 贪心**直接选错** |

56 的排序是效率工具，435 的排序是正确性论证的一部分 ——
那个交换论证的第一句就是「设 a 是全局右端点最小的区间」，没有这个前提整个证明不存在。

**所以遇到新区间题，先分清排序是为了压缩历史还是为了支撑贪心，再谈选哪个键。**

## 边界

`[1,4]` 和 `[4,5]` 在本题**算**重叠，要合成 `[1,5]`，所以是 `s <= res[-1][1]`。
435 里端点相碰**不算**重叠，条件是反的。**逐题看题面，没有通则。**

## 自测用例

```
[[1,3],[2,6],[8,10],[15,18]]  -> [[1,6],[8,10],[15,18]]   基本
[[1,4],[4,5]]                 -> [[1,5]]                  端点相碰
[[1,10],[2,3]]                -> [[1,10]]                 包含关系 (验 max)
[[1,5],[2,3],[4,8]]           -> [[1,8]]                  链式吞并 (验 res[-1])
[[1,4],[0,4]]                 -> [[0,4]]                   乱序输入
```

后两个是专门验「max 不能写成 = e」和「比的是 res[-1] 不是原始邻居」的。
