# 417 Pacific Atlantic Water Flow

## 我最初的想法(错的)

```
2d dp
for p if curr > left and top, and left/top is true, then current is true
a is right and down
```

想法是: 太平洋在上边和左边, 所以「能到太平洋」只跟左邻居、上邻居有关, 按行优先扫一遍就行; 大西洋反过来倒着扫一遍。

## 为什么错

DP 成立的前提是**依赖关系无环**, 能排出一个「先算谁后算谁」的顺序。

这题里水能往**四个**方向流(只要邻居 <= 自己)。所以到太平洋的路径完全可以先往右、往下绕一圈, 再拐回上/左边界。

### 反例(必须找内部格子!)

我第一次举的反例是 2x2 的 `9 5 / 1 4` 看 `(0,1)` —— **这是错的**,
`(0,1)` 本来就在第一行, 贴着太平洋, base case 就把它设 True 了, 说明不了任何问题。
反例必须落在既不在第一行也不在第一列的格子上。

```
9 9 1
9 5 2
9 9 9
```

看 `(1,1)=5`:
- 上邻居 `(0,1)=9 > 5` → 流不过去
- 左邻居 `(1,0)=9 > 5` → 流不过去
- 但 **往右** 流到 `(1,2)=2`(2 <= 5 ✓), 再 **往上** 流到 `(0,2)=1`(1 <= 2 ✓), `(0,2)` 在第一行 → 到太平洋 ✅

真值 `(1,1) = True`; 只看 left/up 的 DP 算出 `False`。

### 「虚拟第一行第一列设 0」/「第一行第一列直接设 True」为什么救不了

这两个是同一件事, 而且**只修了 base case, 没修转移方程**。

边界格子本来就该是 True(它贴着海), 这部分你是对的。错的是**内部格子的转移只看 left/up**。
上面反例里 `(1,1)` 就是内部格子, base case 怎么设都轮不到它。

那把四个方向都写进转移行不行? 不行 —— `(1,1)` 依赖 `(1,2)`, 而 `(1,2)` 也可能依赖 `(1,1)`,
依赖成环 → 没有任何扫描顺序能算对 → **成环就不是 DP, 是图搜索**。

(硬要用 DP 的话只剩「反复扫直到不再变化」这种迭代到不动点的写法, 但那本质就是 BFS, 还多跑了很多轮无效扫描。)

> 跟 [133 Clone Graph](../133.%20Clone%20Graph/note.md) 是同一个病根: 无向边天然成环, 所以那题也不能「先算依赖再算我」, 只能用「先占位后填充」破环。这题的破法不一样, 见下面。

## 正解：反向多源 BFS

> 两个海的整条边界各自一次性入队，逆流而上（只走高度 `>=` 当前的邻居），各得一个可达集合，取交集。
> 代码见 `sol2.py`。

### 这是图吗？

是的。每个格子是一个节点，水能从 A 流到相邻的 B（`h[B] <= h[A]`）就连一条 A→B 的边。

### 怎么想到建图的？

信号：题目给了「一步的规则」，却问「多步的结果」。

### 从哪里开始搜索，每个 node 吗？

有 naive 版和优化版：

| | 问法 | 起点 | 复杂度 |
|---|---|---|---|
| naive | 正向问「谁能流到海」 | 每个格子都得当一次起点，因为要逐个检验 | mn 个起点 × 每次最坏 mn → O((mn)²) |
| 优化 | 反向问「从海边逆流能爬到谁」 | 只有贴着海的那一圈 | 一次搜索把答案全标出来 → O(mn) |

### 这个搜索顺序咋想出来的？

不是「反向搜得快」，而是反向能把 m*n 个独立问题合并成 1 个：

1. 正向：每个起点问的是不同的问题（「**我**能到海吗」），答案各自独立，没法合并 —— 从 (1,1) 搜完的 visited 对 (2,3) 毫无用处，得清空重来。
2. 反向：所有候选共享同一个目标集合。「能到达集合里任意一个」是个 OR 关系，OR 恰好可以合并成一次多源搜索 —— 把整个目标集合一起当起点扔进去就行。

> 目标端是共享的，起点端是独立的，所以从共享的那端出发。

这叫**多源 BFS**。心智模型：虚构一个「太平洋」超级节点，连向所有上/左边界格子，然后从它做普通的单源 BFS —— 把整圈边界一起入队，效果完全等价，只是省掉了那个虚拟节点。

### 为什么只写 BFS

这题只关心可达性（布尔量），不关心步数，遍历顺序无所谓，DFS 也对（`sol1.py` 留作对照）。只写 BFS 是因为：

- 整圈边界一次入队，**就是**上面那个超级节点，写法和心智模型一一对应；
- 200×200 全同高度时，递归 DFS 深度能到 4 万层，Python 会 RecursionError；
- 「入队即标记 visited」这套写法和 [994 Rotting Oranges](../994.%20Rotting%20Oranges/note.md) 是同一套 —— 那题要数步数，只能 BFS。

## 理解solution

### 这道题里的递推关系是啥？

```
reach(v) = v 贴着海   OR   存在邻居 u: h[u] <= h[v] 且 reach(u)
```

长得和 DP 转移方程一模一样，但 `reach(v)` 和 `reach(u)` 可以**互相依赖**（等高的平地、先绕出去再拐回来），所以它不是能按某个顺序算完的递推，而是一个**不动点**：一直套这个式子，直到没有格子再从 False 变 True。

BFS 就是求这个不动点最省的办法：base case（边界格）先入队，每出队一个 u，就把「因为 u 而变成 True」的邻居标上、入队。

把式子倒过来读：u 是 True 时，所有 `h[v] >= h[u]` 的邻居 v 都变 True —— **这就是逆流条件 `>=` 的来历**，不用靠「水往低处流所以反过来往高处爬」去硬想方向。

## 备注：硬改成 DP 也行（不写）

> DP和图会有相似性？
> 所以图可以无损改dp吗，比如我们先mark两个海的边界块为true，然后沿着边界螺旋迭代块，每个块看上下左右？

可以，但要先把平台缩点：把每个等高连通块缩成一个超级节点（块内所有格子共享同一个 dp 值，因为它们互相可达），缩点后依赖图是严格的 DAG，按高度排序就是合法拓扑序，DP 成立且正确。

一句话：**图改 DP 需要无环**。知道能行就好，比 BFS 麻烦得多，选择题和答案卡都不考它。
