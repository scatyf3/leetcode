### 这是啥算法

不属于 DP / 二分 / 滑窗这些通用范式，是一个**专门的经典算法**：字典序下一个排列（Narayana Pandita，14 世纪），C++ `std::next_permutation` 就是它。第一次见基本想不出来，面试默认你见过。

### 直觉：手算 `1342` 的下一个

> 用 1、2、3、4 各一次，找比 `1342` 大的数里最小的那个。

**1. 前面能保留多少位就保留多少位**（越靠左越不想动）

| 尝试保留 | 剩下的数 | 剩下最大能排成 | 结论 |
|---|---|---|---|
| `134` | `2` | `2` | 就是自己 ✗ |
| `13` | `4 2` | `42` | 已经到顶 ✗ |
| `1` | `3 4 2` | `432`，现在才 `342` | 还有空间 ✓ |

所以要改的是第二位的 `3`。

> **尾巴是从大到小排的 = 已经到顶。** 这就是「降序后缀」。第 1 步从右往左扫，就是在找「从哪开始尾巴还没到顶」。

**2. 这一位只变大一点点**：从后面的 `4 2` 里挑比 `3` 大的最小数 → `4`，得到 `14 _ _`。

**3. 后面排成最小**：第二位已经变大了，后面怎么排都比原数大，所以排成最小 `23`。答案 **`1423`**。

核对一下，以 1 开头的排列按顺序是 `1234, 1243, 1324, 1342, 1423, 1432`，`1342` 后面就是 `1423` ✓

> **尽量保留左边 → 找第一个「后面还有空间」的位置 → 把它换大一点点 → 后面排成最小。**

### 和「数字 +1」是一回事

`1299 + 1 = 1300`：右边的 `99` 到顶了，所以动 `2`；`2` 只加 1 变成 `3`；右边重置成 `00`。排列只是多了一条限制：只能用手上这几个数。

| +1 | 排列 |
|---|---|
| 到顶的 `99` | 降序后缀 |
| 最右能变大的那一位 | 降序后缀左边紧挨着的 `i` |
| 只加最小的量 | 和后缀里「比它大的最小数」交换 |
| 右边重置成 `00` | 后缀排成升序 |

另一个视角：字典序里**前缀相同的排列排在一起，形成一块**。后缀降序，就说明当前排列已经是这一块的最后一个，只能退到更短的前缀，进入下一块的第一个排列。

### 填空版的三个 bug

| | 我写的 | 应该是 | 为什么 |
|---|---|---|---|
| 1 | `nums[i] < nums[i+1]` | `nums[i] >= nums[i+1]` | 循环意思是「还在降序后缀里就往左走」，条件反了；用 `>=` 是因为相等也算到顶（`[1,1]`） |
| 2 | `nums[j-1] < nums[j]` | `nums[j] <= nums[i]` | 要找的是比 **`nums[i]`** 大的，不是后缀内部相邻比较；`<=` 跳过相等的（`[1,5,1]` → `[5,1,1]`） |
| 3 | `l = i` | `l = i + 1` | `nums[i]` 是刚换上去的那一位，不属于后缀；全降序时 `i = -1`，`l = 0` 正好反转整个数组，不用特判 |

拿 `[1,3,5,4,2]` 跑原版：第 1 步停在 `i=3`（应该是 1）；修好后第 2 步又把 `3` 和 `2` 换了（应该换 `4`）。

### 代码

```python
class Solution:
    def nextPermutation(self, nums: list[int]) -> None:
        n = len(nums)

        # 1. 从右往左跳过降序后缀，停在第一个 nums[i] < nums[i+1] 的位置
        i = n - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1

        # 2. 在后缀里从右往左找第一个比 nums[i] 大的数，就是「比它大的最小数」
        if i >= 0:
            j = n - 1
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]

        # 3. 后缀仍是降序，反转成升序；i = -1 时正好反转整个数组
        l, r = i + 1, n - 1
        while l < r:
            nums[l], nums[r] = nums[r], nums[l]
            l += 1
            r -= 1
```

时间 O(n)，空间 O(1)。

- **为什么从右往左第一个比它大的就是最小的**：后缀是降序，越往右越小。
- **为什么交换后后缀还是降序**：`nums[j]` 左边都 ≥ 它，右边都 ≤ `nums[i]`，把 `nums[i]` 放进 `j` 这个位置，顺序不会乱。所以第 3 步反转就行，不用 sort。

测试用例：`[1,3,5,4,2]` → `[1,4,2,3,5]`，`[1,5,1]` → `[5,1,1]`，`[1,1]` → `[1,1]`，`[3,2,1]` → `[1,2,3]`，`[1]` → `[1]`。可以再手算一遍 `1432` → `2134`，这个例子要一直退到第一位。

### 可迁移

> 「求下一个 / 恰好大一点」类问题都问这三句：**哪一位是最右边还能变大的？它最少变大多少？它右边怎么重置成最小？**
