size of prefix and suffix is n or n+1?

n+1，几乎总是 n+1。 而且理由不是「方便」，是这个约定下下标的含义变了

| | size n（含自己） | **size n+1（不含自己）** |
|---|---|---|
| 定义 | `P[i] = agg(nums[0..i])` | `P[i] = agg(nums[0..i-1])` = `agg(nums[:i])` |
| 下标含义 | **元素位置** | **切片端点 / 已取了几个** |
| `P[0]` | `nums[0]` | 幺元（和 0，积 1） |
| 建表 | `P[0]=nums[0]` 要单独写 | `P[0]=e`，循环从 0 跑到 n-1，无特判 |
| 区间和 | `P[r] - P[l-1]`，`l=0` 要 if | `P[r] - P[l]`，`l=r` 自动得 0 |

即我们这里枚举缝

```
元素:      1   2   3   4          n = 4 个元素
缝:      ↑   ↑   ↑   ↑   ↑        n+1 = 5 条缝
下标:    0   1   2   3   4
P:       1   1   2   6  24        P[i] = 缝 i 左边所有元素的积
S:      24  24  12   4   1        S[i] = 缝 i 右边所有元素的积
```

不过我们这里各自用不到最后一个缝，agent：「那个 ±1 必须出现在某处，你只能选它出现在建表还是用表。」

n+1版

```python
prefix_mul = [1] * (n + 1)
for i in range(n):
    prefix_mul[i + 1] = prefix_mul[i] * nums[i]

suffix_mul = [1] * (n + 1)
for i in range(n - 1, -1, -1):
    # nums [n-1 =>0]
    # suffix read [n=>1] write [n-1 => 0]
    suffix_mul[i] = suffix_mul[i + 1] * nums[i]

return [prefix_mul[i] * suffix_mul[i + 1] for i in range(n)]
```

为啥suffix+1，因为suffix看的是右缝儿prefix是左缝


这个东西算1d dp吗？

不对，这个不就是 只依赖i-1的1d dp吗，aka退化特例，对的，这里的分类学是：

| | 候选数 | 例子 |
|---|---|---|
| DP | 多个，要回头比较 | 53、300 |
| 贪心 | 多个，但赢家当场唯一确定 | 122、55 |
| **scan（本题）** | **零个，转移是纯函数** | 前缀和 / 前缀积 / 前缀 max |

怎么判断不需要explict存 prefix 和suffix array，直接先用后更新？
1. 第一层（已有的）：依赖窗口是不是常数。圈出转移方程右边的下标，k = max(i - 被依赖下标)。前缀积 P[i+1] = P[i] * nums[i]，k = 1 → 那一侧可以是标量。这一层 238 和 42 都过。
2. 第二层（新的）：两侧方向相反时，有没有一块白送的 O(n) 暂存。方向相反 ⇒ 一个循环装不下 ⇒ 必须拆两趟 ⇒ 第一趟的 n 个结果得存在某处等第二趟来合并。
