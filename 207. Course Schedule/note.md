## framework

这类事更复杂的graph，需要自己建grpah自己找起点，后面的非简单grid graph都这样吗？

基本是，但不全是。按两个问题归类：**图怎么给你的**、**从哪开始搜**。

### 图怎么给你的

| 形式 | 要做什么 | 例子 |
|---|---|---|
| 已经是节点对象 | 不用建，顺着指针走 | [133](../133.%20Clone%20Graph/note.md) |

| 边列表 | **自己建邻接表** | 207、210、261、323、743、787 |
| 完全隐式，节点是「状态」 | 自己定义节点和边 | 127 Word Ladder(单词是节点，差一个字母连边)、269 Alien Dictionary(相邻单词比较出边) |

越往下越难，难点从「怎么遍历」变成「**怎么建模**」。遍历本身还是 BFS / DFS 那两个骨架。

边列表建图是固定写法：

```python
graph = [[] for _ in range(n)]
for a, b in edges:
    graph[a].append(b)
    graph[b].append(a)   # 无向图才加这行
```

分清**有向 / 无向**：207 有向，261、323 无向。无向图每条边天然是个环，一定要 visited(133 那个坑)。

### 从哪开始搜

| 起点 | 例子 |
|---|---|
| 题目给了 | 127(beginWord)、743(源点 k) |

### 还有一类不用遍历：并查集

684、323、261 都能用并查集，不建邻接表也不 BFS，一条边一条边合并。
擅长「两点连没连通」「加这条边会不会成环」。

### 总结

> 非 grid 的图题模板都差不多，活在建模上：
> 1. 节点是什么、边是什么、有向还是无向
> 2. 起点从哪来：题目给 / 多源 / 外层循环
> 3. 用什么：只问能不能到 → BFS/DFS 都行；问最少几步 → BFS；问连通 / 成环 → 也可以并查集

plan 里剩下的：210 = 207 + 输出顺序；261、323 = 无向图 + 外层循环或并查集；684 = 并查集；127 最难，难在建模。

## 讨论：拓扑排序是啥，跟我写的 BFS 什么关系

> 我们用的算法是 bfs 的变体，需要找起点，但是 agent 说有啥拓扑排序，是这个吗，还是有别的写法

是同一个东西。**拓扑排序是问题的名字**：给一张有向图，排出一个顺序，让每条边 `u → v` 里 u 都在 v 前面。
只有**无环**的有向图排得出来，所以「能不能排出来」⇔「有没有环」—— 207 问的正是这个。

上面写的「从入度 0 出发的 BFS」是求拓扑排序的第一种经典算法，叫 **Kahn 算法**。另一种基于 DFS。

### 两种写法

| | Kahn(BFS，上面写的) | DFS 三色标记 |
|---|---|---|
| 思路 | 不断拿走入度为 0 的点 | 一路走到底，看会不会走回**当前路径**上的点 |
| 怎么判环 | 最后拿走的点数 < n | DFS 中遇到「正在访问中」的点 |
| 拓扑序 | 出队顺序 | **后序**反过来 |
| 需要什么 | 入度数组 + 队列 | 每个点一个状态：0 没访问 / 1 在当前路径上 / 2 已搜完 |

### DFS 版为什么要三种状态，只用 visited 不行

普通 visited 只分「来过 / 没来过」。但有向图里**来过 ≠ 有环**：

```
0 → 1 → 2
0 → 2
```

从 0 出发先走 `0→1→2`，2 搜完。回到 0 再走 `0→2`，又碰到 2 —— 来过，但没有环。

所以「来过」要拆成两种：
- **1 在当前路径上**：又碰到它 = 绕回来了 → **有环**
- **2 已搜完**：这条路之前验证过没问题 → 直接跳过

> 无向图只要 visited 就够(见 [133](../133.%20Clone%20Graph/note.md))；有向图判环才需要把「来过」拆成「在路上」和「搜完了」。

### 学哪个

- **Kahn 练熟**：直观、不爆递归，210 要输出顺序时出队顺序直接就是答案
- **DFS 三色知道原理**：面试官追问「还有别的写法吗」时，能讲清三种状态的区别就够

所以拓扑排序就是given一个图，但不知道从哪里开始遍历，找到全部的起点，保证一定能遍历的这个前提对吗？
### 追问：拓扑排序 = 找到全部起点、保证能遍历？

> 所以拓扑排序就是given一个图，但不知道从哪里开始遍历，找到全部的起点，保证一定能遍历的这个前提对吗？

不对，这是把 Kahn 的**实现细节**当成了拓扑排序的**定义**。

- 拓扑排序关心的是**先后顺序**(每条 `u → v` 里 u 在前)，不是「怎么把图走遍」
- 「找所有入度 0 的点」只是 Kahn 的第一步，而且**不保证走遍** —— 有环时环上的点永远走不到，207 判环靠的就是这个

### 真正的区别：OR vs AND

跟 [417](../417.%20Pacific%20Atlantic%20Water%20Flow/note.md) 的普通多源 BFS 对比：

| | 417(普通多源 BFS) | 207(Kahn) |
|---|---|---|
| 一个点什么时候能入队 | **任意一个**邻居走到它(OR) | **所有**前置都处理完(AND) |
| 用什么判断 | `seen`：来过没有 | 入度计数：还差几个前置 |
| 比喻 | 水只要有一条路能流过来 | 课要**所有**先修课都修完 |

入度数组不是用来「找起点」的，是**给每个点计数：还差几个前置没完成**。
起点只是一开始计数就为 0 的点；之后每个点都要等自己的计数降到 0 才能入队。

> 普通 BFS：有**一个**邻居到了我，我就能走(OR，用 visited)；
> 拓扑排序：**所有**前置都完成了，我才能走(AND，用入度计数)。
> 从入度 0 出发只是 AND 规则的自然结果，不是拓扑排序的定义。
