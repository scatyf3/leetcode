### 形状 1 的第一版错在哪

写出来的第一版 1318/N 组错（AB 两字母 n≤8 全枚举），不是 edge case 是结构性的：

```
s='A'     k=2  → 0   (期望 1)   ← 最小反例
s='AB'    k=5  → 0   (期望 2)
s='ABBB'  k=0  → 2   (期望 3)
s=''      k=1  → ValueError
```

**一个根因**：`max(cnt.values())` 在空 Counter 上抛 ValueError。为绕开它打了两个补丁，两个补丁各漏一个 bug：

1. `r=k` + `cnt=Counter(s[:k])`（"刚开始肯定 valid"）。**k 是预算，r 是下标，量纲不同。**
   `k > len(s)` 时 r 一上来就越界，外层一次都不进。而且这个 seed 本来就不必要，内层自己会扩到那儿。
2. `if k==0: cur_max=0`。它在**每个外层迭代开头**都生效，不只第一次。
   入口判断退化成 `r <= l`，窗口一非空就进不去内层。`ABBB, k=0` 死在这儿。

`max(cnt.values(), default=0)` 一行同时干掉两个补丁。

### l 和 r 在两版里的区别

`r` 六条全不同，`l` 只有语义相同：

| `r` | sol2（形状 2） | sol3（形状 1） |
|---|---|---|
| 指什么 | **元素**（刚纳入的字符下标） | **缝**（下一个待纳入的位置） |
| cnt 覆盖 | 闭区间 `[l, r]`，含 r | 半开 `[l, r)`，不含 r |
| 谁驱动 | `for`，无条件每轮 +1 | 内层 `while`，有预算才推 |
| 一轮动几格 | 恒定 1 格 | 0 格或多格 |
| 取值范围 | `[0, n-1]`，永不越界 | `[0, n+1]`，**会空推到 n+1** |
| 结算时指向 | 最后一个**合法**元素 | 第一个**非法**位置（或 n+1） |

| `l` | sol2 | sol3 |
|---|---|---|
| 指什么 | 窗口最左元素下标 | **完全一样** ← 唯一没有分歧的量 |
| 什么时候动 | **有条件**，只在窗口非法时 | **无条件**，每个外层迭代必动 |
| 一轮动几格 | 0 到多格 | 恒定 1 格 |
| 动的目的 | **修复**（缩回合法） | **换题**（换下一个左端点重问） |
| 总移动 | 按需 | 全量，一直走到 n |

长度公式的 ±1 就是 r 那三条推出来的，不是试出来的：

```
sol2: r-l+1    闭区间, r 本身算在内
sol3: r-l-1    半开是 r-l, 但停在第一个非法处, 再退一格
```

还有一条最容易错的：**sol3 里 cnt 覆盖的 `[l,r)` 和结算对象 `[l,r-1)` 不是同一段**；sol2 里这两者永远相同。

### 一句话收束

两版把「无条件」和「有条件」分给了不同的指针：

```
sol2: r 无条件推进(for)   + l 有条件修复(while)
sol3: l 无条件推进(while) + r 有条件扩张(while)
```

外层循环变量就是无条件动的那个 = 主角，内层那个负责擦屁股。于是：

> **探索性操作必须多走一步才知道停，所以谁负责探索，谁就带一格误差。**

sol3 让 r（探索）当配角，误差落在 r 上 → cnt 多含一格 → `-1`，外加 `if r<n` 那个空推
（撞边界时没有元素可多含，只能假装多走一步，好让 `-1` 对两条退出路径都成立）。
sol2 让 l（确定性的移除）当配角，误差就没了。这正是 pass2「加入是探索性的，移除是确定性的」落到指针上的样子。

### 代价与收益，实测

- **性能没差别**：35735 字符 / 5 字母表，sol2 的 `max()` 调用 64647 次，sol3 65247 次。同一个算法。
- **代价**：sol2 零特判；sol3 三个（`default=0`、`if r<n`、`l<n`）。空串 sol2 靠初始状态自动对，sol3 必须加守卫。
- **收益**：只有「按左端点索引的数组免费」这一点人体工学。**净亏。**

### 更正：pass2 决策表第 2 条是错的

原来写的是「答案是数组 → 形状 1」，理由是 sol3 能返回「以每个 i 开头的最长合法窗口」而 sol2 不能。
**后半句不成立**，sol2 加一行就能吐出同一个数组（对拍 5000 组零错）：

```python
while (r-l+1) - max(cnt.values()) > k:
    ans[l] = r - l            # ← [l,r] 非法 ⇒ 以 l 开头最长是 [l,r-1]
    cnt[s[l]] -= 1; l += 1
for v in range(l, n): ans[v] = n - v      # 收尾
```

根子上是因为**两个形状走的是同一条单调阶梯**：

```
f(l) = 使 [l,r] 合法的最大 r      g(r) = 使 [l,r] 合法的最小 l
```

两者都单调不减、互为逆函数，**知道一个等于知道另一个**。O(n) 就是走完这条阶梯的代价——
两个形状都走完了整条，所以不只复杂度相同，**信息量也相同**，能回答的问题就相同。

差别只在哪个方向的数组**顺手**：

| | 按 r 索引（以 r 结尾） | 按 l 索引（以 l 开头） |
|---|---|---|
| 形状 2 | **免费**，结算那行 `r-l+1` 就是 | 多两笔 |
| 形状 1 | 多两笔 | **免费**，结算那行 `r-l-1` 就是 |

人体工学差异，不是能力差异。所以形状 1 真正不可替代的只剩两条：
**state 删不掉**、**删除很贵**（这两条未验证）。**答案卡/默认写法认 sol2。**


## pass2

我们知道要双指针，要维护counter，然而为什么枚举r，收缩l呢，通常来讲都是枚举l，再向前推进r。

两种写法本质上一样，但「枚举r，收缩l」更好，因为
1. 加入是"探索性"的，移除是"确定性"的 ← 最核心。你必须先把 s[r] 加进 counter，才知道窗口坏没坏。而移除 s[l] 永远不会把合法窗口变成非法。所以自然的结构是：无条件做那个确定的事（推进 r），发现坏了再修复（收缩 l）。
2. 模版好。`for r: add(r); while bad: remove(l++); update(ans)` 这一个骨架同时覆盖最长 / 最短 / 计数三类，只有 bad 的定义和 update 的位置在变。而枚举 l 的写法，r 到头时要 break、答案更新时机在 while 之后，三类题的形状各不相同。

以及内层while 里max(cnt.values()) 不带来额外复杂性，因为cnt是const，怪，但在算法题的语境里确实.

### 写法

有两个写法，然而里面有两个写法
1. 外层循环肯定iterate left boundary, while valid，继续扩有边界
2. 外层循环肯定iterate right boundary,while not valid，l默认为0，缩左边界

这里写法取舍是啥，很直觉的双指针是1，然而1有好多edgecase和+-1，写2更简略，怎么判断写2更简略？
判据是循环退出后的后置条件，是不是一个单一命题。
1. case 1 退出时是第一个invalid
2. case 2 退出时是第一个valid

形状 2 退出后你确切知道窗口是合法的，所以结算就是 r - l + 1，不加不减。形状 1 退出后你不知道是哪种情况停的 —— 而这两种情况的结算方式不一样（多扩一格 vs 没多扩）。你上一版那个 -1 就死在这儿：它默认了「一定是 valid 失败停的」，遇到 AAAA 撞边界停的就削错了。

case2 的不变式只有一句：「结算的那一刻，窗口 [l, r] 一定合法」
