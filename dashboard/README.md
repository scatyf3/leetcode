# LeetCode 看板

本地看板，单页，只管**追进度**。首屏一排四个数：下个里程碑 n/N · 超前/落后 · 本周额度 · 今日复习（点它开始复习），
下面是里程碑轴和「计划 vs 实际」折线；其余（题目 / 攻坚 · Mock / 专题 / 覆盖）折起来。
点题卡打开详情：左边 `*.py` 解法，右边可编辑的笔记（保存回磁盘）。

页面上不放说明文字 —— 口径 / 定义都在悬停提示（`title`）和下面这份 README 里。

后端是纯 Python 标准库，**零依赖、无需 pip 安装**；前端是 Vite + Vue 3 + TypeScript 工程
（`dashboard/web/`，结构照着 [ai-infra-inferview](https://github.com/scatyf3/ai-infra-inferview)），
需要 Node 22+ 构建一次。

## 运行

```bash
npm install          # 仓库根目录, 第一次 / package.json 变了之后
npm run build        # -> dashboard/web/dist/ (gitignore)
python dashboard/server.py
```

然后打开 http://localhost:8765 （Ctrl+C 停止）。server.py 伺候的是 `dashboard/web/dist/` 里的产物，
**改了前端要重新 `npm run build`**（或者用下面的热更新）。没构建过的话首页会提示你先构建，API 照常可用。

改前端时：

```bash
python dashboard/server.py   # 一个终端: API
npm run dev                  # 另一个终端: http://localhost:5173, 热更新, /api 自动代理到 8765
npm test                     # lib/ 下纯函数的单测 (vitest)
npm run typecheck            # vue-tsc
```

## 架构

```
每题文件夹/
  meta.json      ← 标签的真相源（git 追踪）：structures / paradigms / techniques / difficulty / status / familiarity
                   还有 complexity（时间/空间）和 fsrs（下次到期日 / stability …）
  answer.md      ← 复习答案卡：**一句话思路**。和 note.md 分开——note 是过程流水账，这个是压缩过的结论
  *.py           ← 解法（面板里按文件名分 tab 展示）
  note.md 等     ← 笔记（面板右侧可编辑，Ctrl+S 保存）

structures/<结构>.md   ← 该数据结构的通用 trick(点「题目」里的组标题打开)
paradigms/<范式>.md    ← 该算法范式的通用 trick(同上, 看 plan.json 里组挂的是哪份)
notes/*.md             ← 跨题笔记 + scratch.md 随想收件箱(右上角 📓 笔记)

syntax/<主题>.md       ← **语法牌组**的卡片(一个 ## 一张卡, `---` 上下分正反面)
syntax/state.json      ← 语法卡的 FSRS 调度状态(按卡 id 索引, git 追踪)

dashboard/
  server.py      ← 标准库 http + sqlite 索引 + API
  scaffold.py    ← 题号/题名 → 抓题面 + 建空题目文件夹（TODO 加条目时自动调）
  fetch_desc.py  ← 批量补抓已有文件夹的 problem.html
  web/           ← 前端 (Vite 工程, 配置在仓库根目录 vite.config.ts / package.json)
    index.html               ← 页面骨架 + 首帧前落定深浅色的那段内联脚本
    src/main.ts              ← 入口: 字体 + 样式 + 主题开关 + app.js
    src/app.js               ← 看板的手写 DOM 部分(首页 / 各个 overlay)
    src/components/ReviewPanel.vue ← 🧠 复习面板
    src/lib/*.ts             ← 纯计算(熟练度阶梯 / 排队 / 选择题 / 时间轴 / markdown / 高亮), 有单测
    src/styles.css           ← 全部样式; 最上面一块是设计 token(VitePress 配色), 换主题只改那里
    public/static-shim.js + ro.css ← 只读静态站专用, 只有 export_static.py 会把它们挂进 index.html
    src/sync.ts + components/SyncControl.vue ← 只读站的复习同步(☁), 见[手机上复习](#手机上复习同步)
  fsrs.py        ← FSRS-6 调度算法（移植自 py-fsrs，纯标准库；`--selftest` 可自查）
  inbox.py       ← 手机上的复习记录: 拉 data 分支 → 落回 meta.json / reviews.jsonl（server 启动和 ↻ Sync 时自动跑）
  sync-applied.jsonl ← 落过的手机事件账本（按 eid 去重），git 追踪
  backfill_edits.py ← 从 git 历史回填 edits.jsonl（时间轴开写之前那一截）
  syntax.py      ← 语法牌组: 解析 syntax/*.md + 调度 + 就地改背面
  reviews.jsonl  ← 每次复习评分追加一行（**两个牌组共用**，靠 `deck` 字段区分），git 追踪
  edits.jsonl    ← 每次改标签/难度/状态/熟练度追加一行（只记 diff），git 追踪，给「标签什么时候长出来的」时间轴用
  attempts.jsonl ← 每次「＋ 做了一遍」打卡追加一行（**动作**，不是成绩），git 追踪，日课那两半靠它
  data.db        ← SQLite 索引，由 meta.json 重建，已 gitignore
  plan.json      ← 坐标系视图的分层 + 时间线（手改）
  .lc_index.json ← LeetCode 全量题目清单缓存（题号→slug），一周重抓，已 gitignore
```

- **真相在 `meta.json`**：删掉 `data.db` 也不丢标签，`↻ Sync` 会从各文件夹重建索引。
- **新增题目**：右上角 `📋 TODO` 里输入**题号或题名**回车（`105` / `word break`）→ 自动去 LeetCode 抓题面，建好
  `<编号>. <标题>/`（`problem.html` + 空 `sol.py` + `note.md` + `meta.json`，`status: todo`）并直接进看板表。
  离线或抓失败时 todo 照记，只是没建文件夹。命令行等价物：`python dashboard/scaffold.py 105 "word break"`。
  手工建文件夹放解法也行 → 点面板右上角 `↻ Sync` → 它会出现在「未完全打标签」区，点进去填标签即可。
- **新增/修改解法**：详情页左边代码区，**双击进入编辑**、`Ctrl+S` 保存、`Esc` 或点开退出（和右边笔记一套交互）。
  tab 条最后的 `+ 新解法` 输入文件名（不写 `.py` 会自动补）新建一个。
  文件名只收 `.py`，带路径成分的一律拒绝；**名字打一半点开不会留下空文件**——要保存过才落盘。
  题面 tab（`📄 题目`）是只读的。删文件仍然只能在文件系统里做。

## 熟练度 familiarity

`meta.json` 里的 `familiarity`，`0`–`4`（**`0` 是最熟的一档**），缺这个键 = 未评：

| 值 | 含义 | 该怎么处理 |
|----|------|-----------|
| 0 | 英语讲得清 | 面试门槛。60 秒讲清思路与复杂度 |
| 1 | 已经熟悉 | 只做间隔重刷，别再花时间。**只有盲写一次过、且写的是最优解才升到这档** |
| 1.5 | 写得对，但不是最优解 | 半档。能较熟练地盲写出一个过 OJ 的解，但复杂度不是最优（比如该 O(n) 写成了 O(n log n)、该 O(1) 空间用了 O(n)）。**OA 够用，面试不够**——补的不是「会不会写」而是「知不知道更好的那个」，去看 note 里的最优解那一节 |
| 2 | 思路会，细节容易写错 | 别重看题解，**盲写一遍**，对着 note 里的 bug 清单查 |
| 3 | 思路大概知道，不熟 | 先复述思路再写；写不出来说明卡在「怎么想到」那一步 |
| 3.5 | 方向对，但只是直觉 | 半档。说得出「大概往哪个方向想」，但严谨不起来 —— 补不出不变式、说不清为什么这么贪心/这么转移。**不算 S1**（那一栏叫「思路清楚」，直觉不算清楚）。要做的是把直觉写成一句能证伪的话，写不出来就去看题解的论证那一段 |
| 4 | 思路都不知道 | 当新题重做，做完补 note |

> **熟练度和 🧠 复习是两套独立的东西。** `familiarity` 是你手工维护的**掌握档位**（决定看板颜色、
> 过滤、题单进度条）；FSRS 只管**什么时候再问一次**。复习时评分**不会**去改 `familiarity` ——
> 因为 L1 的定义是「盲写一次过」，而复习模式只想思路不写代码，成功回忆不足以证明能盲写。
> 觉得某道题该升降档，还是自己去改。

题卡左边的方块是熟练度，右边的圆点是难度 —— **两个不是一回事**，简单题也可以不熟。
点方块循环改熟练度；详情页「熟练度」下拉改完也即存回 `meta.json`。

## 🧠 复习（FSRS）

右上角 `🧠 复习`，徽章上的数字 = 今天该复习几张（**两个牌组加起来**，鼠标停上去看拆分）。

面板左上角切牌组：

| 牌组 | 问什么 | 真相在哪 |
|---|---|---|
| **题目** | 看题面 → 这题用什么结构 / 什么范式 | 各题文件夹的 `meta.json` + `answer.md` |
| **语法** | 看一段有坑的代码或一句语义 → 该用哪个 API / 错在哪 | `syntax/*.md` + `syntax/state.json` |

两组**只共用调度器**（`fsrs.py`）**和历史**（`reviews.jsonl`），排队规则各写各的 ——
语法卡没有 `status` 也没有 `familiarity`，硬套题目那套会得到一个全靠 `undefined` 参与排序的随机顺序。
**换牌组 = 重开一轮**（`done` / `total` 清零）：两组的 id 空间不一样（题号是整数，
语法卡是 `主题/标题` 字符串），混进同一个队列会拿着题号去语法卡里找。

下面这一整节讲的都是**题目牌组**；语法牌组见 [语法牌组](#语法牌组)。

一道题的流程：**看题面 → 在心里说清「用什么结构 / 什么范式 / 触发条件是什么」→ `空格` 揭晓
答案卡 → `1`-`4` 自评**。不写代码 —— 这一步测的是**能不能被检索出来**，不是能不能 AC
（对应 [notes/practice-loop.md](../notes/practice-loop.md) 里的第 3 道）。

揭晓**之前**，题面下面有两道选择题（思路 / 复杂度），选不选都行 —— 直接按空格也能揭晓，
选了的话揭晓时会标出对错。干扰项是**这道题上似是而非的错解法**（多半是邻近题目的正确解法），
测的是「该用哪个模板」的辨别力，不是排除废话的能力。

> 选择题是**再认**，比**再现**容易。所以它只是个额外的自检，真正的复习动作还是「先在心里把
> 思路说出来」—— 别看到选项就直接挑。

右下角 `↓ 押到队尾`（快捷键 `0`，揭晓前后都能按）：把这道题挪到**本次会话**的最后再问一遍。
**不评分、不写 `reviews.jsonl`、不动 `due`、不算进度**，纯粹是「现在没空细看，等会儿再说」。
和评 `1` 的区别在这儿 —— 评 `1` 是真的记一次「忘了」，会拉低这道题的 stability；
想留着慢慢啃的难题走这个入口，别拿评分当暂存。已经是本轮最后一道时按钮会置灰。
押过的记录存在 `session.json` 的 `defers` 里（按牌组分开、只认今天），所以**关掉面板 / 刷新页面再打开，
押过的题仍然排在队尾**，见下面[队列快照](#队列快照-dashboardsessionjson)。

旁边的 `⏸ 暂停` 是「这阵子都别问」：不评分，这道题从此不进复习队列（徽章也不数），直到在详情页取消勾选
「暂停复习」。`meta.json` 里记成 `"paused": "开始暂停的日期"`。**interval 一起冻住**：恢复时服务端把
`fsrs.due` 和 `fsrs.last_review` 一起往后推停掉的天数（`server.set_paused`），回来时不是一片逾期，
下次评分的 `elapsed_days` 也不含暂停那段。只推 `due` 不够 —— FSRS 会以为你隔了很久还记得，高估 stability。
看板上暂停的行变淡、标题前带 ⏸；每次暂停 / 恢复在 `edits.jsonl` 里记一行 `field: "paused"`。
顶栏的 **⏸ 暂停** 浮层列出所有暂停中的题（停得最久的在上，带停了几天），每行一个「恢复」；上面输题号回车就暂停那道。

揭晓后最先看到的是**答案卡**，三样东西正好对应你该说清的三件事：

| | 存在哪 |
|---|---|
| 结构 / 范式标签 | `meta.json`（本来就有） |
| 时间 / 空间复杂度 | `meta.json` 的 `complexity` |
| 自然语言思路 | 题目文件夹里的 `answer.md` |

选择题的选项存在 `meta.json` 的 `quiz` 字段：`{"idea": "正确的一句话", "wrong": [三个干扰项]}`。
一句话里塞了两个考点的题可以**拆成几步问**：顶层加 `"q"` 当题干，再用 `"then": [{"q", "idea", "wrong"}, ...]`
接着问（例：133 先问「DFS 还是 BFS」，再问「哈希表怎么用」）。不写 `q` 的第一问题干默认是「思路是哪个？」。
`idea` 写成**数组**就是多选（题干自动加「（多选）」），要恰好选中全部正确项才算对，漏选的揭晓时标虚线「✓漏」。
留给「两种说法是一回事」的题（例：139 图的可达性 = 一维 DP）—— 别用单选配一个「两者都行」，
做多了会发现"都行"那项总是对的。选项总数至多 4 个，`wrong` 超出的部分截掉。
复杂度那题的干扰项**不用手写** —— 从全库出现过的复杂度里按出现频次抽（抽常见的才容易混）。
写干扰项时注意**长度要和正确项差不多**，否则「选最长的」就能蒙对。
干扰项必须**真的是错的**：另一种也能 AC 的写法不能拿来当干扰项，也不能当正确项。
每类题只认自己平时写的那一套，比如二分只写闭区间 `[l, r]`（见 `paradigms/binary-search.md`），
半开区间 `[l, r)` 不出现在任何选项里。好的干扰项是那套写法里**真实踩过的坑**（例：35 的「没找到返回 mid」）。

完整的 `note.md` 和各个解法退成下面的次要 tab —— 想深挖再点。

**答案卡可以就地改**：揭晓后点右上角「改一下」（或双击思路区），`Ctrl+S` 存、`Esc` 取消。
刚回忆完的那一刻脑子最热，此时把它压缩成一句话最准。

**给 agent 的批注**：卡本身有毛病、又不是一句话能当场改完的（干扰项其实也能 AC、答案卡和 note 对不上、
语法卡背面漏了一种情况……），按 `c` 或右下角 `💬 批注` 记一句，`Ctrl+Enter` 存，`Esc` 收起（草稿留着，换卡才清）。
**两个牌组都能批，揭晓前后都能批**，不评分、不动调度。攒够了跟 agent 说一句「处理卡片批注」，
它按 `.claude/skills/card-comments/SKILL.md` 把所有待改的一次清掉。

- 存在 `dashboard/card-comments.jsonl`（git 追踪，不导出到只读站），一条批注一行，两个牌组共用，靠 `deck` 区分。
  线上站连上 GitHub 后也能批，经 `data` 分支回来（见[手机上复习](#手机上复习同步)），那边只看得到自己还没落盘的几条。
  是一个集中文件而不是 `meta.json` 里的字段：语法卡没有 per-card 的 meta，而 agent 第一步就是「找出所有没处理的」。
- 处理完**不删**，改成 `done` / `skip` 并带一句 `reply`。卡上的批注区会显示状态和回复 ——
  **揭晓后才显示内容**，揭晓前只报条数，因为批注和回复多半会提到正确答案。
- 还没处理的可以点「撤回」；处理过的撤不回（那是改卡的记录）。
- 命令行：`python dashboard/card_comments.py` 列待处理的，`done <cid> "回复"` / `skip <cid> "回复"` / `reopen <cid>` 改状态。

| 键 | 作用 |
|----|------|
| `空格` | 显示答案（揭晓后不响应，防手滑跳过不评分） |
| `1` `2` `3` `4` | 忘了 / 勉强 / 想起来了 / 很熟 —— 按钮上直接标着各自的下次间隔 |
| `c` | 给 agent 写批注（框里 `Ctrl+Enter` 存，`Esc` 收起） |
| `Esc` | 退出 |

- **算法**：FSRS-6，`dashboard/fsrs.py`，逐函数移植自
  [py-fsrs](https://github.com/open-spaced-repetition/py-fsrs)，跑 937 步对拍与上游逐位一致。
  想换参数就放一个 `dashboard/fsrs_params.json`（`{"w": [...21 个], "retention": 0.9}`），
  没有这个文件就用官方默认值。
- **粒度是「天」**，不做 Anki 那种「10 分钟后再问一次」。评 `1`（忘了）时 FSRS 给的下次到期
  仍然至少是明天，但这道题会**排回本次会话的队尾**，今天还会再问你一遍。
  关掉重开也不丢：开面板时会从 `reviews.jsonl` 里找出**今天最后一次评分是 1** 的题追加到队尾
  （评 1 之后重问又评了 2+ 的就不再回来）。注意首页徽章只数到期的，不含这些。
- **哪些题会进队列**：`status` 是 `solved` / `review` 的。`todo` 不进——没想出来过的思路谈不上复习。
  第一次打开时所有符合条件的题会一次性入队，之后 FSRS 自然把它们摊到不同日期；
  没到期的题不会出现。新卡按熟练度从生到熟排（L4 先来）。
- **队列顺序有三档**（复习面板右上角切换，选择记在浏览器 localStorage 里，下次还是它）：
  `到期优先`（默认，到期的按到期日 → 新卡按熟练度从生到熟）、`顺序`、`随机`。
  「顺序」在题目牌组是**题号升序**，在语法牌组是**文件里的书写顺序**（同一个文件里相关的卡
  挨着问，正好横向对照）。三档的**范围完全一样**，只换顺序；中途切换只重排**还没问到的**那些，
  当前这张和 `n / N` 进度不受影响。
- **状态存在各题的 `meta.json` 里**（`fsrs` 字段），所以 git 能看到复习历史，删掉 `data.db` 也不丢。
  代价是每天刷完会脏十几个 `meta.json`——这是有意的。
- **每次评分往 `dashboard/reviews.jsonl` 追一行**，记的是**评分前**的状态 + 这次的评分，
  外加一个 `deck` 字段区分牌组（**老记录没有这个字段 = 题目牌组**，没有回填，也不需要）。
  正好是 FSRS 优化器要的格式。
- 只读的线上站没有写接口，复习模式会退化成**纯自测**：题面 → 空格 → 答案 → 「下一题」，不记录进度。
  **连上 GitHub token 之后**可以照常评分 / 暂停 / 批注，记录经 `data` 分支回到本机，见[手机上复习](#手机上复习同步)。

自查算法有没有移植错：

```bash
python dashboard/fsrs.py --selftest
```

## 语法牌组

回答的问题是：**同一个语法坑，别栽第三次。**

和题目牌组正交 —— 那个测「这题该用哪个模板」，这个测「写的时候手会不会抖」。
卡片写在 `syntax/<主题>.md`，一个文件一个主题：

````markdown
# Python str 语法坑
第一个 `##` 之前的一切都是前言，不是卡。

## 判回文的预处理，这段有什么问题
```python
s = "".join(c for c in s.lower() if c.isalpha())
return s == s[::-1]
```
---
`isalpha()` 漏掉数字。"0P" 会被洗成 "p" → 误判 True，该用 `isalnum()`。
栽过：125
````

- 每个 `##` 是一张卡，**卡标题就是问题的一部分**（揭晓前它一直显示在最上面）。
- 卡里那行单独的 `---` 上面是正面、下面是背面。**没写 `---` 就整段算背面**，
  正面只剩标题 —— 「想判断字符是字母或数字，用哪个方法」那种一句话卡可以这么偷懒。
- 代码块里的 `---` 和 `##` 不算数（贴 diff、贴带 `##` 注释的代码都不会把卡切碎）。
- 卡 id = `<文件名>/<卡标题>`。⚠️ **改卡标题 = 换了个 id**，那张卡的复习历史会断掉
  （旧状态留在 `state.json` 里成为孤儿，不删 —— 历史不该被悄悄抹掉）。想改措辞就改正反面。

**同一个文件有两种读法**：在看板里按 FSRS 抽卡，或者直接打开 `.md` 从头通读当 checklist
（写字符串题之前扫一眼）。这是选这个格式而不是一卡一文件/一个大 JSON 的主要理由 ——
[notes/off-by-one-checklist.md](../notes/off-by-one-checklist.md) 已经证明通读形态有用，
不该为了抽卡把它拆散。

**收录标准：只收自己真栽过的。** 抄一本 Python 教程进来这个文件就废了 ——
它值钱的地方是「这些坑我确实踩过」。每条末尾记一下哪道题栽的；
同一条在 ≥3 道题里重犯，说明它是真的记忆问题，值得多抽几次。

**为什么内容和调度状态分开存**（题目那边是合在一个 `meta.json` 里的）：
卡片文件是手写手读的，每张卡底下插一坨 FSRS 数字就没法通读了。题目那边没这个矛盾，
`meta.json` 本来就是机器文件。代价是刷完会脏 `syntax/state.json` 一个文件（题目那边是脏十几个）。

揭晓后点「改一下」能**就地改背面**，`Ctrl+S` 存回 `.md`。写法是**按行区间原样替换**，
不是「解析成结构再序列化回去」—— 后者会顺手重排空行、统一列表符号，把手写的排版洗一遍。

### 掌握度时间轴

  绕过面板直接手改 `meta.json` 不会被记进日志，只会让更早的那几天偏一点，不会整条线漂掉。

```bash
python dashboard/backfill_edits.py --write  # 真写
```

只保留服务器实时写的那些。代价是粒度只到 commit（时间戳是 commit 时间，一个 commit 一堆题）。

## 首页

回答的问题是：**离下个里程碑还差几题、这周该做的做了没、今天还剩几张复习。**

顶栏副标题是当前阶段（`阶段 2 · 补第一层 · 剩 23 天`，悬停看这段的投入 / 目标 / 说明），右边是全库 S2 数。

首屏（其余全折起来，展开状态记在 localStorage 的 `lc-grid-folds`）：

1. **KPI 一排四格**
   - **下个里程碑**：每条链（主线、Hot 100 冲刺……）各一行，报它日期没过、还没达标的下一个点：n/N + 剩几天。
   - **超前 / 落后**：[配速](#配速计划-vs-实际)图上选中那条链（默认离今天最近的里程碑所在的链）今天的差额，按这一段斜率折成天；落后时还写出到下个里程碑要几题/天。
   - **本周**：[本周额度](#本周额度)三条迷你进度条（复习重做 / 新题 / 攻坚），悬停看巩固数。
   - **今日复习**：两个牌组今天还能刷几张（到期数和每日上限取小）；**点它直接开复习面板**。刷完变 ✓ —— 就是原来的「最低日」。
2. **里程碑** —— 一条时间轴：阶段是底色色段（悬停看这段的目标和说明），`plan.milestones` 是轴上的菱形，
   今天是一根竖线；轴下面每个里程碑一行（日期 · 进度条 · n/N · 剩几天，悬停看焦点和口径）。
   琥珀色的是「现在对的那个」，过了日期没到数的标红。
3. **计划 vs 实际** —— [配速](#配速计划-vs-实际)折线；下面列今天打过卡的题。

折叠区：**题目**（按 pattern 分组的题卡，见下）· **攻坚 · Mock** · **专题** · **覆盖**（格子 + 账本）。
格子里点层标签会自动展开题目区再跳。

两个轴：

| 轴 | 取值 | 含义 |
|----|------|------|
| 深度（列） | S1 / S2 / S3 | 思路清楚 → 写得对 → 英语讲得清。S1→S2 是 OA 门槛，S2→S3 是面试门槛 |
| | | **不单独记** —— 由每题的熟练度 `familiarity` (L0–L4，含半档 L1.5 / L3.5) 算出来，见下 |
| 覆盖（行） | 第一/二/三层 | 题单铺到 ≈75 / ≈110 / ≈150 题 |

- 每题只有**一个**原始标记：`meta.json` 里的 `familiarity`（详情页那个「熟练度」下拉）。S1/S2 是算出来的。

- **深度轴累计**：每格 = 该层里达到该级**及以上**的题数。S3 的题同时计进 S1/S2 列，反过来不成立。
  这才对得上「S2 是 OA 门槛」的读法 —— 问「能过 OA 的有几题」，答案得把讲得清的那些也算上。
- **覆盖轴不累计**：每题只属于一层，第二层那行的分母是它自己的 33 题，不是 110。
  `累计 110` 说的是「题单铺到这一层时总共 110 题」，是计划规模，不是那一行的分母。
- **琥珀格 +「现在」角标** = 当前阶段该站的格子，跟着日期自己走；过去阶段的目标格降成灰徽章。
- 底下按 pattern group 列题。方块里写的是**原始的 L**，方块的**颜色**是算出来的 S —— 两个都看得见。
  一个 chip 上有**两个点击区**：点左边方块循环 `— → L4 → L3.5 → L3 → L2 → L1.5 → L1 → L0`（写回该题
  `meta.json`，和详情页那个下拉是同一个字段）；点右边**题号 / 题名打开详情**。
- 显示 `+` 的是**还没建文件夹**的题，点哪都是「开始这道题」：抓题面 + 建目录（和 📋 TODO 同一条路）。
  建的过程中方块变 `…`；建不出来（离线之类）方块回原样、chip 描红，原因写在 `title` 里；
  文件夹建好了但**题面没抓到**（会员题）会弹一条提示 —— 否则详情页一片空白，没人知道为什么。
  新建的题**不带** `familiarity` 键，也就是「未评」；早先这里写死 `0`，而 `0` 是阶梯顶端，
  于是每道新建的题一出生就是 L0，还直接计进 S3。
- **组标题可点** → 打开这个 pattern 的通用 trick 文档（`paradigms/*.md` 或 `structures/*.md`）。
  哪些 pattern 还没写 trick，扫一眼标题就知道。
- **层标签可点** → 跳到下面「题目」区这一层的第一组。
- **灰掉的组**（Math & Geometry / Bit Manipulation）在第三层里低优先：迁移性最低、OA 命中率最低，时间不够先砍它们。
  第三层内部的取舍顺序是 2-D DP > Advanced Graphs > Greedy > 这两组，从后往前砍。
- **每组按题单分框**。实线框是 NeetCode 150（就是 `groups[].problems`，算进度）；
  下面的虚线框是 `lists.json` 里其他题单**补的**题 —— 只放 NeetCode 150 没有的，每题全页只出现一次，
  一道题同时在 Hot 100 和 Top Interview 150 里就进排前面那个的框。虚线框**只看不计**：
  不进格子、不进组右上角的 x/y、不进目标，框头自己带一个「S1 及以上 / 框内题数」。
  题卡右边的 `B H T` 角标说这题还在哪些题单里（Blind 75 / Hot 100 / Top Interview 150），悬停看全名。
  归组靠 `plan.json` 的 `extras` 那张「题单分类 → 组名」表；对不上任何组的分类进页面最底下的「其他」组。
  表里写错组名不会报错，只会把那个分类挪进「其他」并在 console 里 warn 一行。

### 本周额度

首屏 KPI 第三格。回答的是：**这周该做的几件事做了没有。**

日课**故意不看效果**，分成互不相通的两半。分档**先问「以前碰过没有」，再看档位** ——
顺序不能反：

| 半边 | 判据 | 说明 |
|------|------|------|
| **复习重做** | 以前做过 + 打卡时 L3 / L3.5 / L4 | **做成什么样不影响这一格**，重做完更差了照样算数 |
| **新题** | 以前没打过卡，且（从没评过档 **或** 文件夹是今天才建的） | 第一次做 |
| （巩固） | 以前做过 + 打卡时 L0–L2 | 照样记一行，但**不占任何额度** |

> **两个判据都不能单独用。**
> 只看档位会漏一个大洞：今天点 `+` 建文件夹 → 做一遍 → 完全不会评成 L4 → 打卡，
> 档位是 4，于是算成「复习重做」——**新题被洗成了复习**，reward hack 只是换了个地方。
> （这不是假想：9/8 那天五次打卡里有四次就是这样，239 / 76 / 155 / 150 都是当天新建的题。）
> 反过来「有没有文件夹」也不能单独当判据：`📋 TODO` 会**提前**把空文件夹建出来，
> 加进 todo.md 那一刻就建了 —— 那些题有文件夹、没评档、也确实还没做过，它们才是真正的新题。
> 所以真正的判据是**有没有做过**，文件夹的生日只是它的一个信号。

> **为什么不接着用熟练度跃迁算。** 原来的日课只认「爬到 L2」，于是只有**升档**才得分：
> 重做一道 L4 没升上去 = 白干，诚实降档 = 倒扣。唯一的最优策略变成**挑软柿子 + 把自己评高** ——
> 恰好是刷题里最该避免的两件事，而最该做的重做因为「不出成绩」反被系统惩罚。
> 所以日课改读 `attempts.jsonl`，记的是**动作**（哪天做了哪道题、打卡当时是什么档），
> 效果一概不参与。两半互相**顶不了**：新题刷再多也补不上没重做，反过来也一样。

- **打卡入口只有一个**：题目详情页右上角的 **`＋ 做了一遍`**。一天一题只记一次，
  点第二下是撤销（手滑用，只能撤当天当题那一条）。
- **打卡故意不动 `familiarity`。** 打卡说的是「我动手了」，升不升档是另一件事 ——
  合成一个动作的话又会变成「只有做好了才算做过」，日课就退回原来那个只奖励升档的样子。
  重做完觉得该升/该降，还是自己去改那个下拉。
- **分档看的是打卡那一刻**，服务端定死一处（`server.py` 的 `attempt_state`），
  打完卡再改熟练度不回头改写这一笔。「文件夹哪天建的」读的是 `edits.jsonl` 里那条
  `exists: null → true`（`backfill_edits.py` 从 git 回填的那截也算数）。
  按钮上会先写清这一下会记进哪一半，那句预告直接来自 `/api/problems/{id}` 的
  `attempt_next` —— **前端不重算规则**，否则迟早和服务端分叉，而预告和落盘的必须是同一个答案。
- 每行还记下当时的 `born` / `seen`，日后想复盘「这一笔当初凭什么算成新题」不用再猜。
- 额度手改 `plan.json` 里 `phases[].weekly`（`{"redo": 4, "new": 6, "attack": 2}`），**按周算**（周一起），
  跟着当前阶段走。错过的不补，下周从 0 开始。（旧的 `daily` 写法已经不读了。）
- **最低日**（首屏「今日复习」那格变 ✓）：到期闪卡刷到上限（`review_cap`，每个牌组每天默认 10 张）就算这天没断。
  复习面板开队列时也按这个上限截断，逾期堆得再多也不一次清。所以顶栏 🧠 徽章（全部到期数）可能比那格大。
- **打卡后补结果**：详情页打卡后多出一行 —— `一次过 / 小 bug / 思路错` + `攻坚` 开关 + 这次踩的坑。
  结果写回 attempts.jsonl 那一行的 `result` / `attack` / `pit`，**不影响额度**，只喂弱题列表。
  标了攻坚的那一笔只算攻坚额度，不再同时算新题/重做。

### 攻坚 · Mock

折叠区「攻坚 · Mock」，覆盖之外的两个数：

- **弱题**（`/api/weak`，`server.weak_list`）：复习忘过 ≥ 2 次，或最近一次打卡不是 `clean`。
  关掉靠：之后又做一遍 clean，或挂了变体簇（meta.json 的 `cluster`）且同簇**另外两道**题 clean。
  meta.json 的 `pit` 是这题栽过的实现细节，复习揭晓时显示在答案卡下面。两者都在详情页标签栏里改。
- **Mock**（`/api/mock`，`mock.jsonl`）：从没做过的 medium 里随机抽 `plan.mock.count` 道
  （NeetCode 150 未做 + 其他题单未做，砍掉的组、会员题、`plan.topics` 里的专题题、抽过的都不抽）。
  只记 AC 和范式判断对没对，按周汇总。抽错了点「作废」，题放回池子。
- **专题**：`plan.topics`（如 Roblox OA · 实现模拟、Infra 实操），按小节列题，不计进度、mock 不抽，自己排。加新专题直接往这个数组里写。小节可带 `note`（显示在小节标题下），写这一类题的要点。
- **里程碑**：`plan.milestones`，`{date, tier, stage, n?, groups?, focus, mock}`，首屏 KPI 第一格 + 里程碑轴。每两周对一次表，落后就砍下一段的尾巴。
  - 按**题单**算的写 `list` 代替 `tier`（如 `{"date": "2026-10-09", "list": "Hot 100", "stage": 2}`）：数的是
    `lists.json` 里那份题单的全部题，没建文件夹的算「还没到 S1」。
  - `from`：这条链的起点日期（计划线从那天的实际值起步）。不写就用第一个点所在阶段的开始日 ——
    冲刺这种跨阶段的短链要自己写。
  - `short`：卡片 / KPI 上显示的短名，不写就用题单名或层名 / 组名。
  - 同口径的点自动串成一条链，几条链并行互不影响：Hot 100 冲刺（10/2–10/9）和主线（第一层 → S2 10/15）就是这样同时追的。
    冲刺的每日题单写在 `topics` 的「Hot 100 冲刺」里（一天一个小节）。

### 配速（计划 vs 实际）

首屏「计划 vs 实际」：**对着下一个里程碑，我比计划快还是慢。** 只有升档才动 —— 它天生只认结果；
认不认真做看本周额度，两个一起看才对得上。

- **口径相同的里程碑串成一条链**（同层 · 同组 · 同深度），比如「第一层 → S2」的 10/11 56 题、10/25 72 题。
  多条链时上面有 tab，默认选「现在对的那个里程碑」所在的链。
- **计划线是折线**：起点 = 链起点那天（第一个里程碑所在阶段的开始日）的实际值，不是 0，
  然后连到每个里程碑的 (日期, 目标数)。从 0 画会显示「领先十几题」，其实一天都没多做。
- y 轴也不从 0 起 —— 链上大半的题早就到了，从 0 画整条线挤在顶上一条缝里。
- 实际线由 `edits.jsonl` **逐日回放**得到，和「掌握度时间轴」同一条路 —— 没有第二份统计。
  今天那一列直接来自 `/api/problems`，往左靠每条改动的 `from` 一步步倒推。
- 差额进首屏 KPI 第二格（超前绿、落后红，按这一段的斜率折算成天；落后时写出到下一个里程碑要的节奏）。
  KPI 跟着图上选中的链走；链还没起跑（起点在未来）时换成「还差几题 · 几号起跑」。
  图上没有图例：虚线 = 计划，实线 = 实际，今天那根竖线 = 差额（悬停图看说明）。
- 历史是懒加载的：首屏先出里程碑，`/api/edits` 回来了再补这一段。

### S1 / S2 / S3 是怎么算出来的

深度轴**没有自己的存储**。真相只有一处：每题 `meta.json` 里的 `familiarity`，
也就是详情页那个「熟练度」下拉。一个字段，一条阶梯：

```
L0 英语讲得清            ──→ S3 讲得清（面试门槛）
L1 已经熟悉             ─┐
L1.5 写得对 · 非最优解    ├─→ S2 写得对（OA 门槛）
L2 思路会 · 细节易写错   ─┘
L3 思路大概知道 · 不熟   ──→ S1 思路清楚
L3.5 方向对 · 只是直觉   ─┐
L4 思路都不知道           ├─→ 还没到 S1
未评 / 还没建文件夹      ─┘
```

半档（`1.5`、`3.5`）是**故意存成小数**的。要在 L1 和 L2 中间插一档，另一条路是重新编号
（新档占 `2`，老的 2/3/4 各加一），那样每加一档就得迁移一次所有 `meta.json`，而且从此
`"familiarity": 3` 读起来不再是 L3 —— 这文件是手写手读、进 git 看 diff 的，不值当。
阶梯的语义本来就是**排序**而不是计数，小数不碍事：代码里比较档位一律用数值大小
（`depthOf` 用的是 `L <= 2` 这样的区间，不是 `L === 1 || L === 2` 的等值列举）。
唯一要绕的是 CSS —— `.f1.5` 会被读成两个类名，所以类名走 `famCls()` 转成 `f1_5`，
对象键和 `data-` 属性仍然是 `famKey()` 给的 `"1.5"`。Python 侧同理，用 `fam_num()`
而不是 `int()`：`int(1.5) == 1` 会把半档悄悄升成 L1。

因为阶梯是有序的，`S3 ⊂ S2 ⊂ S1` 由构造保证 —— 讲得清的题必然也写得对，
不可能出现「讲得出但写不对」的题混进 S2 那一列，而 S2 正是判断能不能去做 OA 的那一列。

**⚠️ `0` 是阶梯顶端，不是「未评」。** 未评 = `meta.json` 里**没有这个键**，一路传 `null`。
代码里千万别写 `Number(x) || 0` / `int(x or 0)` —— 那会把所有没评过的题静默算成最熟的一档。
读的时候走 `famOf()`（JS）/ `fam_level()`（Python），它们是唯一正确的入口。

题单 150 题里大半还没有文件夹 —— 那些题没有 `meta.json`，自动算作「还没到 S1」，正是想要的语义。

早先版本把掌握度另存在 `dashboard/progress.json`，同一件事有两个记录点，会出现
「熟练度 L2 但坐标系标了 S1」这种自相矛盾的状态；中间还短暂用过 `familiarity` + `explained`
两个字段，也是同类问题。现在只剩一个字段。

### 改计划

直接编辑 `plan.json` —— 分层、时间线、每组题都在里面，刷新页面即生效：

- `tiers` / `groups[].tier` — 哪些 group 算第几层
- `phases` — 里程碑轴上那几段的日期、周投入、目标、说明
- `targets` — 哪个阶段该点亮哪个格子（`{phase, tier, stage}`）
- `extras.lists` — 每组下面那几个虚线框：`{name, short, map}`，`name` 对 `lists.json` 的题单名，
  `map` 是「分类 → 组名」，顺序就是框的顺序和去重优先级
- `groups[].tag` — 这一组挂到哪份 trick 文档（`{kind: "paradigms"|"structures", name}`），
  组标题就是链到它。指向一份还不存在的文档也没关系 —— 点开是空的，写完保存就建出来了。

### 手机上复习（同步）

照着 [ai-infra-inferview](https://github.com/scatyf3/ai-infra-inferview) 的闪卡同步做的：出门用手机打开线上站，
复习照样能评分，回到电脑上记录自己落进 `meta.json`。

**设置（每台设备一次）**：线上站顶栏点 ☁ → 按提示建一个 fine-grained token（只授权这个仓库，
*Contents* 选 *Read and write*）→ 粘贴、连接。token 只存在那台设备的浏览器里，手机丢了去 GitHub 吊销。
没连 token 的站和以前一样是纯自测 —— 路人打开也不会多出评分按钮。

**连上之后**复习面板里这几样能用，每一下都记成一条**事件**：

| 动作 | 回到本机后落在哪 |
|---|---|
| 评分 `1`–`4` | 那题的 `meta.json` `fsrs` / `syntax/state.json` + `reviews.jsonl` 一行（带 `eid`、`src: "sync"`） |
| ⏸ 暂停 | `meta.json` 的 `paused`（日期是手机上按的那天）+ `edits.jsonl` 一行 |
| 💬 批注 | `card-comments.jsonl` 一行（`cid` = 事件的 `eid`），之后照常「处理卡片批注」 |

「押到队尾」只存在那台设备的浏览器里（和本地的 `session.json` 一样是易失状态）。「改一下」答案卡仍然只有本地能用 ——
那是改内容文件，不是复习记录。

**数据怎么走**：

```
手机评分 → localStorage（立刻生效、离线不丢）
        → 停手 2 秒 / 切后台 / 重新联网 → data 分支的 dashboard/sync-inbox.json（一次同步一个 commit）
电脑 server.py 启动 / 点 ↻ Sync → git fetch origin data → inbox.py 落还没落过的 → 记进 sync-applied.jsonl
你 commit + push main → 线上站重新部署, 导出的 api/sync-applied.json 里有了这些 eid
手机下次同步 → 这些事件从 inbox 里删掉, 也不再重放
```

- **为什么记事件而不是同步状态**（ai-infra-inferview 同步的是整份 json）：这边的调度状态散在一百多个 `meta.json` 里，
  电脑上的看板也在同时评分。事件只追加、不修改，合并就是按 `eid` 取并集，两台设备怎么交错都不会互相覆盖；
  `sync-applied.jsonl` 按 `eid` 去重，同一份 inbox 拉多少遍都只落一次。
- **为什么是单独的 `data` 分支**：手机每次同步是一个 commit，不混进 main 的历史、不触发部署，
  电脑上 `git push` 也不会因此被拒。分支第一次同步时从 main 自动建出来。
- **手机上看到的 due 是临时算的**：线上站的数据是 main 当时的状态，还没落进 main 的事件用
  `web/src/lib/fsrs.ts`（`fsrs.py` 的逐行移植）在上面重放一遍，到期数 / 队列 / 📈 / 按钮上的间隔才对得上。
  真正落盘时 `fsrs.py` 按同一条事件再算一次。两份实现有对拍（`lib/__tests__/fsrs.test.ts`，固定种子的 319 步，
  `python dashboard/fsrs.py --fixture …` 重新生成）。
- **事件晚到**（手机评过、还没落盘，电脑上又评了同一题）：按 `max(事件那天, 上次复习那天)` 算，当成同一天又评了一次，
  不会排出负的间隔。两边是同一条规则（`server._fsrs_day` / `lib/inbox.ts` 的 `fsrsDay`）。
- 落不下去的事件（题被删了、语法卡改了标题 = 换了 id）在账本里记成 `missing`，不会每次都重试；
  格式不对的事件跳过、不进账本。`fsrs_params.json` 换了参数的话手机上的临时 due 会和落盘的不一样 —— 记得 `fsrs.ts` 也改。
- 命令行：`python dashboard/inbox.py`（拉 + 落）、`--dry-run`（只列出来）、`--no-fetch`（用上次拉下来的）。
- 已经落过、还没 push 的事件在手机上会一直显示「等电脑落盘」，push 之后自然清掉。

### 队列快照 `dashboard/session.json`

前端每次动队列（开面板 / 换题 / 押到队尾 / 换模式 / 关面板）就把当前队列
`POST /api/review/session` 覆盖存一份，`GET` 同一个地址读回来。里面是当前这道、
剩下的队列、这一轮押到队尾的记录，**都带题名**（服务端从索引里补的）。

> **这是易失状态, 不是数据源。** 不进 git（`.gitignore` 里）、不参与 FSRS 调度，
> 队列仍然是每次开面板现算。大部分字段只是让浏览器外面能看见"现在队列长什么样"。

**唯一会被读回去的是 `defers`**：`{"date": "2026-09-10", "problems": [...], "syntax": [...]}`，
今天两个牌组各自押过队尾的题号（按发生顺序、可重复）。前端只 POST 当前牌组那份，另一份服务端从旧文件
原样带过来；`date` 不是今天就整份作废。文件是原子写（tmp + `os.replace`）。

开面板时 `start()` 先 `GET /api/review/carry?deck=...` 拿两样东西，再在现算队列上做调整：

| 字段 | 来源 | 怎么用 |
|---|---|---|
| `deferred` | `session.json` 的 `defers[deck]` | 现算队列里有的挪到队尾（押了几次的按最后一次排） |
| `again` | `reviews.jsonl` 里今天、同牌组、**最后一次**评分是 1 的 | 现算队列里没有（due 已是明天）就追加到队尾 |

两类都只认**现算队列里或牌组里还在**的 id —— 改了语法卡标题留下的旧 id 会被滤掉，
「关掉重开就好」那条恢复路径照旧有效。押队尾**没有**写进 `reviews.jsonl`：那份是 FSRS 训练数据，
📈 面板也把每一行都当一次复习算。

只读站没有写接口，`syncSession()` 和拉 carry 都直接跳过，队列就是现算的。

## 前端

照着 [ai-infra-inferview](https://github.com/scatyf3/ai-infra-inferview) 的做法：Vite + Vue 3 SFC + TS，
纯计算抽成不依赖 DOM 的 `src/lib/*.ts` 并配 vitest 单测，外观用 VitePress 的设计语言
（品牌蓝 `#2563eb`、毛玻璃顶栏、浅/深色两套 token、右上角拨片切换）。

- **复习面板是 SFC**（`src/components/ReviewPanel.vue`），其余看板和 overlay 仍然是 `app.js` 里的手写 DOM。
  这一屏状态最多（队列 / 揭晓与否 / 选择题 / 就地编辑 / tab），最早迁到 Vue；现在模板从 index.html
  搬进了 SFC，编译期就能查出模板错误。
- **面板和看板之间只走 `host` 一个口子**（见 `ReviewPanel.vue` 的 `ReviewHost`）：读两组行、
  算今天的队列、重画看板、改 meta、开 📈。以前是直接摸全局变量；拆成模块后依赖得写明白。
  `app.js` 里构造 host 时全用箭头函数 —— `putMeta` / `PLAN` 在文件更下面才声明，直接取值会撞 TDZ。
- **`src/lib/` 是纯函数**：熟练度阶梯与 S 深度、账本、复习队列的范围与顺序、选择题、时间轴回放、
  markdown + 题号链接、Python 高亮。改这些先跑 `npm test`。marked 锁在 15.0.7（和原来 vendor 的同版本），
  渲染结果不变。
- **深浅色**：`<html data-theme>` 是唯一开关，`index.html` 里一段内联脚本在首帧前落定（不闪白）。
  手动切过记在 `localStorage` 的 `lc-theme`，没切过就一直跟系统。
- **离线**：Inter 字体用 `@fontsource-variable/inter` 打进产物，不走 Google Fonts；构建产物不依赖网络。
- **只读站的退化**靠组件里的 `readOnly` 标志位（读 `<html class="ro">`），评分按钮 / 「改一下」/
  「下一题」直接用 `v-if` 决定渲染哪一套；其余写入口由 `ro.css` 藏掉。
- **CI**（`.github/workflows/pages.yml`）：`npm ci` → `npm test` → `npm run build` → `export_static.py`。
  单测挂了就不发布。
