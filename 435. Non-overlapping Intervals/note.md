# 435. Non-overlapping Intervals

范式：区间题 §2 调度/贪心 —— [paradigms/intervals.md](../paradigms/intervals.md)


idea很简单，用end排序然后迭代，greedy过序列，如果序列valid则+1.


但为啥这样保证cover最优解？
右端点 = 资源什么时候被释放。释放得越早，后面能塞的东西越多，而且"选它"和"选别的"在计数上都只算 1 个——收益一样，代价更小，所以永远不亏。

论证

严格一点，用交换论证（exchange argument）证明：

命题：设 a 是全局右端点最小的区间，那么一定存在一个最优解包含 a。

证明：取任意一个最优解 OPT，把它按右端点排序，设它的第一个区间是 f。

若 f == a，结论成立。
否则，把 f 换成 a，得到 OPT' = OPT - {f} + {a}。要验证 OPT' 仍然合法：
a 是全局右端点最小的，所以 a.end <= f.end。
OPT 里除 f 外的任何区间 x，都满足 x.start >= f.end >= a.end，所以 x 和 a 也不重叠。 ✅
|OPT'| = |OPT|，所以 OPT' 同样是最优解。

反过来看两个错误的排序方式，直觉会更清楚：

按左端点排 — 会被一个又长又早的区间坑死：

```
[1,100]  ■■■■■■■■■■■■■■■■■■■■
[2,3]      ■
[4,5]          ■
```
先选 [1,100] 只能得 1 个，最优是 [2,3],[4,5] 得 2 个。

按长度排（"选最短的总没错吧"）— 短的可能卡在正中间：

```
[1,5]   ■■■■■
[4,6]       ■■        ← 最短，但它同时挡住了上下两个
[5,9]        ■■■■
```

先选 [4,6] 只能得 1 个，最优是 [1,5],[5,9] 得 2 个。

只有右端点这个指标，能保证"选它之后剩余空间最大"，而交换论证正是把这个直觉变成了证明。
