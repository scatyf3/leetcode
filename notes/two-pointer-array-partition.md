# 原地切数组 SOP:有效区 + 垃圾区(双指针)

适用题:LC 26(去重)、27(删元素)、283(移零)等「原地把数组切成两部分」的题。

## 核心约定(约定 A,推荐)

`k` 指向**垃圾区第一格** = valid 区的右开边界。半开区间 `nums[0:k]` 是已确认结果。

这样 `k` 同时是三样东西:
1. 下一个要写的位置(写完 `k += 1`)
2. 有效元素个数(半开区间 `[0:k]` 长度正好是 `k`)
3. 返回值

→ 不用再单独维护计数变量(如 27 题里多余的 `no_eq_count`,直接 `return k`)。

## 关键澄清:数组没有「空」位置

`nums[k]` 里存的是旧数据(垃圾),原地覆盖即可。

安全的原因:`k <= i` 永远成立 —— 要覆盖的位置早被快指针 `i` 读过了,绝不会丢未探测的数据。

```
nums[0 : k]   有效区(k 不在内)
nums[k]       垃圾区第一格 ← k 指这里,装着没用的旧值
```

## 快慢指针模板(同向,保序)

```python
k = 0                      # k 永远指垃圾区第一格
for i in range(len(nums)):
    if keep(nums[i]):
        nums[k] = nums[i]  # 踩在垃圾位上写
        k += 1
return k
```

## 设计 index 的 4 步

1. **写下不变式**:指针左右各是什么(`nums[0:k]` 已保留 / `nums[k:i]` 已丢弃 / `nums[i:]` 未探测)。
2. **定初值**:让空区间也成立。约定 A → `k=0`。
3. **定循环条件**:相向首尾指针待处理区是**闭区间**,必须 `i <= tail`(写成 `i < tail` 会漏最后一个)。
4. **定返回值**:由不变式推出。约定 A 返回 `k`。

## 记忆口诀

- k 站在「有效」和「垃圾」的门槛上,脚踩在垃圾那边。
- 慢指针只在「该保留」时前进。

## 约定 B(`k` 指最后一个有效元素)

`k` 指最后一个有效元素 → 返回 `k+1`、空区间初值 `-1`,off-by-one 容易错。
**多数题用约定 A;但当「判断是否保留」需要回看「最后一个已保留值」时,约定 B 更自然**(见 26 题)。

# 三道题用本模板的拆解

## LC 27 Remove Element —— 模板原型(约定 A)

不变式:`nums[0:k]` 是已保留(≠val)的元素,`k` 指垃圾位。
判断保留只看当前元素本身,与已保留区无关 → 约定 A 最干净,`k` 三位一体。

```python
def removeElement(self, nums, val):
    k = 0
    for i in range(len(nums)):
        if nums[i] != val:      # keep
            nums[k] = nums[i]
            k += 1
    return k
```
> 比首尾交换法逻辑更统一;原写法里的 `no_eq_count` 是多余的,`k` 就是个数。

## LC 26 Remove Duplicates —— 变体:比较对象是「最后一个已保留值」

去重要判断「当前元素和上一个保留的是否相同」,**判断条件依赖已保留区的末尾**。
这时让 `k` 指「最后一个有效元素」(约定 B)读起来最顺:直接 `nums[i] != nums[k]`。

```python
def removeDuplicates(self, nums):
    if not nums:
        return 0
    k = 0                        # k = 最后一个已保留元素的下标(约定 B)
    for i in range(1, len(nums)): # 首元素必留,从 1 开始
        if nums[i] != nums[k]:   # 和最后一个已保留值不同 → 保留
            k += 1
            nums[k] = nums[i]
    return k + 1                 # 约定 B:个数 = k+1
```
> 这正是你 sol2 的写法,思路是对的。若硬用约定 A,条件得写成 `nums[i] != nums[k-1]`,反而绕。
> wa1 的教训:用 set 去重既丢了「已排序」这个前提,又破坏了保序约束 —— 排序数组去重不需要 set。

## LC 88 Merge Sorted Array —— 镜像:从尾部往前写

nums1 尾部有空位,若从前往后写会覆盖 nums1 还没读的有效值。
**解法:把 `k` 设成「右侧结果区的下一个写位」,从最大端往前填**。
不变式:`nums1[k+1:]` 是已排好序的最大后缀;两个读指针 `i,j` 始终 `<= k`,覆盖安全。

```python
def merge(self, nums1, m, nums2, n):
    i, j = m - 1, n - 1          # 两个有效区的尾
    k = m + n - 1                # 下一个要写的位置(从尾往前)
    while j >= 0:                # nums2 没放完就继续(nums1 剩的本就在原位)
        if i >= 0 and nums1[i] > nums2[j]:
            nums1[k] = nums1[i]; i -= 1
        else:
            nums1[k] = nums2[j]; j -= 1
        k -= 1
```
> 这就是 opt2。sol1 用 `nums1.copy()` 是 O(n) 额外空间;从尾往前写就不用拷贝。
> 循环条件只需 `while j >= 0`:nums2 放完时,nums1 剩余元素已经在正确位置上,无需再搬。

## 三题对照速记

| 题 | 写方向 | k 语义 | 判断保留依赖 | 返回 |
|----|--------|--------|-------------|------|
| 27 | 从前往后 | 垃圾位(约定 A) | 仅当前元素 | `k` |
| 26 | 从前往后 | 最后有效(约定 B) | 已保留区末尾 | `k+1` |
| 88 | **从后往前** | 右侧结果区写位 | 两源尾部比较 | 原地 |

通用判据:**写指针永远不能踩到「还没读的数据」**。同向能保证(`k<=i`)就从前写;前写会覆盖未读数据(88)就从后写。
