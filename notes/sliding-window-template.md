# 滑动窗口骨架:两个模板 + 两个填空位

适用题:LC 3、76、209、424、438、567 等「在数组/字符串上找满足某条件的连续区间」的题。

配套:[off-by-one-checklist.md](off-by-one-checklist.md)(索引不出错)、[two-pointer-array-partition.md](two-pointer-array-partition.md)(原地双指针)

---

## 先说「骨架」是什么

**骨架 = 一段可以复制粘贴的代码框架,里面有明确标出的填空位。** 不是函数,不是类,就是模板。

它复用的是**结构**:循环怎么转、什么时候收缩、什么时候结算。每道题只改填空位里的 1~2 行。

## 为什么是骨架,不是封装成函数/类

先看封装成类真长什么样(这份能跑,LC3 全用例过):

```python
class Window:
    def __init__(self, s):
        self.s, self.l, self.r, self.cnt = s, 0, -1, Counter()
    def extend(self):
        self.r += 1
        self.cnt[self.s[self.r]] += 1
    def shrink(self):
        self.cnt[self.s[self.l]] -= 1
        self.l += 1
    def valid(self):
        return self.cnt[self.s[self.r]] <= 1     # ← 只有这一行是题目相关的
    def __len__(self):
        return self.r - self.l + 1

w = Window(s); best = 0
for _ in range(len(s)):
    w.extend()
    while not w.valid():
        w.shrink()
    best = max(best, len(w))
```

写得挺干净,能跑。问题在于:

1. **`valid()` 是题目特定的,换题必须打开类改内部。** 抽象的价值是「写一次,之后不打开就能用」。这个类**每道题都要打开改**,那它就不是抽象,只是把 8 行摊成 30 行。
2. 想让它真通用 → `valid` 得当 callback 传进来 → callback 又要访问 `self.cnt` / `self.r` / `self.s` → 封装当场被打穿,签名变成 `Window(s, valid=lambda w: w.cnt[w.s[w.r]] <= 1)`,比 inline 难读得多。
3. 状态是可变的(`l`/`r`/`cnt` 全在变),这里又是热路径,抽象层性价比本来就低。

**骨架的诚实之处:它不假装内部不用改,它直接把「要改的地方」标出来给你填。** 结果是同样的复用(结构复用),但没有那 20 行仪式。

> 一句话:算法题的复用发生在**写代码之前**(模板 + 不变式),不是**运行时**(函数边界)。
> 工程里也一样 —— 热路径代码同样是手动内联、不封装的。不是两套价值观,是同一套价值观在不同规模下的不同结论。

## 骨架 A:求**最长**合法窗口

不变式:**结算时窗口一定合法**。所以先收缩到合法,再结算。

```python
state = init()
l = 0
best = 0
for r, x in enumerate(arr):
    add(state, x)                    # ① 纳入 r
    while not valid(state):          # ② 不合法就收缩(注意是 while 不是 if)
        remove(state, arr[l]); l += 1
    best = max(best, r - l + 1)      # ③ 结算(此刻必合法)
return best
```

## 骨架 B:求**最短**合法窗口

不变式:**合法时才结算,结算完立刻收缩试试更短的**。结算在 while 内部。

```python
state = init()
l = 0
best = INF
for r, x in enumerate(arr):
    add(state, x)                    # ① 纳入 r
    while valid(state):              # ② 合法就一直缩
        best = min(best, r - l + 1)  # ③ 先结算
        remove(state, arr[l]); l += 1
return 0 if best == INF else best
```

**A 和 B 的差别只有两处**:`while` 条件取反、结算在循环外/内。选哪个看题目求最长还是最短。

## 填空位对照表(全部验证跑过)

| 题 | 骨架 | `state` | 收缩条件 |
|----|------|---------|----------|
| **3** 无重复最长子串 | A | `Counter` | `cnt[x] > 1` |
| **424** 替换 k 次后最长同字符 | A | `Counter` + `mx`(历史最大频次) | `(r-l+1) - mx > k` |
| **209** 和 ≥ target 最短子数组 | B | `sum` | `tot >= target` |
| **76** 最小覆盖子串 | B | `Counter(t)` + `miss` | `miss == 0` |
| **438/567** 找异位词 | 定长窗口 | `Counter` | `r-l+1 > len(p)` |

### LC 3

```python
cnt = Counter(); l = 0; best = 0
for r, x in enumerate(s):
    cnt[x] += 1
    while cnt[x] > 1:
        cnt[s[l]] -= 1; l += 1
    best = max(best, r - l + 1)
return best
```

### LC 424

```python
cnt = Counter(); l = 0; best = 0; mx = 0
for r, x in enumerate(s):
    cnt[x] += 1; mx = max(mx, cnt[x])
    while (r - l + 1) - mx > k:          # 窗口内非众数的个数 > k 就不合法
        cnt[s[l]] -= 1; l += 1
    best = max(best, r - l + 1)
return best
```

### LC 209

```python
tot = 0; l = 0; best = float('inf')
for r, x in enumerate(nums):
    tot += x
    while tot >= target:
        best = min(best, r - l + 1)
        tot -= nums[l]; l += 1
return 0 if best == float('inf') else best
```

### LC 76

```python
need = Counter(t); miss = len(t); l = 0; bl, br = 0, -1
for r, x in enumerate(s):
    if need[x] > 0: miss -= 1
    need[x] -= 1
    while miss == 0:
        if br == -1 or r - l < br - bl: bl, br = l, r
        need[s[l]] += 1
        if need[s[l]] > 0: miss += 1
        l += 1
return s[bl:br+1] if br != -1 else ""
```

## 骨架版 vs 官方「特化版」

LC 3 的官方解不是骨架版,而是**特化**:

```python
last = {}; l = 0; best = 0
for r, c in enumerate(s):
    if c in last and last[c] >= l:
        l = last[c] + 1          # 一步跳到位, 把 while 收缩塌成一次跳跃
    last[c] = r
    best = max(best, r - l + 1)
return best
```

对比:

| | 骨架版 | 特化版 |
|---|---|---|
| 复杂度 | O(n),最坏 2n 步 | O(n),n 步 |
| 通用性 | 一套解 6 道题 | 只解这一道 |
| 下标算术 | 只有 `l += 1` | 有 `last[c] + 1` ← **off-by-one 高发区** |
| `>= l` 守卫 | 不需要 | 必须有,漏了就错 |

**默认写骨架版。**它显示你识别出了题型而不是背了一道题;而且它天生绕开了 `last[c] + 1` 和 `>= l` 这两个坑(参见 [off-by-one-checklist.md](off-by-one-checklist.md) 的实战复盘)。特化版留作「被问到能不能更快」时的加分项。

## 第 -1 个问题:这题到底是不是滑窗?

在问任何形状之前先过这一关,否则后面全白搭:

**题目要的是「子串 / 子数组」(连续) 还是「子序列」(可以跳着选)?**

- **连续** -> 滑窗有戏,往下走
- **可跳** -> 滑窗**出局**,任何窗口都是连续的一段,表示不了"跳过中间某个"。去找 DP

一字之差: `substring` / `subarray` vs `subsequence`;中文「子串 / 子数组」vs「子序列」。
这是读题第一杀手,栽过一次(把 LC 300 lengthOfLIS 当滑窗做)。术语全表和另外两个坑见
[subseq-vs-substr.md](subseq-vs-substr.md)。

    nums = [10,9,2,5,3,7,101,18]
    LC 300 最长上升子"序列"(可跳)   = 4   [2,5,7,101], 跳过了下标 4
    LC 674 最长连续递增"子数组"     = 3   [3,7,101]
    同一个输入两个答案 —— 区别是实质性的, 不是措辞。

第二关:**合法性依赖窗口里的什么?**
如果只依赖「刚加进来的元素和它前一个」(如 674 的 `nums[i] > nums[i-1]`),
窗口会退化成一个计数器,`l` 都不需要:

    cur = cur + 1 if nums[i] > nums[i-1] else 1     # 断了就重新计数
    best = max(best, cur)

真正需要完整骨架的,是合法性依赖**整个窗口的统计量**的题(3 的重复、424 的众数、209 的和、76 的覆盖)。

## 第 0 个问题:外层该枚举 r 还是 l?

上面那三个问题是在「已经决定外层跑 r」之后才成立的。但很多人(包括我)第一反应是枚举**左**端点、
向右扩 —— 那是另一种形状,也能对,但会多出一堆 ±1。判据如下。

### 判据:while 退出后的后置条件,是不是一个单一命题

```python
# 形状 1: 枚举左端点, 向右扩
while r < n and valid(): r += 1
# 退出后: valid 失败  或  越界        <- "或", 两种情况

# 形状 2: 枚举右端点, 向左缩(= 骨架 A/B)
while not valid(): l += 1
# 退出后: valid 成立                   <- 单一命题
```

形状 2 退出后你**确切知道窗口合法**,所以结算就是 `r - l + 1`,不加不减。
形状 1 退出后你不知道是哪种情况停的,而两种情况的结算方式不一样 —— 于是必须写 `-1` 之类的补丁,
而那个补丁只对其中一种退出原因成立。

> **一个表达式没法同时为两种退出原因负责。后置条件里出现「或」,就一定会有 ±1 和 edge case 来补它。**

这条可以在**动手之前**判断:先把 while 的退出条件写成一句话,看有没有「或」。

### 为什么形状 2 的后置条件天然单一

两个操作的性质不对称:

| 操作 | 对「合法」的影响 |
|---|---|
| 加入右边一个 | 只可能**变差**(合法 -> 可能非法) |
| 移出左边一个 | 只可能**变好**(非法 -> 可能合法) |

形状 2 = **无条件做那个会变差的操作, 再用单向的修复操作补回来**。
加入永远不会失败(不需要判断),修复永远朝一个方向(`l` 只右移,一到合法就停)。

形状 1 想在「加入之前」判断能不能加 -> 变成**试探 + 回滚**:先改状态、发现不行再撤销,
于是多出「撤销」分支,还多出「窗口空了 r 要跟上 l」这类同步问题。

> **把可能失败的操作,放在不需要回滚的位置。**

第二条判据:**每个变量的修改点是不是唯一。** 形状 2 里 `r` 只由 for 改、`l` 只在收缩里改;
形状 1 里 `r` 有两处修改点,就必须论证它们不打架。

这不是滑窗特有的 —— **单调栈是同一个模式**:不是「判断能不能 push」,而是
`while 违反单调: pop` 然后无条件 `push`。先修复再无条件做,后置条件同样单一。

### 什么时候**必须**用形状 1

不是形状 2 永远赢,有三类它根本用不了:

1. **答案是一个数组而不是一个数。** 形状 2 的窗口是共享的,`l` 单调右移,丢掉的左端点回不去。
   题目要「对每个 i 求以 i 开头的最长区间」就只能枚举左端点。
2. **state 不支持删除。** 形状 2 的收缩要求 `remove(state, arr[l])` 存在:

   | 聚合 | 可减? |
   |---|---|
   | 和、计数、异或 | ✓ (异或的逆是它自己) |
   | **max / min** | ✗ 删一个元素,新极值无从得知 |
   | **OR / AND / gcd** | ✗ `1|1=1`,撤销一个 1 不知道该不该变 0 |

   424 踩的是缩水版:频次可减,但「从频次表取最大值」不可增量维护,所以要么 O(26) 重算、
   要么加一层 bucket(频次的频次)。真正不可减的聚合会让形状 2 **直接写不出来**,
   出路是枚举左端点 + 二分/倍增,或换数据结构(LC 239 用单调队列绕开 max 不可减)。
3. **删除能做但很贵。** 合法性对长度单调时,`for l: 二分最大的 r`,O(n log n),比维护窗口好写。

### 决策顺序

```
1. 两个指针同向还是相向?       相向(11/15/42/167) -> 另一族, 见 paradigms/two-pointer.md
2. 答案是一个数还是一个数组?   数组 -> 形状 1
3. state 支持"删一个"吗?       不支持 -> 形状 1, 或换数据结构
4. 删除很贵吗?                 很贵 -> 形状 1 + 二分
   以上都不是                  -> 形状 2 = 骨架 A/B
```

3、76、209、424、438、567、1004 四问全过 -> 全都用形状 2。所以「一般情况形状 2 更好」这个感觉是对的,
但它的真实含义是「大多数题的 state 恰好可加可减,且只要一个数」,不是形状 2 本身更优越。

## 拿到新题的 3 个问题

1. 求**最长**还是**最短**? → 选骨架 A 还是 B
2. 窗口里要维护**什么统计量**? → `state`
3. **什么时候算不合法**? → 收缩条件

回答完这三句,代码就是填空。真正要练的是把这三句说出来的速度,不是把代码写短。

## 起始状态怎么想

**state 是「当前窗口内容」的函数,初始化就是把这个函数作用在「空窗口」上。**
窗口一开始是空的(`l = 0`,`r` 概念上是 -1),所以每个变量都问同一句:*窗口里一个元素都没有时,我该是多少?*

| 题 | state 的含义 | 空窗口时 |
|---|---|---|
| 3 / 424 | 各字符出现次数 | `Counter()` 空表 |
| 209 | 窗口和 | `0` |
| 76 | 还差多少个字符没覆盖 | `len(t)` <- 一个都没覆盖,所以是满的 |

76 那个最容易错:直觉想写 `miss = 0`,但 `miss` 是「还缺多少」,空窗口当然缺全部。
**判断标准不是「零值」,是「对空窗口求值」。**

`best` 是另一回事,它不是窗口 state,是**聚合的单位元**:求最长 -> `0`(空窗口长度 0,安全下界);
求最短 -> `INF`(还没找到)。别写成 `arr[0]` 或 `1`,那是假设至少有一个答案。

**怎么检验:跑两个退化输入。**

- `n = 0`:循环一次都不进 -> 直接返回 `best` 初值 -> 必须正好是「无解」的答案
- `n = 1`:循环恰好一轮 -> 「空窗口 + 纳入 arr[0]」-> state 初始化对了,这一轮自动正确

**初始状态正确 = 边界情况自动正确。** 骨架里不需要 `if not s: return 0` 这类特判;
发现自己在加特判,多半是初始状态设错了。

### 一个隐含的安全条件

收缩循环 `while not valid(): remove(arr[l]); l += 1` 没有 `l <= r` 保护,凭什么不越界?
**因为长度为 1 的窗口必须永远合法** —— 缩到只剩 `arr[r]` 时 valid 一定成立,循环就停了。

424 验一下:单字符窗口 `len=1, mx=1` -> `1-1=0 <= k` ✓。LC 3 同理(单字符不可能重复)。
**设计 valid 时要顺带检查这条**;若某题单元素窗口可能不合法,骨架不能直接用,得加 `l <= r` 守卫。

## 两个易错点

- ② 处是 `while` 不是 `if`。一次收缩未必够(LC 209 里可能连缩好几格)。
- 骨架 A 的结算必须在 while **之后**,骨架 B 的结算必须在 while **之内**。写反了就是在非法窗口上结算 / 漏掉最短解。
