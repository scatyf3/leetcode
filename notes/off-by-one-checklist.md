# Off-by-one 自查清单:索引/区间不靠「小心」的机械流程

适用:滑动窗口(LC 3)、双指针(LC 26/27/88)、区间长度计算、任何出现 `+1` / `-1` / `<=` vs `<` 的地方。

前提认知:off-by-one 是有专名的高频 bug,不是粗心问题。**它的解法是把脑子里的约束变成机器能检查的东西**,而不是下次更专注。

---

## 第 0 步:先定区间约定,再写代码

动手前一行注释定死语义,后面所有公式都从它推:

```python
# 不变式: 窗口 s[l..r] 闭区间, 内部无重复字符
```

约定一旦写死,长度就没有第二种写法:

| 约定 | 记法 | 长度 | 空区间 | Python 切片 |
|------|------|------|--------|-------------|
| 闭区间 | `[l, r]` | `r - l + 1` | `l > r`(别扭) | `s[l:r+1]` |
| **半开** | `[l, r)` | `r - l` | `l == r`(自然) | `s[l:r]` ← 天然对齐 |

**长期建议:全项目统一用半开区间。** Python 的切片、`range()`、`enumerate` 边界本来就是半开,统一之后长度永远是 `r-l`,不用记什么时候 `+1`。同时维护两套规则迟早混。

(注:滑窗题因为 `r` 来自 `enumerate` 是「当前元素下标」,闭区间更自然。那就**在这类题里**统一用闭区间 —— 关键是同一类题里不摇摆。)

## 5 个机械动作

### 1. 写下不变式

指针把数据切成几段,每段是什么状态,写成注释。参见 [two-pointer-array-partition.md](two-pointer-array-partition.md) 的「设计 index 的 4 步」:

```
nums[0 : k]   有效区(k 不在内)
nums[k : i]   已丢弃
nums[i : ]    未探测
```

不变式写出来之后,循环条件、初值、返回值都是**推出来的**,不是猜的。

### 2. 长度公式代两个点验证

只代一个点会漏掉方向错误。**必须代单元素 + 一个长区间**:

| 公式 | `[2,2]` 应为 1 | `[2,5]` 应为 4 | 结论 |
|------|------|------|------|
| `r - l + 1` | `2-2+1 = 1` ✓ | `5-2+1 = 4` ✓ | 对 |
| `l - r + 1` | `2-2+1 = 1` ✓ | `2-5+1 = -2` ✗ | **错**(单点看不出来) |

附加的 3 秒检查:**长度不可能为负**。已知 `l <= r` 恒成立,那 `l-r+1` 恒 ≤ 1 —— 光看符号就能毙掉。

### 3. 把不变式写成 assert(最有效的一招)

调试期临时插一行,让机器替你盯:

```python
for r, c in enumerate(s):
    if c in last and last[c] >= l:
        l = last[c] + 1
    last[c] = r
    assert len(set(s[l:r+1])) == r - l + 1, f"窗口破了: l={l} r={r} w={s[l:r+1]!r}"
    best = max(best, r - l + 1)
```

漏掉 `+1` 的版本跑 `"abab"` 立刻炸在 `窗口破了: l=0 r=2 w='aba'`,直接指出哪一步、哪个窗口。提交前删掉。

其他题型的不变式 assert:
- 双指针原地删除:`assert k <= i`(写指针不能踩未读数据)
- 排序数组去重:`assert nums[:k+1] == sorted(set(nums[:k+1]))`
- 二分:`assert lo <= hi + 1`(区间不会跨过头)

**这条是核心**:凡是你脑子里默念「这里应该永远成立」的话,都能写成一行 assert。

### 4. 用退化用例,不用题目样例

题目给的 `"abcabcbb"` 太「好」了,很多 bug 它抓不到。固定跑这一套:

| 用例 | 专治 |
|------|------|
| `""` | 空输入 / 初值 |
| `"a"` | 单元素 / 长度公式方向 |
| `"aa"` | 最简单的重复 |
| `"ab"` | 无冲突的两元素 |
| `"abab"` | `l = last[c]` 少了 `+1` |
| `"abba"` | 缺 `>= l` 守卫(旧记录把 l 往回拽) |
| `"tmmzuxt"` | 同上,经典陷阱 |

数组题的对应版本:`[]`、`[1]`、`[1,1]`、`[1,2]`、全同、全不同、已排好序、完全逆序。

`"abab"` + `"abba"` 两个基本盖住 LC3 全部索引错误。

### 5. 结构上少给自己犯错的机会

- 能 `enumerate` 就不写 `range(len(x))` + 手动 `x[i]`
- 能用切片表达就不用下标算术
- 变量名带语义,不同概念不同名字:`last_seen_index`(上次出现的位置)和 `l`(窗口左界)是两个东西,名字不同就会提醒你「从一个推另一个要 ±1」
- 只维护一个计数来源。`k` 能同时当写位/个数/返回值时,别再开一个 `count`(LC 27 的 `no_eq_count` 就是多余的)

## 「位置」vs「边界」:±1 的唯一来源

绝大多数 off-by-one 都是这一类:**哈希表/变量里存的是「某元素所在的位置」,而你要把它当「区间的边界」用。**

```python
last[c] = r              # 存的是「c 出现在哪」    ← 位置
l = last[c] + 1          # 用作「窗口从哪开始」    ← 边界, 必须跨过它
```

自查问句:**这个数值指的是「某个元素」还是「元素之间的缝」?**
- 指元素 → 当左边界要 `+1`(跨过去),当右闭边界直接用
- 指缝 → 直接用

同理:
- `nums[i]` 是「最后一个已保留元素」→ 个数是 `i+1`
- `k` 是「下一个写位」→ 个数就是 `k`

## while 循环退出时,指针停在「第一个不合法的位置」

这是 ±1 的第二大来源,和上面的「位置 vs 边界」并列。

`while` 是**先测条件、再执行循环体**。循环体最后一步移动了指针,移动完必须回到条件处重测才知道新位置行不行 —— 所以**退出时指针必然已经踩在那个不合法的位置上**,要拿最后一个合法位置就得减回来。

```python
# LC5 中心扩展
while l >= 0 and r < n and s[l] == s[r]:
    l -= 1; r += 1
# 此刻 [l, r] 已经不合法, 最后一个合法区间是 [l+1, r-1]
```

同一现象的其他面孔:
- 二分 `while lo < hi` 退出后,`lo` 停在**第一个** `>= target` 的位置(不是最后一个 `<`)
- `while i < n and cond(a[i])` 退出后,`a[i]` 是第一个不满足 cond 的元素

### 推论:±1 消灭不掉,只能选择把它放在哪

以 LC5 的 `expand` 为例,同一个逻辑有三种落点:

| 放哪 | 写法 | ±1 出现次数 |
|------|------|------------|
| 循环条件 | 向前看:`while l-1 >= 0 and r+1 < n and s[l-1] == s[r+1]` | 3 次(还要补前置守卫) |
| 返回值 | `return l+1, r-1`,返回下标对 | 2 次 |
| **语法** | `return s[l+1 : r]`,切片右端开区间白送一个 -1 | **1 次** ✓ |

**选出现次数最少的那个落点** —— 每多出现一次就多一个写错的机会。这也是第 0 步「统一用半开区间」的同一条理由:让语法替你承担一半的 ±1。

配套的第二招:**让非法输入自然退化成空区间,而不是写 if 特判**。LC5 里偶中心传 `(i, i+1)`,即使 `s[i] != s[i+1]` 或 `i+1` 越界,while 首轮就退出并返回 `""`,不需要任何守卫。特判写得越少,能写错的地方越少。

完整复盘见 [5. Longest Palindromic Substring/note.md](../5.%20Longest%20Palindromic%20Substring/note.md)。

## 实战:LC3 的两个 bug 如何互相掩盖

错误版:

```python
if c in last and last[c] >= l:
    l = last[c]                        # bug A: 少 +1
last[c] = r
max_len = max(l - r + 1, max_len)      # bug B: 写反
```

- bug B 让 `max_len` 恒为 1(动作 2 可查)
- bug A 让窗口内混进重复字符(动作 3 的 assert 可查)
- **合起来只表现为「永远返回 1」**,bug B 把 bug A 的症状盖住了 —— 你修好 B 之后 `"abab"` 会返回 3,还是错的

教训:**症状少 ≠ bug 少。** 不要根据「输出看着像哪儿错了」去猜,用 assert 把每个不变式单独暴露出来。

## 速记

1. 先写不变式,后写代码 —— 边界是推出来的,不是试出来的
2. 长度公式代两个点(单元素 + 长区间),再查符号不为负
3. 不变式写成 assert,让机器盯
4. 测退化用例,别测题目样例
5. 「位置」当「边界」用,几乎总要 ±1
6. while 退出时指针停在第一个**不合法**的位置;±1 只能搬家不能消灭,搬到出现次数最少的地方

> 口诀:**定约定 → 写不变式 → 断言它 → 用最短的用例打它。**
