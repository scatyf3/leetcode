# 138. Copy List with Random Pointer

##  思路
复杂linkedlist/graph clone都要两次forward，第一次建node to node hash，第二次连接，很怪

一旦不是单向linkedlist，有循环

把 node_map 看成一个函数 f:旧节点 → 新节点。「克隆」的准确定义是 f 要满足:
```
u --next--> v   在原图  ⟺  f(u) --next--> f(v)   在新图
u --random--> w 在原图  ⟺  f(u) --random--> f(w) 在新图
```
这就是图同态/同构的定义,而它天然是两个部分:先有顶点映射,才谈得上边的保持。你的两趟不多不少就是这两句:

第一趟:构造 f 本身(定义域、陪域、一一对应)
第二趟:让 f 满足上面那两条边的条件
你没法在 f 还没定义完之前就去验证 f 保边——第二趟第一行要用的 f(v),可能对应的是链表末尾的节点。所以顺序是被数学逼出来的,不是实现上的将就

顺带一提,map 有两个作用,防环只是其一:

防环:否则无限递归
保共享:三个节点的 random 都指向同一个 w,新图里也必须是同一个 f(w),不是三个副本。克隆要保的不是值相等,是指针的相等关系


## 语法

语法上，Python 对象的属性是动态的,给一个不存在的属性赋值不是错误,是创建。这行代码忠实地给新节点挂了一个叫 ramdom 的新属性,存得好好的;而 random 从来没被碰过,保持 __init__ 里的 None。

值得记住的是这个不对称:


node.ramdom = x     # 写:静默成功,凭空造出新属性
y = node.ramdom     # 读:AttributeError,立刻炸
所以拼写错误出现在赋值号左边就是静默的,出现在右边才会响。这也是为什么你看到的现象是「全是 None」而不是报错——你踩的正是安静的那一侧。
